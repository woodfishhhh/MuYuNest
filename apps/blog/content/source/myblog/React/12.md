### 一、HOC 解决的是哪类重复
1. **定义**：高阶组件（Higher-Order Component，简称 HOC）接收一个组件，再返回包装后的新组件。它是一种组件增强模式，不是页面里直接渲染的函数组件或类组件。
2. **用途**：把没有独立 UI 的通用逻辑抽出来，例如数据处理、计算、生命周期操作。这个思路和 Vue1 中的 `mixin` 都指向逻辑复用，但组织方式不同。
3. **先判断要复用什么**：
   - 既有 UI 又有配套逻辑，例如弹窗、表格，通常直接抽普通组件；
   - 只有数据处理、事件监听或生命周期操作时，才更符合 HOC 的使用方式。

### 二、包装过程怎么写
#### 1. 先看完整结构
```javascript
// 定义高阶组件（接收组件，返回新组件）
function withHOC(WrappedComponent) { // WrappedComponent：需复用逻辑的目标组件
  // 返回匿名类组件或函数组件（封装复用逻辑）
  return class AnonymousComponent extends React.Component {
    // 1. 编写复用逻辑（数据、方法、生命周期等）
    state = {
      data: '复用的数据',
      x: 0,
      y: 0
    };

    handleLogic = () => {
      // 复用的方法逻辑
    };

    // 2. 生命周期钩子（若需复用生命周期逻辑）
    componentDidMount() {
      // 如：监听事件、数据请求等
    }

    // 3. 渲染目标组件，传递 props + 复用的逻辑/数据
    render() {
      return (
        <WrappedComponent
          {...this.props} // 传递高阶组件自身接收的 props
          data={this.state.data} // 传递复用的数据
          handleLogic={this.handleLogic} // 传递复用的方法
          mouseX={this.state.x}
          mouseY={this.state.y}
        />
      );
    }
  };
}

// 使用高阶组件：包装目标组件，生成新组件
const EnhancedComponent = withHOC(TargetComponent);
// 渲染增强后的组件
ReactDOM.render(<EnhancedComponent />, document.getElementById('root'));
```

#### 2. 这段代码里有三个关键点
- **props 要透传**：包装层接收到的 `this.props` 还要继续传给目标组件，代码里用的是 `{...this.props}`。漏掉这一步，原组件收到的 props 会不完整；
- **最终使用的是包装结果**：匿名组件不必单独命名，`EnhancedComponent` 才是渲染时使用的组件；
- **不要在渲染期间创建 HOC**：把 `withHOC(TargetComponent)` 放在组件外部，避免每次渲染都生成新的组件类型。

### 三、高阶组件实战案例
#### 案例 1：复用「鼠标位置监听」逻辑
多个组件都要读取鼠标 X、Y 坐标时，重复的不只是 state，还有事件的绑定、更新和解绑。下面把这整段逻辑放进包装层。
```javascript
// 定义监听鼠标位置的高阶组件
function withMousePosition(WrappedComponent) {
  return class extends React.Component {
    state = { x: 0, y: 0 };

    // 组件挂载时绑定鼠标移动事件
    componentDidMount() {
      window.addEventListener('mousemove', this.handleMouseMove);
    }

    // 组件卸载时解绑事件（避免内存泄漏）
    componentWillUnmount() {
      window.removeEventListener('mousemove', this.handleMouseMove);
    }

    // 处理鼠标移动，更新坐标
    handleMouseMove = (e) => {
      this.setState({
        x: e.clientX, // 鼠标X坐标（相对于可视区）
        y: e.clientY  // 鼠标Y坐标（相对于可视区）
      });
    };

    render() {
      // 传递坐标数据给目标组件
      return <WrappedComponent {...this.props} mouseX={this.state.x} mouseY={this.state.y} />;
    }
  };
}

// 使用高阶组件：包装需要坐标的组件
const MouseComponent = (props) => {
  return (
    <div>
      鼠标位置：X={props.mouseX}，Y={props.mouseY}
    </div>
  );
};
const EnhancedMouseComponent = withMousePosition(MouseComponent);
```

目标组件只接收坐标并负责展示。事件监听留在 HOC 内部，挂载时绑定、卸载时解绑，不会把资源清理散落到每个业务组件里。

#### 案例 2：复用「性能优化」逻辑（模拟 PureComponent）
这里再包装一次 `shouldComponentUpdate`，当 props 和 state 的浅比较结果都没有变化时，跳过后续更新。
```javascript
// 定义性能优化高阶组件（模拟 PureComponent）
function withPureRender(WrappedComponent) {
  return class extends React.Component {
    // 重写 shouldComponentUpdate，判断 props 和 state 是否变化
    shouldComponentUpdate(nextProps, nextState) {
      // 1. 判断 props 是否变化（浅比较）
      const propsChanged = Object.keys(nextProps).some(key => {
        return nextProps[key] !== this.props[key];
      });

      // 2. 判断 state 是否变化（浅比较）
      const stateChanged = Object.keys(nextState).some(key => {
        return nextState[key] !== this.state[key];
      });

      // 仅当 props 或 state 变化时，才允许更新
      return propsChanged || stateChanged;
    }

    render() {
      return <WrappedComponent {...this.props} />;
    }
  };
}

// 使用高阶组件：包装需要优化的组件
const TestComponent = (props) => {
  console.log('组件更新');
  return <div>{props.content}</div>;
};
const OptimizedComponent = withPureRender(TestComponent);

// 父组件使用：仅当 content 变化时，OptimizedComponent 才更新
class ParentComponent extends React.Component {
  state = { count: 0, content: '初始内容' };

  handleClick = () => {
    this.setState({ count: 99 }); // 仅修改 count，content 不变，子组件不更新
  };

  render() {
    return (
      <div>
        <button onClick={this.handleClick}>修改 count</button>
        <OptimizedComponent content={this.state.content} />
      </div>
    );
  }
}
```

这段实现只做浅比较。对象或数组即使内容相同，只要引用变了，仍会被判断为变化；反过来，原地修改引用类型也可能让变化被漏掉。

### 四、使用前检查
1. **复用对象**：多个组件是否真的共享一段无 UI 的逻辑，例如数据处理、事件监听或生命周期操作；
2. **包装收益**：抽取后能否减少重复，同时让业务组件只处理自己的展示；
3. **实现细节**：
   - 透传 props，避免原组件丢数据；
   - 在组件外部调用 HOC，避免反复创建组件类型；
   - 在 `componentWillUnmount` 中解绑事件、清理资源；
4. **与 mixin 的差别**：
   - 两者都能复用逻辑；
   - HOC 通过外层组件注入数据和行为，复用边界更显式；mixin 则更容易把不同来源的字段和生命周期逻辑混在一起。
