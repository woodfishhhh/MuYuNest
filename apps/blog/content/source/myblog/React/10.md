## 一、ref 能拿到什么
1. ref 可以获取**原生真实 DOM 元素**和**类组件实例**，作用和 Vue 中的 `ref` 接近。
2. 组件要在**挂载完成后**才能取到目标，因此获取逻辑要放进 `componentDidMount` 生命周期。
3. 它的边界很明确：
- 可以获取：原生 DOM、**类组件实例**
- 无法获取：函数组件，函数组件无实例对象

## 二、顺带补一下 JSX 根节点
一个组件返回多个元素时，外面必须有**单一根标签**。
- 常规写法是在外层嵌套 `<div>`
- 不想增加额外 DOM 时，可以用空标签碎片 `<></>`，它不会带来多余节点和样式

## 三、ref 两种写法
### 1. 废弃写法（字符串 ref + this.refs）
```jsx
<div ref="boxRef"></div>
```
通过 `this.refs.boxRef` 获取元素。不过这种写法已经被官方废弃，会触发控制台警告，项目里不要再用。

### 2. 使用 createRef
1. 先创建 ref 对象：
```jsx
this.boxRef = React.createRef()
```
2. 再绑定 DOM / 组件：
```jsx
<div ref={this.boxRef}></div>
```
3. 最后通过 `.current` 访问真实元素：
$$dom = this.boxRef.current$$

## 四、ref 获取类组件实例
1. 给子类组件绑定 `createRef`
2. 等组件挂载后，通过 `ref.current` 拿到子组件实例
3. 拿到实例后，可以访问子组件 `state`，也可以调用它的自定义方法
- 这是因为类组件会被实例化并拥有 this 上下文；函数组件没有 this 和实例，所以不支持这种方式。

## 五、Context 跨层传值
### 1. 什么时候用
组件嵌套较深时，**多层嵌套组件（爷孙/曾孙）**可以通过 Context 直接传值，省掉 props 一层层透传。它对应 Vue 的 `provide / inject`。

### 2. 基本写法
1. 创建一个全局唯一的上下文
```jsx
const MyContext = React.createContext()
```
2. 由上层组件提供数据：
用 `MyContext.Provider` 包住后代组件，并通过 `value` 属性传值
$$Provider_{value} = 传递的数据源$$
3. 由底层组件消费数据：
通过 `MyContext.Consumer` 接收，内部用**作用域插槽函数**取得 value。

### 3. Context 对象必须是同一个
**提供方、消费方必须使用同一个 Context 对象**。不要重复调用 `createContext`，否则消费方收不到数据。

## 六、Context 多值传递方案
1. 常用写法
给 `Provider` 的 value 传一个**对象**，一次就能带上多份数据：
```jsx
<MyContext.Provider value={{ msg1: "数据1", msg2: "数据2" }}>
```
2. 另一种写法
也可以嵌套多个不同 Context 组件，每个 Context 只传一个值，但代码会更长，可读性也更差。

## 七、几个容易踩的坑
1. Context 中不能直接渲染对象，解构取出属性再渲染，避免页面报错。
2. ref 不能在 `render` 同步阶段直接获取 DOM，此时 DOM 未挂载，`current` 为 `null`。
3. 严格区分：ref 操作 DOM/实例，Context 负责跨组件数据通信，二者场景完全独立。


## React 现代 Context 用法
## 一、先把 Context 的角色说清楚
Context 是 React **官方原生跨层级状态共享方案**。它让**祖孙/多层组件直接传值**，不用再让 props 逐层透传（prop drilling）。

$$\text{同一 Context 实例} = \text{Provider 提供} + \text{Consumer/钩子消费}$$

---

## 二、先创建 Context
```jsx
// 创建：可传入默认值（只有不使用 Provider 时生效）
const DemoContext = React.createContext(defaultValue);
```

---

## 三、三种消费方式
### 1. 函数组件使用 useContext 钩子
**提供方**
```jsx
import { createContext, useState } from 'react';
export const DemoContext = createContext();

function Parent() {
  const [count, setCount] = useState(0);
  return (
    // value 可传任意类型：值、对象、函数
    <DemoContext.Provider value={{ count, setCount }}>
      <Child />
    </DemoContext.Provider>
  );
}
```

**消费方**
```jsx
import { useContext } from 'react';
import { DemoContext } from './Parent';

function Grandson() {
  // 直接获取，无需 Consumer
  const { count, setCount } = useContext(DemoContext);
  return <div>{count}</div>;
}
```

---

### 2. 类组件使用 static contextType
```jsx
import { DemoContext } from './Parent';

class Grandson extends React.Component {
  // 绑定上下文
  static contextType = DemoContext;

  render() {
    // 通过 this.context 获取
    const { count } = this.context;
    return <div>{count}</div>;
  }
}
```

---

### 3. Context.Consumer 兼容所有组件
```jsx
<DemoContext.Consumer>
  {(value) => <div>{value.count}</div>}
</DemoContext.Consumer>
```

---

## 四、使用时要守住这些规则
1. **Provider 的 value 变化**，所有消费组件**自动更新**
2. 必须使用**同一个 Context 对象**，否则无法通信
3. 默认值仅在**没有匹配 Provider** 时生效
4. 可**多层嵌套 Provider**，内层覆盖外层
5. 传递函数/复杂对象时，建议用 `useMemo` 缓存避免重复渲染

---

## 五、把 Provider 和读取逻辑封装起来
### 封装自定义 Context 容器
```jsx
// DemoContext.jsx
import { createContext, useContext, useState, useMemo } from 'react';

const DemoContext = createContext();

export function DemoProvider({ children }) {
  const [user, setUser] = useState(null);

  // 缓存 value，防止不必要重渲染
  const value = useMemo(() => ({
    user, setUser
  }), [user]);

  return (
    <DemoContext.Provider value={value}>
      {children}
    </DemoContext.Provider>
  );
}

// 自定义钩子，简化使用
export function useDemo() {
  return useContext(DemoContext);
}
```

**使用**
```jsx
import { DemoProvider, useDemo } from './DemoContext';

// 根组件包裹
<DemoProvider>
  <App />
</DemoProvider>

// 任意子组件直接调用
const { user } = useDemo();
```

## 六、什么时候该用 Context
### 适用
- 全局主题、语言、用户信息
- 多层嵌套组件共享状态
- 替代深层 props 透传

### 不适用
- 组件局部状态
- 高频频繁更新（性能不如状态管理库）
- 非跨层级通信

---

## 七、与旧版区别
- 旧版：只能类组件使用、API 繁琐
- **新版**：函数组件可以直接用 `useContext`，写法更短，也支持多 Context 共存和性能优化
