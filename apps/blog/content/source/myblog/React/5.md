## 一、React 把渲染交给 JS
1. React 没有指令体系，渲染什么由 JS 逻辑算出来，这和 Vue 的指令（`v-if`/`v-for`）不一样。
2. JSX 对返回值的处理很直接：
   - 返回 `undefined / null / 空字符串 / false` → 不生成任何 DOM
   - 返回 JSX 标签结构 → 转成 `ReactElement`，再渲染成真实 DOM 节点
3. 布尔值和空值不占页面元素的位置，条件渲染就是靠这一点。

## 二、React 条件渲染（对标 Vue `v-if`）
### 1. 条件最后要返回什么
条件渲染就是一次 JS 逻辑表达式运算：
- 要显示时，返回 JSX 结构。
- 要隐藏时，返回 `false / '' / null`，React 不渲染这些值。

### 2. 三种常用写法
#### （1）三元表达式：二选一
```jsx
{ show ? <div>展示内容</div> : '' }
```

#### （2）逻辑与 `&&`：只控制显示
写法是 `条件 && 展示DOM`：
- 条件为 `true` 时返回右边的 DOM。
- 条件为 `false` 时直接返回 `false`，页面上不渲染。
```jsx
{ show && <div>展示内容</div> }
```

#### （3）函数返回式：处理复杂分支
把判断单独封装成函数，在里面写 `if/else`，最后返回 JSX 或空值，再到模板里调用。

### 3. 案例：状态切换显隐
- 用 `state` 里的布尔值控制内容显示还是隐藏。
- 按钮文字用三元表达式判断，点击时通过箭头函数改 state。
- 布尔值可以直接取反：`this.setState({show: !this.state.show})`。
> 类组件行内绑定事件必须用箭头函数，不然 `this` 指向会丢。

## 三、React 列表循环（对标 Vue `v-for`）
### 1. 列表先变成 JSX 数组
1. JSX 能直接渲染数组，数组里的每一项会依次处理。
2. 原始业务数据（纯数组/对象数组）→ 用数组方法转成存放 ReactElement 的 JSX 数组 → 直接交给页面渲染。

### 2. 三种遍历写法
#### （1）forEach + 手动push
先定义一个空数组，遍历原数据，把拼好的 JSX 元素 push 进新数组，最后渲染这个数组。
> 这种写法代码多，项目里很少用，主要用来理解过程。

#### （2）map 遍历
`map` 直接返回新数组，所以能在 JSX 里直接链式写，也是项目里最常用的方式：
```jsx
{ list.map((item, index) => (
  <div key={index}>{item}</div>
))}
```

#### （3）filter + map 组合
先用 `filter` 过滤数据，再用 `map` 渲染，就是条件列表渲染。

### 3. 列表项别忘了 key
1. key 和 Vue 里的作用一样，Diff 算法用它对比列表项，提高 DOM 更新效率。
2. 必须唯一且稳定，优先用后端返回的唯一 ID，实在没有才用 index。
3. 没有 key 时控制台会报错，还可能让 Diff 性能下降、列表数据错乱。

### 4. 更新列表时先复制一份
类组件更新状态时，别直接改原来的 state 数组：
- `push/pop` 这些方法会改动原数组。
- 要先浅拷贝原数组得到新数组，改完再通过 `setState` 更新，这样才会刷新视图。
```jsx
// 正确写法
const newList = [...this.state.list];
newList.push(Math.floor(Math.random()*10));
this.setState({list: newList});
```

## 四、和 Vue 对照着看
1. 编程方式
   - Vue 由指令驱动，内置了大量开箱即用的指令，简单场景写起来更快。
   - React 由 JS 原生逻辑驱动，没有额外的指令，自由度更高，复杂逻辑也更好定制。
2. 学习成本
   - Vue 要记各种指令的语法。
   - React 只靠原生 JS 语法，没有额外的指令要记。
3. 更适合的场景
   - Vue 适合轻量、快速开发的中小型项目。
   - React 更适合复杂业务、逻辑嵌套和定制化需求。

---
## 五、写完后检查这四处
1. 条件渲染别用 `display` 硬写样式代替，逻辑上销毁比样式隐藏好。
2. 列表渲染的 `map` 必须配 `key`，不能省。
3. 更新数组、对象这类状态时，必须替换引用，不能原地改。
4. 类组件行内绑定事件时优先用箭头函数，免得 this 指向出错。
