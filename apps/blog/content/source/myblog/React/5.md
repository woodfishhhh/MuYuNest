## 一、React 把渲染交给 JS
1. React 没有指令体系，**渲染内容由 JS 逻辑运算生成**，这和 Vue 的指令（`v-if`/`v-for`）不同。
2. JSX 对返回值的处理很直接：
   - 返回 `undefined / null / 空字符串 / false` → **不生成任何DOM**
   - 返回 JSX 标签结构 → 转为 `ReactElement`，再渲染成真实DOM节点
3. 布尔值和空值不会占用页面元素位置，条件渲染正是利用了这一点。

## 二、React 条件渲染（对标 Vue `v-if`）
### 1. 条件最后要返回什么
条件渲染就是一次**JS逻辑表达式运算**：
- 需要显示时，返回 JSX 结构。
- 需要隐藏时，返回 `false / '' / null`，React 不会渲染这些值。

### 2. 三种常用写法
#### （1）三元表达式：二选一
```jsx
{ show ? <div>展示内容</div> : '' }
```

#### （2）逻辑与 `&&`：只控制显示
写法是 `条件 && 展示DOM`：
- 条件为 `true` 时返回右侧DOM。
- 条件为 `false` 时直接返回 `false`，页面上不渲染。
```jsx
{ show && <div>展示内容</div> }
```

#### （3）函数返回式：处理复杂分支
把判断单独封装成函数，在里面写 `if/else`，最后返回JSX或空值，再到模板中调用。

### 3. 案例：状态切换显隐
- 用 `state` 中的布尔值控制内容显示或隐藏。
- 按钮文字用三元表达式动态判断，点击时通过箭头函数修改state。
- 布尔值可以直接取反：`this.setState({show: !this.state.show})`。
> 类组件行内绑定事件必须用**箭头函数**，否则 `this` 指向会丢失。

## 三、React 列表循环（对标 Vue `v-for`）
### 1. 列表先变成 JSX 数组
1. JSX 可以直接渲染**数组**，数组里的每一项会被依次处理。
2. 原始业务数据（纯数组/对象数组）→ 用数组方法转成**存放ReactElement的JSX数组** → 直接交给页面渲染。

### 2. 三种遍历写法
#### （1）forEach + 手动push
先定义空数组，再遍历原数据，把拼好的JSX元素push进新数组，最后渲染这个数组。
> 这种写法代码较多，项目中很少使用，主要用来理解过程。

#### （2）map 遍历
`map` 会**直接返回新数组**，因此可以在JSX里直接链式书写，也是项目中的常用方式：
```jsx
{ list.map((item, index) => (
  <div key={index}>{item}</div>
))}
```

#### （3）filter + map 组合
先用`filter`过滤数据，再用`map`渲染，就能得到**条件列表渲染**。

### 3. 列表项别忘了 key
1. key 和Vue里的作用相同，Diff算法会用它对比列表项，提高DOM更新效率。
2. 它必须**唯一且稳定**，优先使用后端返回的唯一ID，其次才是index。
3. 没有 key 时，控制台会报错，还可能造成Diff性能下降和列表数据错乱。

### 4. 更新列表时先复制一份
类组件更新状态时，不要直接修改原state数组：
- `push/pop` 等方法会改动原数组。
- 应该先**浅拷贝原数组**得到新数组，修改后再通过`setState`更新，这样才会触发视图刷新。
```jsx
// 正确写法
const newList = [...this.state.list];
newList.push(Math.floor(Math.random()*10));
this.setState({list: newList});
```

## 四、和 Vue 对照着看
1. **编程方式**
   - Vue 由指令驱动，内置了大量开箱即用的指令，简单场景写起来更快。
   - React 由**JS原生逻辑驱动**，没有额外指令，自由度更高，也更方便定制复杂逻辑。
2. **学习成本**
   - Vue 需要记忆各类指令语法。
   - React 只依赖原生JS语法，没有额外的指令语法需要记。
3. **更适合的场景**
   - Vue 适合轻量化、快速开发中小型项目。
   - React 更适合复杂业务、逻辑嵌套和定制化需求。

---
## 五、写完后检查这四处
1. 条件渲染不要用`display`硬写样式代替，**逻辑销毁**优于样式隐藏。
2. 列表渲染`map`必须配套`key`，不能省略。
3. 更新数组或对象这类状态时，必须替换引用，不能原地修改。
4. 类组件行内绑定事件时优先用箭头函数，避免this指向出错。
