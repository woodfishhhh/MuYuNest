### 一、先分清函数组件和类组件
| 特性                | 类组件                          | 函数组件                          |
|---------------------|---------------------------------|-----------------------------------|
| 生命周期            | 有（如 `componentDidMount`）    | 无，依赖 Hook 模拟                |
| `this` 指向         | 存在，需处理绑定（如箭头函数）  | 不存在，无需考虑 `this`           |
| 核心 API 风格       | 选项式 API（固定位置写固定逻辑）| 组合式 API（Hook 组合实现功能）   |
| 渲染逻辑载体        | 需写 `render()` 方法返回 JSX    | 函数体直接返回 JSX（等价于 `render`） |
| Props 接收方式      | `this.props.xxx`                | 函数第一个参数直接接收（`props.xxx`） |

### 二、函数组件怎么写
1. **两种定义方式**：
   - 普通函数形式：`function 组件名(props) { return <JSX>; }`
   - 箭头函数形式：`const 组件名 = (props) => <JSX>;`（单表达式可省略大括号）
2. **调用方式会改变 React 的处理路径**：
   - 作为组件使用：`<组件名 />`（React 会转化为虚拟 DOM）
   - 作为普通方法使用：`组件名()`（直接执行函数，返回 JSX 片段）
3. **文件拆分**：
   - 组件较多时，可以把单个组件拆到独立文件（如 `Sun.js`），通过 `export default` 暴露，再在使用处导入

### 三、常用 Hook 怎么选
#### （一）`useState`：让状态驱动界面
组件需要保存数据，并在数据变化后重新渲染时，先看 useState：

1. **基本写法**：

   ```javascript
   const [state, setState] = useState(initialValue);
   ```
   - `initialValue` 是状态初始值，可以是基础类型、对象或数组
   - `state` 是当前渲染拿到的状态值，不要直接修改
   - `setState` 用来提交下一次状态，并触发组件重新渲染
2. **更新状态时看数据类型**：
   - 基础类型可以直接传新值：`setState(newValue)`
   - 数组和对象要传入新引用，不要在原值上修改
     ```javascript
     // 数组修改（解构创建新数组）
     setState([...oldArr, newItem]);
     // 对象修改（解构创建新对象）
     setState({ ...oldObj, key: newValue });
     ```
   - 下一次状态依赖上一次状态时，使用函数形式，避免连续更新读到旧值
     ```javascript
     setState(prevState => prevState + 1); // 正确（依赖上一次状态）
     setState(state + 1); // 可能失效（state 可能是旧值）
     ```
3. **容易踩的坑**：
   - 不要在函数组件顶层直接调用 `setState`。这相当于在 `render` 期间继续更新状态，组件会反复渲染
   - 初始值需要复杂计算时，可以传入函数，让这段计算只在初始化时执行一次：
     ```javascript
     const [state, setState] = useState(() => heavyComputation());
     ```

#### （二）`useEffect`：把副作用和清理放在一起
请求数据、操作 DOM、订阅事件都不属于纯渲染逻辑，适合放进 useEffect。

1. **基本写法**：
   ```javascript
   useEffect(() => {
     // 副作用逻辑（如请求数据、操作 DOM、订阅事件）
     return () => {
       // 清理逻辑（如取消订阅、移除事件监听）
     };
   }, dependencies); // 依赖数组（可选）
   ```
2. **依赖数组决定何时重新执行**：
   | 依赖数组配置       | 等价生命周期/功能                | 执行时机                          |
   |--------------------|---------------------------------|-----------------------------------|
   | 不传递             | `componentDidMount` + `componentDidUpdate` | 组件挂载后 + 每次组件更新后       |
   | 传递空数组 `[]`    | `componentDidMount`             | 仅组件挂载后执行一次              |
   | 传递具体依赖 `[a,b]`| Vue 的 `watch([a,b], ...)`      | 组件挂载后 + 依赖项（a/b）变化后  |
3. **副作用需要对应的清理**：
   - 定时器、事件监听和订阅如果不清理，会在组件离开后继续工作
   - 清理函数会在组件卸载前，或下一次副作用执行前触发：
     ```javascript
     useEffect(() => {
       const timer = setInterval(() => console.log('定时器'), 1000);
       return () => clearInterval(timer); // 组件卸载时清除定时器
     }, []);
     ```

#### （三）`useMemo`：缓存计算结果
当一段计算确实耗时，而且依赖没有变化时不必重算，再考虑 useMemo。

1. **基本写法**：
   ```javascript
   const cachedValue = useMemo(() => {
     // 复杂计算逻辑（如数组求和、数据过滤转换）
     return computation(props, state);
   }, dependencies); // 依赖数组
   ```
2. **它做了什么**：
   - 减少组件更新时重复执行的昂贵计算，例如大数据量处理
   - 依赖项变化后重新计算；依赖不变时返回已有结果
3. **常见用法**：
   - 复杂数学计算：`const sum = useMemo(() => arr.reduce((a,b) => a+b, 0), [arr]);`
   - 数据转换：`const filteredList = useMemo(() => list.filter(item => item.age > 18), [list]);`
4. **不要把缓存当默认写法**：
   - `a + b` 这类简单计算没有必要套 `useMemo`，维护依赖本身也有成本
   - 回调必须返回计算结果，否则没有可复用的值

#### （四）`useCallback`：稳定函数引用
函数作为 props 传给做浅比较的子组件时，引用变化可能让优化失效。这个场景可以使用 useCallback。

1. **基本写法**：
   ```javascript
   const cachedFn = useCallback(() => {
     // 函数逻辑
     handleAction(props, state);
   }, dependencies); // 依赖数组
   ```
2. **它解决的问题**：
   - 在依赖不变时保持函数引用稳定
   - 常与 `React.memo` 配合，减少子组件因函数 props 变化而产生的重复渲染
3. **一个常见场景**：
   - 把事件处理函数传给子组件：
     ```javascript
     // 父组件
     const handleClick = useCallback(() => console.log('点击'), []);
     return <Child onClick={handleClick} />;
     // 子组件（React.memo 浅比较 props）
     const Child = React.memo(({ onClick }) => <button onClick={onClick}>按钮</button>);
     ```
4. **和 `useMemo` 怎么区分**：
   - `useMemo` 缓存值，也就是计算结果
   - `useCallback` 缓存函数引用，可以把它理解为 `useMemo(() => fn, deps)` 这一用法的简写

#### （五）`useRef`：保存不参与渲染的值
需要访问 DOM，或者需要跨渲染保存一个可变值但不希望触发更新时，可以使用 useRef。

1. **基本写法**：
   ```javascript
   const refObj = useRef(initialValue);
   ```
   - 值放在 `refObj.current` 中；它可以修改，但修改不会让组件重新渲染
2. **两个常用方向**：
   - 获取真实 DOM 元素：
     ```javascript
     const inputRef = useRef(null);
     useEffect(() => {
       inputRef.current.focus(); // 组件挂载后让输入框聚焦
     }, []);
     return <input ref={inputRef} />;
     ```
   - 保存组件生命周期内需要持续存在的值，例如定时器 ID 或上一次状态：
     ```javascript
     const prevStateRef = useRef();
     useEffect(() => {
       prevStateRef.current = state; // 记录上一次状态
     }, [state]);
     // 可在任意地方访问 prevStateRef.current
     ```

#### （六）`useContext`：读取跨层级数据
当数据要穿过多层组件时，可以用 Context 提供数据，再通过 useContext 读取。

1. **使用流程**：
   - 1. 创建 Context：`const MyContext = createContext(defaultValue);`
   - 2. 提供 Context 数据（父组件）：
     ```javascript
     <MyContext.Provider value={共享数据}>
       子组件树
     </MyContext.Provider>
     ```
   - 3. 消费 Context 数据（函数组件）：
     ```javascript
     const value = useContext(MyContext); // 直接获取共享数据
     ```
2. **适合解决什么问题**：
   - 避免数据通过多层 `props` 逐级透传
   - 与 `Context.Consumer` 相比，调用位置更直接，也少一层嵌套回调
3. **更新边界**：
   - 只有 `defaultValue` 会在组件没有被 `Provider` 包裹时生效
   - Provider 提供的共享数据变化后，使用 `useContext` 读取该 Context 的组件会重新渲染。可以用 `useMemo` 稳定 Provider 的 value，但仍要根据组件边界判断是否值得优化

### 四、Props 传递与接收
父组件通过 JSX 属性传值，子组件从参数里读取。

1. **父组件传值**：
   ```javascript
   <ChildComponent name="React" age={10} isActive={true} />
   ```
2. **子组件接收**：
   - 直接解构参数：`const ChildComponent = ({ name, age, isActive }) => { ... }`
   - 完整 props 对象：`const ChildComponent = (props) => { console.log(props.name); ... }`
3. **需要运行时校验时再接入 PropTypes**：
   - 安装 `prop-types`：`npm install prop-types`
   - 使用示例：
     ```javascript
     import PropTypes from 'prop-types';
     ChildComponent.propTypes = {
       name: PropTypes.string.isRequired, // 必传字符串
       age: PropTypes.number, // 可选数字
       isActive: PropTypes.bool.isRequired // 必传布尔值
     };
     ```

### 五、Hook 不能破坏调用顺序
1. 只能在**函数组件顶层**调用 Hook（不可在条件语句、循环、嵌套函数中使用）
2. 只能在**函数组件**或**自定义 Hook** 中调用 Hook（不可在类组件、普通函数中使用）
3. 依赖数组需包含所有在 Hook 中使用的外部变量（避免闭包陷阱导致的旧值问题）
4. 自定义 Hook 必须以 `use` 开头（如 `useRequest`、`useLocalStorage`），否则 React 无法检测 Hook 规则
