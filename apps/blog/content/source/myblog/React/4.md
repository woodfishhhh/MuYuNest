## 一、state 怎么定义
1. 类组件把响应式数据放进 `state` 对象。`state` 必须是对象，里面的属性都当响应式数据用。
2. 两种写法：
   - 传统写法保留 `constructor`：
     ```javascript
     class Component extends React.Component {
       constructor(props) {
         super(props); // 必传props并调用super
         this.state = {
           a: 0, // 响应式数据a
           b: { c1: 123, c2: 999 }, // 嵌套对象类型响应式数据
           arr: [1, 2, 3] // 数组类型响应式数据
         };
       }
     }
     ```
   - ES7 简写跳过 `constructor`，更推荐：
     ```javascript
     class Component extends React.Component {
       state = {
         a: 0,
         b: { c1: 123, c2: 999 },
         arr: [1, 2, 3]
       };
     }
     ```
3. 直接挂在 `this` 上的属性（比如 `this.b = 123`）也能用，但不是响应式的，值变了页面不会更新。

## 二、在模板里读取 state
- 类组件要通过 `this.state.属性名` 访问数据，不能像 Vue 那样直接读 `data` 里的属性：
  ```javascript
  // 正确使用
  render() {
    return <div>{this.state.a}</div>;
  }
  ```

## 三、修改数据要走 setState
### 1. 为什么不能直接赋值
- React 没有 Vue 那种 `get/set` 数据劫持，直接改 state 不会触发更新。值是变了，页面不会跟着刷新：
  ```javascript
  this.state.a = 1; // 错误：数据改变但页面不更新
  ```
- 修改时要调 `this.setState()`。它做两件事：① 修改 `state` 数据；② 触发组件重新渲染，把变化更新到页面上。

### 2. setState 的三种参数写法
#### （1）参数1传对象（常用）
```javascript
this.setState({
  a: this.state.a + 1, // 直接赋值新值
  "b.c1": 9 // 不推荐直接修改嵌套属性
});
```
#### （2）参数1传函数（少见，用旧 state 计算新值时使用）
```javascript
this.setState(prevState => {
  return { a: prevState.a + 1 }; // prevState 为更新前的 state
});
```
#### （3）参数2传回调函数（读取异步更新后的最新 state）
```javascript
this.setState({ a: 1 }, () => {
  console.log(this.state.a); // 正确：输出 1（更新后的值）
});
console.log(this.state.a); // 错误：输出旧值（setState 是异步操作）
```

### 3. setState 的几个行为
#### （1）只做浅合并
- 传进去的更新对象和原 `state` 做浅合并，只处理第一层，嵌套对象不会递归合并。相当于 `Object.assign(原state, 更新对象)`：
  - 原数据是 `state = {a:0, b:{c1:123, c2:999}}`。
  - 执行 `this.setState({a:1})` 后得到 `{a:1, b:{c1:123, c2:999}}`，只更新第一层的 `a`，`b` 不变。
  - 改嵌套对象时，没保留原属性的话，其他字段会丢。可以展开原对象，或者把属性写全：
    ```javascript
    // 错误：c2 会丢失
    this.setState({ b: { c1: 9 } });
    // 正确：展开原对象保留所有属性
    this.setState({ b: { ...this.state.b, c1: 9 } });
    ```

#### （2）更新是异步的
- `setState` 是异步的，紧跟在后面的同步代码读不到最新的 `state`，要在第二个参数的回调里拿：

  ```javascript
  this.setState({ a: 1 });
  console.log(this.state.a); // 输出旧值（如 0），因更新未完成
  this.setState({ a: 1 }, () => {
    console.log(this.state.a); // 输出 1（更新完成后执行）
  });
  ```

#### （3）连续更新会批量合并
- 连续调用多次 `setState` 会合并成一次更新，减少重复渲染：
  ```javascript
  // 等价于 this.setState({a:1, b:2})
  this.setState({ a: 1 });
  this.setState({ b: 2 });
  ```

#### （4）用空对象强制更新（不规范，仅作原理说明）
- 传空对象 `this.setState({})` 不改数据，但还是会触发组件更新，因为调用了 `setState`。

## 四、用 PureComponent 跳过重复渲染
### 1. 它解决什么问题
- 继承 `React.PureComponent` 代替 `React.Component`，可以跳过相同值的重复更新：
  - `Component` 组件里，就算 `setState` 传的值和原 `state` 一样，也会触发 `render`。
  - `PureComponent` 会浅比较新旧 `state` 和 `props`，值相同就不触发 `render`。

### 2. 引用类型要换地址
- `PureComponent` 对引用类型（对象、数组）只比较内存地址，不比较里面的内容：
  - 直接改原来的引用类型数据，比如用 `push` 改数组、直接改对象属性，内存地址不变，`PureComponent` 认为数据没变，就不更新：
    ```javascript
    // 错误：数组内存地址不变，PureComponent 不更新
    this.state.arr.push(4);
    this.setState({ arr: this.state.arr });
    ```
  - 更新之前先浅拷贝出一个新引用，让内存地址变掉：
    ```javascript
    // 数组：展开运算符创建新数组
    this.setState({ arr: [...this.state.arr, 4] });
    // 对象：展开运算符创建新对象
    this.setState({ b: { ...this.state.b, c1: 9 } });
    ```

## 五、三个容易踩的坑
1. 别在 render 里调 setState：
   - `render` 触发更新 → `setState` 又触发更新，最后死循环，页面卡死。
   - 错误写法：
     ```javascript
     render() {
       this.setState({ a: 1 }); // 绝对禁止
       return <div>{this.state.a}</div>;
     }
     ```
2. 嵌套对象或数组更新后丢属性：

   - 没展开原对象或数组时，浅合并会覆盖原来的嵌套属性。比如改 `b.c1` 时没保留 `b.c2`，`b.c2` 就丢了。
3. 在同步代码里读最新的 state：
   - 把 `setState` 当成同步的，紧接着读 `state`，拿到的还是旧值。
