## 一、state 怎么定义
1. 类组件把响应式数据放进 `state` 对象。`state` 必须是对象类型，里面的属性都会作为响应式数据使用。
2. 写法有两种：
   - 传统写法会保留 `constructor`：
     ```javascript
     class Component extends React.Component {
       constructor(props) {
         super(props); // 必传props并调用super
         this.state = {
           a: 0, // 响应式数据a
           b: { c1: 123, c2: 999 }, // 嵌套对象类型响应式数据
           arr: [1, 2, 3] // 数组类型响应式数据
         };
       }
     }
     ```
   - ES7 简写会跳过 `constructor`，更推荐这样写：
     ```javascript
     class Component extends React.Component {
       state = {
         a: 0,
         b: { c1: 123, c2: 999 },
         arr: [1, 2, 3]
       };
     }
     ```
3. 直接挂在 `this` 上的属性（如 `this.b = 123`）也能使用，但它不是响应式数据，值变了不会触发页面更新。

## 二、在模板里读取 state
- 类组件必须通过 `this.state.属性名` 访问数据，不能像 Vue 那样直接读取 `data` 里的属性：
  ```javascript
  // 正确使用
  render() {
    return <div>{this.state.a}</div>;
  }
  ```

## 三、修改数据要走 setState
### 1. 为什么不能直接赋值
- React 没有 Vue 那样的 `get/set` 数据劫持，**直接修改 state 不触发更新**。数据值虽然变了，页面不会跟着刷新：
  ```javascript
  this.state.a = 1; // 错误：数据改变但页面不更新
  ```
- 修改时必须调用 `this.setState()`。它会做两件事：① 修改 `state` 数据；② 触发组件重新渲染，把变化更新到页面。

### 2. setState 的三种参数写法
#### （1）参数1传对象（常用）
```javascript
this.setState({
  a: this.state.a + 1, // 直接赋值新值
  "b.c1": 9 // 不推荐直接修改嵌套属性
});
```
#### （2）参数1传函数（少见，用旧 state 计算新值时使用）
```javascript
this.setState(prevState => {
  return { a: prevState.a + 1 }; // prevState 为更新前的 state
});
```
#### （3）参数2传回调函数（读取异步更新后的最新 state）
```javascript
this.setState({ a: 1 }, () => {
  console.log(this.state.a); // 正确：输出 1（更新后的值）
});
console.log(this.state.a); // 错误：输出旧值（setState 是异步操作）
```

### 3. setState 的几个行为
#### （1）只做浅合并
- 传入的更新对象会和原 `state` **浅合并**，也就是只处理第一层，嵌套对象不会递归合并。这个过程等价于 `Object.assign(原state, 更新对象)`：
  - 原数据是 `state = {a:0, b:{c1:123, c2:999}}`。
  - 执行 `this.setState({a:1})` 后得到 `{a:1, b:{c1:123, c2:999}}`，只更新第一层 `a`，`b` 保持不变。
  - 修改嵌套对象时，如果没有保留原属性，其他字段会丢失。可以展开原对象，或者把属性完整写出来：
    ```javascript
    // 错误：c2 会丢失
    this.setState({ b: { c1: 9 } });
    // 正确：展开原对象保留所有属性
    this.setState({ b: { ...this.state.b, c1: 9 } });
    ```

#### （2）更新是异步的
- `setState` 是异步操作，紧跟在后面的同步代码读不到最新 `state`，需要在第二个回调参数里获取：

  ```javascript
  this.setState({ a: 1 });
  console.log(this.state.a); // 输出旧值（如 0），因更新未完成
  this.setState({ a: 1 }, () => {
    console.log(this.state.a); // 输出 1（更新完成后执行）
  });
  ```

#### （3）连续更新会批量合并
- 连续多次调用 `setState` 会合并为一次更新，减少重复渲染：
  ```javascript
  // 等价于 this.setState({a:1, b:2})
  this.setState({ a: 1 });
  this.setState({ b: 2 });
  ```

#### （4）用空对象强制更新（不规范，仅作原理说明）
- 传入空对象 `this.setState({})` 不会修改数据，但仍会触发组件更新，因为调用了 `setState`。

## 四、用 PureComponent 跳过重复渲染
### 1. 它解决什么问题
- 继承 `React.PureComponent` 替代 `React.Component`，可以跳过 **相同值重复更新**：
  - `Component` 组件中，即使 `setState` 传入的值和原 `state` 相同，也会触发 `render`。
  - `PureComponent` 会浅比较新旧 `state` 和 `props`，值相同时不触发 `render`。

### 2. 引用类型要换地址
- `PureComponent` 对 **引用类型（对象、数组）** 只比较内存地址，不会深入比较内容：
  - 直接修改原引用类型数据，比如用 `push` 改数组或直接改对象属性，内存地址不会变，`PureComponent` 会认为数据没变，因此不触发更新：
    ```javascript
    // 错误：数组内存地址不变，PureComponent 不更新
    this.state.arr.push(4);
    this.setState({ arr: this.state.arr });
    ```
  - 更新前先浅拷贝出新引用，让内存地址发生变化：
    ```javascript
    // 数组：展开运算符创建新数组
    this.setState({ arr: [...this.state.arr, 4] });
    // 对象：展开运算符创建新对象
    this.setState({ b: { ...this.state.b, c1: 9 } });
    ```

## 五、三个容易踩的坑
1. **不要在 render 中调用 setState**：
   - `render` 触发更新 → `setState` 再次触发更新，最后进入死循环，页面会卡死。
   - 下面是错误写法：
     ```javascript
     render() {
       this.setState({ a: 1 }); // 绝对禁止
       return <div>{this.state.a}</div>;
     }
     ```
2. **嵌套对象或数组更新后丢属性**：

   - 没有展开原对象或数组时，浅合并会覆盖原有嵌套属性。例如修改 `b.c1` 时没保留 `b.c2`，最终会让 `b.c2` 丢失。
3. **在同步代码里读取最新 state**：
   - 把 `setState` 当成同步操作，随后立刻读取 `state`，拿到的还是旧值。
