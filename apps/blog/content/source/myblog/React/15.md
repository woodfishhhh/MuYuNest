## 一、先分清状态库和 React 绑定层
React 自带组件状态和 Context，但跨模块的复杂状态通常会交给独立状态库。以 Redux 这条路线为例，需要两层配合：
- 状态库：`Redux`/`@reduxjs/toolkit`/`MobX` 负责保存和修改纯 JS 数据，本身不会直接驱动 React 组件更新
- 绑定库：`react-redux` 负责把 Redux/RTK 接入组件；原笔记把 MobX 对应包记为`react-mobx`，这个包名需要结合项目依赖再确认
- 绑定完成后，全局状态会映射到组件`props/state`，相关状态变化时组件再更新

## 二、先用原生 Redux 跑通数据流
### 1. 这几个API分别做什么
- `createStore`（已弃用，用`legacy_createStore`）：创建仓库
- `reducer`：纯函数，定义初始状态+修改逻辑
- `dispatch`：触发状态修改
- `getState`：获取当前状态
- `subscribe`：监听状态变化

### 2. 从 reducer 写起
1. 定义reducer（初始state + action处理）
```js
// store/index.js
import { legacy_createStore as createStore } from 'redux'

// 初始状态
const initialState = { message: 'hello' }

// reducer纯函数
function msgReducer(state = initialState, action) {
  switch (action.type) {
    case 'CHANGE_MSG':
      // 必须返回新对象，解除引用
      return { ...state, message: action.payload }
    case 'RESET_MSG':
      return { ...state, message: 'hello' }
    default:
      return state
  }
}

// 创建store
const store = createStore(msgReducer)
export default store
```
2. 手动读取和修改（还没有接入react-redux）
```js
// 组件中
import store from './store'
// 获取状态
console.log(store.getState())
// 触发修改
store.dispatch({ type: 'CHANGE_MSG', payload: 'world' })
```

### 3. 为什么还需要绑定层
- Redux 仓库只处理纯 JS 状态，组件不会因为 store 变化自动订阅更新
- action 和 reducer 的模板代码较多，需要手动写`type`判断
- 直接使用`subscribe`时，还要自己决定哪些组件更新；如果把订阅粗暴地放在应用根部，很容易造成大范围重渲染

## 三、用 react-redux 接入组件
### 1. 两个入口
- `Provider`：全局注入store
- `connect`：高阶组件，映射state/dispatch到props

### 2. 从根组件到业务组件
1. 在根组件注入store
```js
// index.js
import { Provider } from 'react-redux'
import store from './store'

root.render(
  <Provider store={store}>
    <App />
  </Provider>
)
```
2. 在组件中用connect映射（类/函数组件通用）
```js
// App.js
import { connect } from 'react-redux'

function App(props) {
  const { message, changeMsg, resetMsg } = props
  return (
    <div>
      <p>{message}</p>
      <button onClick={() => changeMsg('world')}>修改</button>
      <button onClick={resetMsg}>重置</button>
    </div>
  )
}

// 1. 映射state到props
const mapStateToProps = (state) => ({
  message: state.message
})

// 2. 映射dispatch到props（封装action）
const mapDispatchToProps = (dispatch) => ({
  changeMsg: (val) => dispatch({ type: 'CHANGE_MSG', payload: val }),
  resetMsg: () => dispatch({ type: 'RESET_MSG' })
})

// 连接组件
export default connect(mapStateToProps, mapDispatchToProps)(App)
```

## 四、状态多了以后再拆 reducer
### 1. 用`combineReducers`合并模块
每个 reducer 只处理自己的状态，最后再合并成根 reducer：
```js
// store/index.js
import { legacy_createStore, combineReducers } from 'redux'
import msgReducer from './msgReducer'
import numReducer from './numReducer'

// 合并reducer
const rootReducer = combineReducers({
  msg: msgReducer,
  num: numReducer
})

const store = createStore(rootReducer)
export default store
```
### 2. 取值路径会多一层模块名
```js
// mapStateToProps中
const mapStateToProps = (state) => ({
  message: state.msg.message,
  number: state.num.number
})
```

## 五、用 @reduxjs/toolkit（RTK）减少模板代码
### 1. RTK替你处理了什么
- 内置`immer`，reducer 中看起来可以直接修改 state，实际由 Immer 生成不可变更新结果
- 根据 slice 配置自动生成 action，不必手动维护 type
- 默认集成`thunk`，可以组织异步逻辑

### 2. 两个主要API
- `createSlice`：创建状态切片（初始state + reducer）
- `configureStore`：创建store（合并切片）

### 3. 先创建 slice，再组装 store
1. 创建切片（模块化）
```js
// store/msgSlice.js
import { createSlice } from '@reduxjs/toolkit'

const msgSlice = createSlice({
  name: 'msg', // 切片名（生成action前缀）
  initialState: { message: 'hello' },
  reducers: {
    changeMsg: (state, action) => {
      // 可直接修改，immer自动处理不可变
      state.message = action.payload
    },
    resetMsg: (state) => {
      state.message = 'hello'
    }
  }
})

// 自动生成action
export const { changeMsg, resetMsg } = msgSlice.actions
// 导出reducer
export default msgSlice.reducer
```
2. 配置store
```js
// store/index.js
import { configureStore } from '@reduxjs/toolkit'
import msgReducer from './msgSlice'
import numReducer from './numSlice'

const store = configureStore({
  reducer: {
    msg: msgReducer,
    num: numReducer
  }
})
export default store
```
3. 组件使用方式仍由react-redux提供
```js
// 导入自动生成的action
import { changeMsg, resetMsg } from './store/msgSlice'
```

## 六、函数组件直接使用 Hooks
### 1. 一个负责读，一个负责写
- `useSelector`：获取state
- `useDispatch`：获取dispatch方法

### 2. 放进组件后的写法
```js
// App.js
import { useSelector, useDispatch } from 'react-redux'
import { changeMsg } from './store/msgSlice'

function App() {
  // 获取状态
  const message = useSelector(state => state.msg.message)
  // 获取dispatch
  const dispatch = useDispatch()

  return (
    <div>
      <p>{message}</p>
      <button onClick={() => dispatch(changeMsg('world'))}>修改</button>
    </div>
  )
}
export default App
```

## 七、用 createAsyncThunk 组织异步流程
### 1. 异步不要写进 reducer
Redux/RTK 的 reducer 要保持同步和可预测。这个示例选择`createAsyncThunk`承接异步逻辑，再让 slice 响应不同阶段的 action。

### 2. 从 thunk 的返回值更新状态
1. 创建异步thunk
```js
// store/numSlice.js
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit'

// 1. 创建异步thunk
export const changeNumAsync = createAsyncThunk(
  'num/changeNumAsync', // 唯一标识
  async (payload) => { // 异步逻辑
    // 模拟请求
    const res = await new Promise(resolve =>
      setTimeout(() => resolve(999), 1000)
    )
    return res
  }
)

const numSlice = createSlice({
  name: 'num',
  initialState: { number: 0 },
  reducers: {},
  // 2. 监听异步状态
  extraReducers: (builder) => {
    builder
      // 请求成功
      .addCase(changeNumAsync.fulfilled, (state, action) => {
        state.number = action.payload
      })
      // 请求中/失败可额外处理
      .addCase(changeNumAsync.pending, () => {})
      .addCase(changeNumAsync.rejected, () => {})
  }
})
export default numSlice.reducer
```
2. 组件像派发普通 action 一样触发异步
```js
dispatch(changeNumAsync(1))
```

## 七、把几层关系串起来
1. **原生Redux**：负责状态容器和数据流，但 action、type、不可变更新都要手动处理
2. **RTK**：用 slice、immer 和 thunk 减少这些模板代码，并自动生成 action
3. **react-redux**：通过`Provider`注入 store，再用`connect`或 Hooks 让组件订阅状态
4. **异步**：reducer 本身不写异步；本例使用`createAsyncThunk`组织请求和状态更新
5. **更新路径**：状态先进入 store，再映射到 props/state，相关数据变化后触发组件重渲染
