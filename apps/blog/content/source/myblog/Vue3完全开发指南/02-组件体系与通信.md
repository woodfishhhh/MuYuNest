# Vue 3 组件体系与通信

## 1. 组件边界与数据流

拆组件不是为了把文件"切得更多"，而是为了定清楚职责和约定。一个典型的后台布局可以拆成：

```text
App.vue                 应用壳与全局 Provider
└─ AppLayout.vue        页面结构编排
   ├─ AppSidebar.vue    导航展示与选择事件
   ├─ AppHeader.vue     当前用户和页面级命令
   └─ MainContent.vue   页面内容出口
```

稳定的默认通信规则：

```text
父组件状态 ──props──> 子组件
父组件动作 <──emits── 子组件
父组件内容 ──slots──> 子组件布局出口
```

组件要把输入、输出和可替换的内容公开出来，别让父组件随便读写它的内部状态。

## 2. BEM、Sass 与自适应布局

Sass 可以配合 BEM 组织侧栏、顶栏和内容区的布局。BEM 有三个角色：

```text
.app-layout                 Block：独立组件或区域
.app-layout__content        Element：Block 内部组成部分
.app-layout--compact        Modifier：Block 的状态或变体
```

起名是为了让样式归谁一眼能看出来，不是要求每一层 DOM 都对应一个超长的类名。一个元素只应该属于一个明确的 Block。

```vue
<script setup lang="ts">
import AppHeader from './AppHeader.vue'
import AppSidebar from './AppSidebar.vue'
</script>

<template>
  <div class="app-layout">
    <AppSidebar class="app-layout__sidebar" />

    <div class="app-layout__right">
      <AppHeader class="app-layout__header" />
      <main class="app-layout__content">
        <slot />
      </main>
    </div>
  </div>
</template>

<style scoped lang="scss">
.app-layout {
  display: flex;
  height: 100%;
  overflow: hidden;

  &__sidebar {
    flex: 0 0 14rem;
    border-right: 1px solid #d9dce1;
  }

  &__right {
    display: flex;
    flex: 1 1 auto;
    min-width: 0;
    flex-direction: column;
  }

  &__header {
    flex: 0 0 auto;
  }

  &__content {
    flex: 1 1 auto;
    min-height: 0;
    overflow: auto;
  }
}
</style>
```

`min-width: 0` 和 `min-height: 0` 很关键：Flex 子项默认的最小尺寸可能让它缩不下去，结果内容区把父容器撑开了，而不是在自己里面滚动。

### 2.1 Sass mixin 的适用边界

一种常见的做法是用 Sass mixin 生成 BEM 类名。实际项目里，直接写清楚的类名一般更好搜；只有好几个组件确实共用同一套生成规则时，才值得抽象。

```scss
// styles/_layout.scss
@mixin fill-scroll-area {
  min-width: 0;
  min-height: 0;
  overflow: auto;
}
```

```scss
@use '@/styles/layout' as layout;

.app-layout__content {
  @include layout.fill-scroll-area;
}
```

> 版本提示：Sass 正在逐步用 `@use`/`@forward` 取代旧的 `@import`。Vite 的预处理器配置键、Sass 的实现和警告策略都会变，以项目装的版本为准。

## 3. Props 向下，Events 向上

### 3.1 子组件声明契约

```vue
<!-- UserCard.vue -->
<script setup lang="ts">
interface User {
  id: number
  name: string
  role: 'admin' | 'member'
}

interface Props {
  user: User
  selectable?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  selectable: false,
})

const emit = defineEmits<{
  select: [userId: number]
  remove: [userId: number]
}>()

function selectUser() {
  if (props.selectable) emit('select', props.user.id)
}
</script>

<template>
  <article class="user-card" @click="selectUser">
    <strong>{{ props.user.name }}</strong>
    <span>{{ props.user.role }}</span>
    <button type="button" @click.stop="emit('remove', props.user.id)">
      删除
    </button>
  </article>
</template>
```

父组件保留状态的所有权：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import UserCard from './UserCard.vue'

interface User {
  id: number
  name: string
  role: 'admin' | 'member'
}

const users = ref<User[]>([])
const selectedId = ref<number | null>(null)

function removeUser(userId: number) {
  users.value = users.value.filter(user => user.id !== userId)
}
</script>

<template>
  <UserCard
    v-for="user in users"
    :key="user.id"
    :user="user"
    selectable
    @select="selectedId = $event"
    @remove="removeUser"
  />
</template>
```

Props 是只读的输入。子组件别直接改 prop，也别通过改 prop 内部的对象偷偷改父组件的状态。要变更就派发一个有语义的事件，由父组件决定怎么更新。

`withDefaults` 主要用来给类型式的 props 设默认值。数组、对象这类可变的默认值要用函数创建，免得不同的组件实例共用同一个引用。

### 3.2 组件事件不会冒泡

原生 DOM 事件可能冒泡，Vue 的组件事件不会。孙组件发出的 `saved` 不会自己越过子组件到祖先那里；中间的组件要显式监听再重新发出，或者重新设计状态的边界。

### 3.3 `defineExpose`：只公开必要的命令式 API

优先用 props/emits。只有聚焦、校验、打开弹窗这类本来就是命令式的行为，才让父组件通过模板引用去调子组件：

```vue
<!-- SearchInput.vue -->
<script setup lang="ts">
import { useTemplateRef } from 'vue'

const input = useTemplateRef<HTMLInputElement>('input')

function focus() {
  input.value?.focus()
}

defineExpose({ focus })
</script>

<template>
  <input ref="input" type="search" />
</template>
```

```vue
<!-- Parent.vue -->
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import SearchInput from './SearchInput.vue'

const searchInput = useTemplateRef<InstanceType<typeof SearchInput>>('searchInput')
</script>

<template>
  <SearchInput ref="searchInput" />
  <button type="button" @click="searchInput?.focus()">聚焦搜索框</button>
</template>
```

> 版本提示：`useTemplateRef()` 要 Vue 3.5+。更早的版本用 `ref<InstanceType<typeof SearchInput> | null>(null)`。

## 4. 案例：瀑布流的数据职责

拿瀑布流举例：父组件传入列表，子组件算位置。算法思路：

1. 按容器宽度和列宽算出列数。
2. 记下每一列当前的累计高度。
3. 每张新卡片放进最矮的那一列。
4. 更新那一列的累计高度。

布局组件别改传进来的 prop，要给每一项生成新的布局结果：

```ts
interface WaterfallItem {
  id: number
  height: number
}

interface PositionedItem extends WaterfallItem {
  x: number
  y: number
}

function layoutWaterfall(
  items: WaterfallItem[],
  columnCount: number,
  columnWidth: number,
  gap: number,
): PositionedItem[] {
  if (!Number.isInteger(columnCount) || columnCount < 1) {
    throw new RangeError('columnCount 必须是大于 0 的整数')
  }

  const heights = Array.from({ length: columnCount }, () => 0)

  return items.map(item => {
    const column = heights.indexOf(Math.min(...heights))
    const y = heights[column]!
    const positioned = {
      ...item,
      x: column * (columnWidth + gap),
      y,
    }

    heights[column] = y + item.height + gap
    return positioned
  })
}
```

真实的组件还要用 `ResizeObserver` 响应容器尺寸的变化，卸载时断开观察；别只读一次 `document.body.clientWidth`。

## 5. 局部、全局与递归组件

### 5.1 局部优先

`<script setup>` 里导入的组件，模板里能直接用：

```vue
<script setup lang="ts">
import UserCard from '@/components/users/UserCard.vue'

const user = {
  id: 1,
  name: 'Ada',
  role: 'member' as const,
}
</script>

<template>
  <UserCard :user="user" />
</template>
```

局部注册让依赖关系能搜得到，也方便按模块拆包。只有基础按钮、图标这类整个应用都高频用、又很稳定的组件，才考虑全局注册：

```ts
import { createApp } from 'vue'
import App from './App.vue'
import BaseButton from './components/base/BaseButton.vue'

createApp(App)
  .component('BaseButton', BaseButton)
  .mount('#app')
```

### 5.2 递归树组件

递归组件一定要有终止条件，列表的 key 一定要稳定：

```vue
<!-- TreeNode.vue -->
<script setup lang="ts">
interface TreeItem {
  id: string
  label: string
  children?: TreeItem[]
}

defineOptions({ name: 'TreeNode' })

const props = defineProps<{
  node: TreeItem
}>()

const emit = defineEmits<{
  select: [node: TreeItem]
}>()
</script>

<template>
  <li>
    <button type="button" @click="emit('select', props.node)">
      {{ props.node.label }}
    </button>

    <ul v-if="props.node.children?.length">
      <TreeNode
        v-for="child in props.node.children"
        :key="child.id"
        :node="child"
        @select="emit('select', $event)"
      />
    </ul>
  </li>
</template>
```

同名的自引用可以从 SFC 的文件名推出来；`defineOptions({ name })` 还能给 DevTools、`KeepAlive include/exclude` 和递归识别提供一个稳定的名字。

> 版本提示：`defineOptions` 从 Vue 3.3+ 开始内置。用第三方宏插件提供它的方案只适用于旧版本；现代 Vue 不用再为这个宏额外装插件。

## 6. 动态组件

好几个视图共用同一个挂载位置时，用 `<component :is>` 代替一堆重复的 `v-if`：

```vue
<script setup lang="ts">
import { shallowRef } from 'vue'
import ProfileTab from './ProfileTab.vue'
import SecurityTab from './SecurityTab.vue'

const tabs = [
  { id: 'profile', label: '资料', component: ProfileTab },
  { id: 'security', label: '安全', component: SecurityTab },
] as const

const currentTab = shallowRef(tabs[0])
</script>

<template>
  <nav>
    <button
      v-for="tab in tabs"
      :key="tab.id"
      type="button"
      @click="currentTab = tab"
    >
      {{ tab.label }}
    </button>
  </nav>

  <component :is="currentTab.component" />
</template>
```

组件定义不需要深层响应式。要把组件对象放进响应式容器的话，用 `shallowRef` 存当前组件；非得进 `reactive` 的话，用 `markRaw` 标记组件定义，避免没意义的代理。

动态组件只解决同一个页面里的视图切换；要 URL、历史记录、权限路由和页面级代码分割的话，用 Vue Router。

## 7. 插槽：由父组件控制内容

插槽把"组件负责结构"和"父组件负责内容"分开了。

```vue
<!-- DataList.vue -->
<script setup lang="ts" generic="T extends { id: string | number }">
const props = defineProps<{
  items: T[]
}>()

defineSlots<{
  header(): unknown
  default(props: { item: T; index: number }): unknown
  empty(): unknown
}>()
</script>

<template>
  <section class="data-list">
    <header v-if="$slots.header" class="data-list__header">
      <slot name="header" />
    </header>

    <ul v-if="props.items.length">
      <li v-for="(item, index) in props.items" :key="item.id">
        <slot :item="item" :index="index" />
      </li>
    </ul>

    <slot v-else name="empty">暂无数据</slot>
  </section>
</template>
```

父组件使用具名插槽和作用域插槽：

```vue
<DataList :items="users">
  <template #header>
    <h2>用户</h2>
  </template>

  <template #default="{ item, index }">
    {{ index + 1 }}. {{ item.name }}
  </template>

  <template #empty>
    尚未创建用户
  </template>
</DataList>
```

- 默认插槽没有名字，具名插槽用 `#name`。
- 子组件通过 slot props 把当前的渲染上下文提供给父组件，这就是作用域插槽。
- 动态插槽名可以写成 `#[slotName]`，但只在名字确实由配置决定时才用。
- 可选插槽外面的 wrapper 会影响间距或边框的话，先检查 `$slots.name`，免得渲染出一个空壳。
- 纯逻辑的复用优先用 composable；别为了传几个响应式值就引入一个没有 UI 的 renderless 组件。

> 版本提示：`<script setup generic="...">` 这种 SFC 泛型要 Vue 3.3+ 和配套的工具链。旧项目可以先声明具体的 item 类型，或者用普通的 `defineComponent` 泛型方案。

## 8. 异步组件与代码分割

动态 `import()` 会形成一个异步模块的边界，构建工具一般能把它拆成一个独立的 chunk：

```vue
<script setup lang="ts">
import { defineAsyncComponent } from 'vue'
import ErrorPanel from './ErrorPanel.vue'
import LoadingPanel from './LoadingPanel.vue'

const AsyncReport = defineAsyncComponent({
  loader: () => import('./ReportPanel.vue'),
  loadingComponent: LoadingPanel,
  errorComponent: ErrorPanel,
  delay: 200,
  timeout: 30_000,
})
</script>

<template>
  <AsyncReport />
</template>
```

代码分割只是让首屏不下载这个 chunk；第一次真正显示时，网络和解析的成本还是要付。重的、低频的、不在首屏的组件才做成异步，别把每个小组件都拆成一个请求。

### 8.1 `Suspense` 统一异步边界

顶层的 `await` 会让组件的 `setup` 变成一个异步依赖：

```vue
<!-- UserPanel.vue -->
<script setup lang="ts">
interface User {
  id: number
  name: string
}

const response = await fetch('/api/user')
if (!response.ok) throw new Error('用户加载失败')
const user = await response.json() as User
</script>

<template>
  <p>{{ user.name }}</p>
</template>
```

父组件用 `Suspense` 提供统一的 fallback：

```vue
<template>
  <Suspense @pending="onPending" @resolve="onResolve">
    <UserPanel />

    <template #fallback>
      <UserSkeleton />
    </template>
  </Suspense>
</template>
```

默认插槽和 fallback 都要保持单一的直接根节点。已经 resolve 以后，深层的异步变化不一定会让边界重新进入 pending；要重新触发的话，一般要换掉默认插槽的根节点，并给一个稳定的 `key`。

> 版本提示：`Suspense` 还是一个要谨慎使用的实验性能力，它的嵌套行为和生产建议可能随 Vue 版本变。`defineAsyncComponent` 自带 loading/error 状态时，不一定非得用 `Suspense`。

## 9. `Teleport`：改变 DOM 位置，不改变组件关系

弹窗放在有 `overflow: hidden`、`transform` 或者复杂层叠上下文的容器里，很容易被裁掉或定位错。`Teleport` 把 DOM 渲染到目标容器，但逻辑上还是原组件的子树：props、emits、slots 和 provide/inject 都照常有效。

```vue
<script setup lang="ts">
import { ref } from 'vue'

const open = ref(false)
</script>

<template>
  <button type="button" @click="open = true">打开</button>

  <Teleport to="#modals">
    <div v-if="open" class="modal" role="dialog" aria-modal="true">
      <p>确认提交？</p>
      <button type="button" @click="open = false">关闭</button>
    </div>
  </Teleport>
</template>
```

HTML 里提供目标节点：

```html
<div id="app"></div>
<div id="modals"></div>
```

`to` 支持选择器或 DOM 元素，`:disabled` 可以在某些布局下暂时原地渲染。目标节点一般要在挂载时就已经存在。

> 版本提示：Vue 3.5+ 加了 `defer`，能把目标的解析推迟到同一次挂载周期的后面；旧版本不能依赖这个能力。

## 10. `KeepAlive`：缓存组件实例

动态组件切换时，默认会卸载旧实例，局部状态也跟着没了。`KeepAlive` 把失活的实例放进缓存：

```vue
<template>
  <KeepAlive :max="5" include="ProfileTab,SecurityTab">
    <component :is="currentTab.component" :key="currentTab.id" />
  </KeepAlive>
</template>
```

`include`/`exclude` 匹配的是组件的 `name`，不是随便什么标签文字。缓存要限制数量，并且说清楚哪些页面需要保留状态。

被缓存的组件切走时不会马上卸载，而是停用：

```vue
<script setup lang="ts">
import { onActivated, onDeactivated, onMounted, onUnmounted } from 'vue'

onMounted(() => {
  // 实例第一次真正挂载时执行。
})

onActivated(() => {
  // 首次挂载后也会执行；以后每次从缓存恢复时再次执行。
  refreshIfStale()
})

onDeactivated(() => {
  // 暂停计时器、媒体播放或订阅。
})

onUnmounted(() => {
  // 实例最终被缓存淘汰或父树卸载时执行。
})
</script>
```

这些组件别缓存：

- 每次进入都必须清空的敏感流程。
- 地图、视频、大表格这类很占内存的组件，除非收益明确、也设了上限。
- 离开后还会继续跑、又没法正确暂停的后台任务。
- 用户明确希望每次打开都是全新状态的页面。

超过 `max` 时，用近似 LRU 的策略淘汰最久没用的实例。缓存不会自动解决数据新鲜度的问题，还是要在 `onActivated` 里按时间戳、参数或版本判断要不要刷新。

## 11. 选择通信方式

| 场景 | 首选方案 | 原因 |
| --- | --- | --- |
| 父传子只读数据 | Props | 输入显式、可类型检查 |
| 子请求父改变状态 | Emits | 状态所有权留在父组件 |
| 真正的双向组件契约 | `v-model` | 统一 prop + update event，详见下一篇 |
| 父定义子组件内容 | Slots | 结构与内容解耦 |
| 跨很多层的上下文 | provide/inject | 避免无意义的 props 透传 |
| 全应用跨功能共享状态 | Pinia 等 Store | 状态、动作与调试边界明确 |
| 聚焦、打开、校验等命令 | template ref + `defineExpose` | 仅公开最小命令式接口 |
