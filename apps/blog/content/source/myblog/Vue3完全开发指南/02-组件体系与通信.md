# Vue 3 组件体系与通信

## 1. 组件边界与数据流

组件不是为了把文件“切得更多”，而是建立明确的职责和契约。一个典型后台布局可拆为：

```text
App.vue                 应用壳与全局 Provider
└─ AppLayout.vue        页面结构编排
   ├─ AppSidebar.vue    导航展示与选择事件
   ├─ AppHeader.vue     当前用户和页面级命令
   └─ MainContent.vue   页面内容出口
```

稳定的默认通信规则是：

```text
父组件状态 ──props──> 子组件
父组件动作 <──emits── 子组件
父组件内容 ──slots──> 子组件布局出口
```

组件应把输入、输出与可替换内容公开出来，而不是让父组件随意读取、修改其内部状态。

## 2. BEM、Sass 与自适应布局

Sass 可以配合 BEM 组织侧栏、顶栏和内容区布局。BEM 的三个角色：

```text
.app-layout                 Block：独立组件或区域
.app-layout__content        Element：Block 内部组成部分
.app-layout--compact        Modifier：Block 的状态或变体
```

命名是为了让样式归属可见，不是要求所有 DOM 层级都映射成超长类名。一个元素只应属于清晰的 Block。

```vue
<script setup lang="ts">
import AppHeader from './AppHeader.vue'
import AppSidebar from './AppSidebar.vue'
</script>

<template>
  <div class="app-layout">
    <AppSidebar class="app-layout__sidebar" />

    <div class="app-layout__right">
      <AppHeader class="app-layout__header" />
      <main class="app-layout__content">
        <slot />
      </main>
    </div>
  </div>
</template>

<style scoped lang="scss">
.app-layout {
  display: flex;
  height: 100%;
  overflow: hidden;

  &__sidebar {
    flex: 0 0 14rem;
    border-right: 1px solid #d9dce1;
  }

  &__right {
    display: flex;
    flex: 1 1 auto;
    min-width: 0;
    flex-direction: column;
  }

  &__header {
    flex: 0 0 auto;
  }

  &__content {
    flex: 1 1 auto;
    min-height: 0;
    overflow: auto;
  }
}
</style>
```

`min-width: 0` 和 `min-height: 0` 很关键：Flex 子项默认最小尺寸可能阻止它收缩，导致内容区把父容器撑开而不是在自身滚动。

### 2.1 Sass mixin 的适用边界

一种常见做法是用 Sass mixin 生成 BEM 类名。实际项目中，直接写清晰类名通常更易搜索；只有多个组件确实共享同一生成规则时才值得抽象。

```scss
// styles/_layout.scss
@mixin fill-scroll-area {
  min-width: 0;
  min-height: 0;
  overflow: auto;
}
```

```scss
@use '@/styles/layout' as layout;

.app-layout__content {
  @include layout.fill-scroll-area;
}
```

> **版本提示**：Sass 正逐步以 `@use`/`@forward` 取代旧式 `@import`。Vite 的预处理器配置键、Sass 实现与警告策略会变化，应以项目安装版本为准。

## 3. Props 向下，Events 向上

### 3.1 子组件声明契约

```vue
<!-- UserCard.vue -->
<script setup lang="ts">
interface User {
  id: number
  name: string
  role: 'admin' | 'member'
}

interface Props {
  user: User
  selectable?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  selectable: false,
})

const emit = defineEmits<{
  select: [userId: number]
  remove: [userId: number]
}>()

function selectUser() {
  if (props.selectable) emit('select', props.user.id)
}
</script>

<template>
  <article class="user-card" @click="selectUser">
    <strong>{{ props.user.name }}</strong>
    <span>{{ props.user.role }}</span>
    <button type="button" @click.stop="emit('remove', props.user.id)">
      删除
    </button>
  </article>
</template>
```

父组件保持状态所有权：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import UserCard from './UserCard.vue'

interface User {
  id: number
  name: string
  role: 'admin' | 'member'
}

const users = ref<User[]>([])
const selectedId = ref<number | null>(null)

function removeUser(userId: number) {
  users.value = users.value.filter(user => user.id !== userId)
}
</script>

<template>
  <UserCard
    v-for="user in users"
    :key="user.id"
    :user="user"
    selectable
    @select="selectedId = $event"
    @remove="removeUser"
  />
</template>
```

Props 是只读输入。子组件不应直接修改 prop，也不应通过修改 prop 内部对象来偷偷改变父组件状态。需要变更时派发语义事件，由父组件决定如何更新。

`withDefaults` 主要用于类型式 props 的默认值。数组、对象等可变默认值应通过函数创建，以免不同组件实例共享同一引用。

### 3.2 组件事件不会冒泡

原生 DOM 事件可能冒泡，Vue 组件事件不会。孙组件发出的 `saved` 不会自动越过子组件到达祖先；中间组件必须显式监听并重新发出，或者重新设计状态边界。

### 3.3 `defineExpose`：只公开必要的命令式 API

优先使用 props/emits。只有聚焦、校验、打开弹窗等天然命令式行为，才让父组件通过模板引用调用子组件：

```vue
<!-- SearchInput.vue -->
<script setup lang="ts">
import { useTemplateRef } from 'vue'

const input = useTemplateRef<HTMLInputElement>('input')

function focus() {
  input.value?.focus()
}

defineExpose({ focus })
</script>

<template>
  <input ref="input" type="search" />
</template>
```

```vue
<!-- Parent.vue -->
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import SearchInput from './SearchInput.vue'

const searchInput = useTemplateRef<InstanceType<typeof SearchInput>>('searchInput')
</script>

<template>
  <SearchInput ref="searchInput" />
  <button type="button" @click="searchInput?.focus()">聚焦搜索框</button>
</template>
```

> **版本提示**：`useTemplateRef()` 需要 Vue 3.5+。更早版本使用 `ref<InstanceType<typeof SearchInput> | null>(null)`。

## 4. 案例：瀑布流的数据职责

以瀑布流为例，父组件传入列表，子组件计算位置。算法思路是：

1. 根据容器宽度和列宽求列数。
2. 维护每一列当前累计高度。
3. 每个新卡片放入最矮列。
4. 更新该列累计高度。

布局组件不应修改传入的 prop，为每项生成新的布局结果：

```ts
interface WaterfallItem {
  id: number
  height: number
}

interface PositionedItem extends WaterfallItem {
  x: number
  y: number
}

function layoutWaterfall(
  items: WaterfallItem[],
  columnCount: number,
  columnWidth: number,
  gap: number,
): PositionedItem[] {
  if (!Number.isInteger(columnCount) || columnCount < 1) {
    throw new RangeError('columnCount 必须是大于 0 的整数')
  }

  const heights = Array.from({ length: columnCount }, () => 0)

  return items.map(item => {
    const column = heights.indexOf(Math.min(...heights))
    const y = heights[column]!
    const positioned = {
      ...item,
      x: column * (columnWidth + gap),
      y,
    }

    heights[column] = y + item.height + gap
    return positioned
  })
}
```

真实组件还要使用 `ResizeObserver` 响应容器尺寸，并在卸载时断开观察；不要只读取一次 `document.body.clientWidth`。

## 5. 局部、全局与递归组件

### 5.1 局部优先

`<script setup>` 中导入的组件可直接在模板使用：

```vue
<script setup lang="ts">
import UserCard from '@/components/users/UserCard.vue'

const user = {
  id: 1,
  name: 'Ada',
  role: 'member' as const,
}
</script>

<template>
  <UserCard :user="user" />
</template>
```

局部注册让依赖关系可搜索，也有利于按模块拆包。只有基础按钮、图标等真正全应用高频且稳定的组件，才考虑全局注册：

```ts
import { createApp } from 'vue'
import App from './App.vue'
import BaseButton from './components/base/BaseButton.vue'

createApp(App)
  .component('BaseButton', BaseButton)
  .mount('#app')
```

### 5.2 递归树组件

递归组件必须有终止条件，列表 key 必须稳定：

```vue
<!-- TreeNode.vue -->
<script setup lang="ts">
interface TreeItem {
  id: string
  label: string
  children?: TreeItem[]
}

defineOptions({ name: 'TreeNode' })

const props = defineProps<{
  node: TreeItem
}>()

const emit = defineEmits<{
  select: [node: TreeItem]
}>()
</script>

<template>
  <li>
    <button type="button" @click="emit('select', props.node)">
      {{ props.node.label }}
    </button>

    <ul v-if="props.node.children?.length">
      <TreeNode
        v-for="child in props.node.children"
        :key="child.id"
        :node="child"
        @select="emit('select', $event)"
      />
    </ul>
  </li>
</template>
```

同名自引用可由 SFC 文件名推导，`defineOptions({ name })` 还能为 DevTools、`KeepAlive include/exclude` 和递归识别提供稳定名称。

> **版本提示**：`defineOptions` 在 Vue 3.3+ 内置。通过第三方宏插件提供它的方案只适用于旧版本；现代 Vue 不应再为这个宏额外安装插件。

## 6. 动态组件

多个视图共享同一挂载位置时，用 `<component :is>` 代替重复的 `v-if`：

```vue
<script setup lang="ts">
import { shallowRef } from 'vue'
import ProfileTab from './ProfileTab.vue'
import SecurityTab from './SecurityTab.vue'

const tabs = [
  { id: 'profile', label: '资料', component: ProfileTab },
  { id: 'security', label: '安全', component: SecurityTab },
] as const

const currentTab = shallowRef(tabs[0])
</script>

<template>
  <nav>
    <button
      v-for="tab in tabs"
      :key="tab.id"
      type="button"
      @click="currentTab = tab"
    >
      {{ tab.label }}
    </button>
  </nav>

  <component :is="currentTab.component" />
</template>
```

组件定义不需要深度响应式。若把组件对象放进响应式容器，使用 `shallowRef` 保存当前组件，或在必须进入 `reactive` 时用 `markRaw` 标记组件定义，避免无意义的代理。

动态组件只解决同一页面内的视图切换；需要 URL、历史记录、权限路由和页面级代码分割时，应使用 Vue Router。

## 7. 插槽：由父组件控制内容

插槽把“组件负责结构”和“父组件负责内容”分开。

```vue
<!-- DataList.vue -->
<script setup lang="ts" generic="T extends { id: string | number }">
const props = defineProps<{
  items: T[]
}>()

defineSlots<{
  header(): unknown
  default(props: { item: T; index: number }): unknown
  empty(): unknown
}>()
</script>

<template>
  <section class="data-list">
    <header v-if="$slots.header" class="data-list__header">
      <slot name="header" />
    </header>

    <ul v-if="props.items.length">
      <li v-for="(item, index) in props.items" :key="item.id">
        <slot :item="item" :index="index" />
      </li>
    </ul>

    <slot v-else name="empty">暂无数据</slot>
  </section>
</template>
```

父组件消费具名与作用域插槽：

```vue
<DataList :items="users">
  <template #header>
    <h2>用户</h2>
  </template>

  <template #default="{ item, index }">
    {{ index + 1 }}. {{ item.name }}
  </template>

  <template #empty>
    尚未创建用户
  </template>
</DataList>
```

- 默认插槽没有名字，具名插槽用 `#name`。
- 子组件通过 slot props 向父组件提供当前渲染上下文，这就是作用域插槽。
- 动态插槽名可写成 `#[slotName]`，但只有名称确实由配置驱动时才使用。
- 可选插槽的 wrapper 会影响间距或边框时，先检查 `$slots.name`，避免渲染空壳。
- 纯逻辑复用优先 composable；不要为了传几个响应式值就引入无 UI 的 renderless 组件。

> **版本提示**：`<script setup generic="...">` 的 SFC 泛型能力需要 Vue 3.3+ 及配套工具链。旧项目可以先声明具体 item 类型，或使用普通 `defineComponent` 泛型方案。

## 8. 异步组件与代码分割

动态 `import()` 会形成异步模块边界，构建工具通常可把它拆成独立 chunk：

```vue
<script setup lang="ts">
import { defineAsyncComponent } from 'vue'
import ErrorPanel from './ErrorPanel.vue'
import LoadingPanel from './LoadingPanel.vue'

const AsyncReport = defineAsyncComponent({
  loader: () => import('./ReportPanel.vue'),
  loadingComponent: LoadingPanel,
  errorComponent: ErrorPanel,
  delay: 200,
  timeout: 30_000,
})
</script>

<template>
  <AsyncReport />
</template>
```

代码分割只会让首屏不下载该 chunk；首次真正展示时仍要支付网络和解析成本。应把重、低频、非首屏组件异步化，而不是把每个小组件都拆成请求。

### 8.1 `Suspense` 统一异步边界

顶层 `await` 会让组件的 `setup` 成为异步依赖：

```vue
<!-- UserPanel.vue -->
<script setup lang="ts">
interface User {
  id: number
  name: string
}

const response = await fetch('/api/user')
if (!response.ok) throw new Error('用户加载失败')
const user = await response.json() as User
</script>

<template>
  <p>{{ user.name }}</p>
</template>
```

父组件用 `Suspense` 提供统一 fallback：

```vue
<template>
  <Suspense @pending="onPending" @resolve="onResolve">
    <UserPanel />

    <template #fallback>
      <UserSkeleton />
    </template>
  </Suspense>
</template>
```

默认插槽与 fallback 都应保持单一直接根节点。已经 resolve 后，深层异步变化不一定让边界重新进入 pending；需要重新触发时通常要替换默认插槽根节点并提供稳定 `key`。

> **版本提示**：`Suspense` 仍属于需要谨慎采用的实验性能力，其嵌套行为和生产建议可能随 Vue 版本变化。`defineAsyncComponent` 自带 loading/error 状态时并不强制要求 `Suspense`。

## 9. `Teleport`：改变 DOM 位置，不改变组件关系

弹窗放在有 `overflow: hidden`、`transform` 或复杂层叠上下文的容器内，容易被裁切或错误定位。`Teleport` 把 DOM 渲染到目标容器，但逻辑上仍是原组件的子树：props、emits、slots 和 provide/inject 都保持有效。

```vue
<script setup lang="ts">
import { ref } from 'vue'

const open = ref(false)
</script>

<template>
  <button type="button" @click="open = true">打开</button>

  <Teleport to="#modals">
    <div v-if="open" class="modal" role="dialog" aria-modal="true">
      <p>确认提交？</p>
      <button type="button" @click="open = false">关闭</button>
    </div>
  </Teleport>
</template>
```

HTML 中提供目标节点：

```html
<div id="app"></div>
<div id="modals"></div>
```

`to` 支持选择器或 DOM 元素，`:disabled` 可以在某些布局下暂时原地渲染。目标通常应在挂载时已经存在。

> **版本提示**：Vue 3.5+ 增加 `defer`，可把目标解析推迟到同一次挂载周期的后面；旧版本不能依赖该能力。

## 10. `KeepAlive`：缓存组件实例

动态组件切换时默认会卸载旧实例，局部状态也随之丢失。`KeepAlive` 将失活实例移入缓存：

```vue
<template>
  <KeepAlive :max="5" include="ProfileTab,SecurityTab">
    <component :is="currentTab.component" :key="currentTab.id" />
  </KeepAlive>
</template>
```

`include`/`exclude` 匹配组件的 `name`，不是任意标签文字。缓存应限制数量，并明确哪些页面需要保留状态。

被缓存的组件切走时不会立即卸载，而会停用：

```vue
<script setup lang="ts">
import { onActivated, onDeactivated, onMounted, onUnmounted } from 'vue'

onMounted(() => {
  // 实例第一次真正挂载时执行。
})

onActivated(() => {
  // 首次挂载后也会执行；以后每次从缓存恢复时再次执行。
  refreshIfStale()
})

onDeactivated(() => {
  // 暂停计时器、媒体播放或订阅。
})

onUnmounted(() => {
  // 实例最终被缓存淘汰或父树卸载时执行。
})
</script>
```

不要缓存以下组件：

- 必须每次进入都清空的敏感流程。
- 地图、视频、大表格等高内存组件，除非有明确收益和上限。
- 离开后仍会运行且无法正确暂停的后台任务。
- 用户明确期待每次打开都获得全新状态的页面。

`max` 超限时使用近似 LRU 的策略淘汰较久未使用实例。缓存并不自动解决数据新鲜度，仍需在 `onActivated` 中按时间戳、参数或版本判断是否刷新。

## 11. 选择通信方式

| 场景 | 首选方案 | 原因 |
| --- | --- | --- |
| 父传子只读数据 | Props | 输入显式、可类型检查 |
| 子请求父改变状态 | Emits | 状态所有权留在父组件 |
| 真正的双向组件契约 | `v-model` | 统一 prop + update event，详见下一篇 |
| 父定义子组件内容 | Slots | 结构与内容解耦 |
| 跨很多层的上下文 | provide/inject | 避免无意义的 props 透传 |
| 全应用跨功能共享状态 | Pinia 等 Store | 状态、动作与调试边界明确 |
| 聚焦、打开、校验等命令 | template ref + `defineExpose` | 仅公开最小命令式接口 |

## 12. 复习清单

1. 把包含导航、头部、列表和筛选表单的大组件拆成容器、表单、列表与列表项，写出每个 props/emits 契约。
2. 用 BEM + scoped Sass 实现固定侧栏和独立滚动内容区，验证窄窗口下不会横向撑破。
3. 实现递归树，节点事件逐层显式转发，并解释组件事件为什么不会冒泡。
4. 实现动态 Tab，比较普通切换、异步组件和 `KeepAlive` 对状态与网络加载的影响。
5. 写一个 typed scoped slot 列表组件，分别提供 header、default 和 empty 插槽。
6. 将弹窗 Teleport 到独立容器，并验证组件的 emit 与注入上下文仍然有效。
