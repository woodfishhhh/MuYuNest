# Vue 3 自定义能力与运行时机制

## 1. 先选对复用边界

Vue 提供的几种复用方式，解决的是不同层次的问题：

| 能力 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 组件 | 可复用的 UI、交互和公开契约 | 纯 DOM 小行为 |
| composable | 响应式状态、生命周期、副作用逻辑 | 直接规定一段 UI 长什么样 |
| 自定义指令 | 必须落到真实 DOM 的底层行为 | 通用业务逻辑、权限后端校验 |
| 插件 | 应用级安装、依赖注入、全局组件或指令 | 单页面的临时逻辑 |
| `globalProperties` | 兼容实例式全局 API | Composition API 的默认依赖传递方式 |

经验上的顺序：普通函数 -> composable -> 组件 -> 自定义指令 -> 插件。越往后影响范围越大，问题的边界真的需要时才往后升级。

## 2. 自定义指令

### 2.1 生命周期与绑定信息

`<script setup>` 里，以 `v` 开头的驼峰变量会被认成局部指令：

```vue
<script setup lang="ts">
import type { Directive } from 'vue'

interface HighlightValue {
  background: string
  foreground?: string
}

const vHighlight: Directive<HTMLElement, HighlightValue> = {
  mounted(el, binding) {
    el.style.background = binding.value.background
    el.style.color = binding.value.foreground ?? ''
  },
  updated(el, binding) {
    el.style.background = binding.value.background
    el.style.color = binding.value.foreground ?? ''
  },
  unmounted(el) {
    el.style.removeProperty('background')
    el.style.removeProperty('color')
  },
}
</script>

<template>
  <article v-highlight:card.important="{
    background: '#17324d',
    foreground: '#fff',
  }">
    内容
  </article>
</template>
```

指令的钩子大致对应组件的更新阶段：

| 钩子 | 元素状态 | 常见用途 |
| --- | --- | --- |
| `created` | 属性和监听器应用前 | 极少使用 |
| `beforeMount` | 即将插入 DOM | 插入前准备 |
| `mounted` | 已插入 DOM | 聚焦、监听、Observer |
| `beforeUpdate` | 组件 VNode 更新前 | 极少使用 |
| `updated` | 组件及子节点更新后 | 根据新 binding 同步 DOM |
| `beforeUnmount` | 卸载前 | 提前停止任务 |
| `unmounted` | 已卸载 | 移除监听、断开 Observer |

`binding` 里常用的字段：

- `value`：这次传的值。
- `oldValue`：上次传的值，只在更新阶段有意义。
- `arg`：`v-highlight:card` 里的 `card`。
- `modifiers`：`.important` 这类修饰符的集合。
- `instance`：所属组件的公开实例；一般别依赖它，容易造成隐式耦合。

函数简写会同时当作 `mounted` 和 `updated`：

```ts
import type { Directive } from 'vue'

const vColor: Directive<HTMLElement, string> = (el, binding) => {
  el.style.color = binding.value
}
```

一旦要清理监听器或 Observer，就别用函数简写，改用对象形式的钩子。

### 2.2 按钮权限指令不是安全边界

把权限状态同步到 DOM 上能改善界面，但指令不负责真正的授权：

```ts
import type { Directive } from 'vue'

interface PermissionBinding {
  required: string
  granted: ReadonlySet<string>
}

export const vPermission: Directive<HTMLElement, PermissionBinding> = {
  mounted: syncPermission,
  updated: syncPermission,
}

function syncPermission(
  el: HTMLElement,
  { value }: { value: PermissionBinding },
): void {
  const allowed = value.granted.has(value.required)
  el.hidden = !allowed
  el.setAttribute('aria-hidden', String(!allowed))
}
```

```vue
<button
  v-permission="{ required: 'product:delete', granted: permissions }"
  @click="removeProduct"
>
  删除
</button>
```

服务端还是要对删除接口再鉴权一次。用户可以改 DOM、直接发请求或者伪造本地状态；"按钮不见了"证明不了"这个操作做不了"。

### 2.3 拖拽：事件、坐标与清理缺一不可

拖拽的状态机：按下 -> 移动 -> 抬起/取消。现代实现优先用 Pointer Events，鼠标、触控笔和触摸都能支持：

```ts
import type { Directive } from 'vue'

type Cleanup = () => void
const cleanups = new WeakMap<HTMLElement, Cleanup>()

export const vDrag: Directive<HTMLElement> = {
  mounted(el) {
    const previousTouchAction = el.style.touchAction
    el.style.touchAction = 'none'
    let activeCleanup: Cleanup | undefined

    const onPointerDown = (event: PointerEvent) => {
      if (event.button !== 0) return

      activeCleanup?.()

      const rect = el.getBoundingClientRect()
      const offsetX = event.clientX - rect.left
      const offsetY = event.clientY - rect.top
      const pointerId = event.pointerId

      el.setPointerCapture(pointerId)

      const onPointerMove = (moveEvent: PointerEvent) => {
        el.style.left = `${moveEvent.clientX - offsetX}px`
        el.style.top = `${moveEvent.clientY - offsetY}px`
      }

      const stop = () => {
        el.removeEventListener('pointermove', onPointerMove)
        el.removeEventListener('pointerup', stop)
        el.removeEventListener('pointercancel', stop)
        if (el.hasPointerCapture(pointerId)) {
          el.releasePointerCapture(pointerId)
        }
        if (activeCleanup === stop) activeCleanup = undefined
      }

      activeCleanup = stop
      el.addEventListener('pointermove', onPointerMove)
      el.addEventListener('pointerup', stop)
      el.addEventListener('pointercancel', stop)
    }

    el.addEventListener('pointerdown', onPointerDown)
    cleanups.set(el, () => {
      activeCleanup?.()
      el.removeEventListener('pointerdown', onPointerDown)
      el.style.touchAction = previousTouchAction
    })
  },
  unmounted(el) {
    cleanups.get(el)?.()
    cleanups.delete(el)
  },
}
```

完整的拖拽组件还要处理容器边界、滚动、键盘替代操作、定位方式和 transform。`clientX/clientY - offset` 只表达了核心的几何关系。

### 2.4 图片懒加载与 `IntersectionObserver`

浏览器原生的图片懒加载优先用：

```html
<img loading="lazy" decoding="async" src="/images/cover.webp" alt="文章封面">
```

要占位图、进入视口后再换资源这类自定义行为时，再用指令：

```ts
import type { Directive } from 'vue'

interface LazyImageState {
  observer: IntersectionObserver
  currentUrl: string
  loaded: boolean
}

const lazyImages = new WeakMap<HTMLImageElement, LazyImageState>()

export const vLazyImage: Directive<HTMLImageElement, string> = {
  mounted(el, binding) {
    const observer = new IntersectionObserver(
      ([entry]) => {
        const state = lazyImages.get(el)
        if (!entry?.isIntersecting || !state) return

        el.src = state.currentUrl
        state.loaded = true
        observer.disconnect()
      },
      { rootMargin: '200px 0px' },
    )

    lazyImages.set(el, {
      observer,
      currentUrl: binding.value,
      loaded: false,
    })
    observer.observe(el)
  },
  updated(el, binding) {
    if (binding.value === binding.oldValue) return

    const state = lazyImages.get(el)
    if (!state) return

    state.currentUrl = binding.value
    if (state.loaded) el.src = state.currentUrl
  },
  unmounted(el) {
    lazyImages.get(el)?.observer.disconnect()
    lazyImages.delete(el)
  },
}
```

Vite 里批量导入静态资源可以用 `import.meta.glob`：

```ts
const imageUrls = import.meta.glob<string>('./assets/gallery/*.{png,jpg,webp}', {
  eager: true,
  import: 'default',
  query: '?url',
})

const images = Object.values(imageUrls)
```

默认的 `eager: false` 模式返回动态导入函数，能参与代码分包；`eager: true` 会在当前模块求值时就导入。`import.meta.glob` 是 Vite 的 API，不是 ECMAScript 或 Vue 的标准，Webpack 项目不能原样照搬。

## 3. Composables：复用有状态逻辑

Composable 是基于 Vue 的响应式和生命周期组合出来的函数，按约定以 `use` 开头。它比 mixin 更明确：输入、返回值和依赖在调用的地方都看得到，也不会出现同名字段互相覆盖。

### 3.1 一个可靠的元素尺寸 composable

元素尺寸适合用 `ResizeObserver` 监听。别让 composable 在里面用写死的 CSS 选择器偷偷查 DOM；传一个模板 ref 进去，依赖更清楚：

```ts
// composables/useElementSize.ts
import {
  readonly,
  shallowRef,
  toValue,
  watchEffect,
  type MaybeRefOrGetter,
} from 'vue'

export function useElementSize(
  target: MaybeRefOrGetter<HTMLElement | null>,
) {
  const width = shallowRef(0)
  const height = shallowRef(0)

  watchEffect((onCleanup) => {
    const element = toValue(target)
    if (!element) return

    const observer = new ResizeObserver(([entry]) => {
      if (!entry) return
      width.value = entry.contentRect.width
      height.value = entry.contentRect.height
    })

    observer.observe(element)
    onCleanup(() => observer.disconnect())
  })

  return {
    width: readonly(width),
    height: readonly(height),
  }
}
```

```vue
<script setup lang="ts">
import { useTemplateRef } from 'vue'
import { useElementSize } from '@/composables/useElementSize'

const panel = useTemplateRef<HTMLElement>('panel')
const { width, height } = useElementSize(panel)
</script>

<template>
  <section ref="panel">
    {{ Math.round(width) }} x {{ Math.round(height) }}
  </section>
</template>
```

> `useTemplateRef()` 要 Vue 3.5+。Vue 3.4 及更早的版本用 `const panel = ref<HTMLElement | null>(null)`，模板里的 `ref="panel"` 不用改。

好的 composable 一般有这些特点：

- 输入支持普通值、ref 或 getter 时，用 `toValue()` 统一读取。
- 返回一个装着 refs 的普通对象，调用方解构以后还是响应式的。
- 定时器、监听器、Observer 和没完成的请求，在失效或卸载时都会清理。
- 派生值用 `computed`，副作用用 `watch/watchEffect`。
- API 描述的是业务能力，不是把一大包内部状态都暴露出去。

### 3.2 Canvas 转 Base64 的边界

Canvas 能把图片画成像素，再调 `toDataURL()` 导出，但要清楚这几条边界：

- 等图片加载、解码完再画，优先用 `await image.decode()`。
- 跨域图片必须拿到正确的 CORS 响应，不然 Canvas 会被污染，导出时报安全错误。
- 大图同步调 `toDataURL()` 会生成很长的字符串，还会卡住主线程；上传场景优先用 `canvas.toBlob()`。
- composable 要接收元素 ref 或文件数据，别依赖写死的 `querySelector()`。

## 4. 从 composable 到可发布库

同一个核心函数可以被 composable 和指令适配器复用，但库的公开 API、构建和包的元数据要分开设计：

```text
ResizeObserver 核心逻辑
        ├─ useElementSize(target)       组合式 API
        └─ v-resize="callback"         模板指令适配器
```

Vite 库模式的关键：入口明确、Vue 外置、类型声明跟着包一起发布。先装构建工具，让 lockfile 固定实际的版本：

```bash
npm install -D "vite@^8.1.0" "@vitejs/plugin-vue@^6.0.0" "vue@^3.5.0" "vue-tsc@^3.3.0" "typescript@^6.0.0"
```

`typescript` 和 `vue-tsc` 要按兼容的主版本成对升级；这里把 TypeScript 限制在 6.x，免得包管理器直接拉到还不兼容的新主版本。

```ts
// vite.config.ts
import { resolve } from 'node:path'
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue()],
  build: {
    lib: {
      entry: resolve(import.meta.dirname, 'src/index.ts'),
      name: 'VueElementTools',
      formats: ['es', 'umd'],
      fileName: (format) =>
        format === 'es'
          ? 'vue-element-tools.js'
          : 'vue-element-tools.umd.cjs',
    },
    rolldownOptions: {
      external: ['vue'],
      output: {
        globals: { vue: 'Vue' },
      },
    },
  },
})
```

Vite 只管 JavaScript bundle；声明文件交给 `vue-tsc` 单独生成。单独一份配置，能避免继承应用配置里的 `noEmit: true`，也让声明目录保持稳定：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "types": ["vite/client"],
    "strict": true,
    "jsx": "preserve",
    "skipLibCheck": true,
    "declaration": true,
    "declarationMap": true,
    "emitDeclarationOnly": true,
    "rootDir": "./src",
    "outDir": "./dist"
  },
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue"]
}
```

上面的内容存成 `tsconfig.build.json`。包脚本必须先构建 bundle、再生成声明，因为 Vite 开始构建时会清空 `dist`：

```json
{
  "name": "vue-element-tools",
  "version": "0.1.0",
  "type": "module",
  "files": ["dist"],
  "types": "./dist/index.d.ts",
  "scripts": {
    "build": "npm run build:bundle && npm run build:types",
    "build:bundle": "vite build",
    "build:types": "vue-tsc -p tsconfig.build.json",
    "verify:dist": "node --input-type=module -e \"import { existsSync } from 'node:fs'; const files = ['dist/index.d.ts', 'dist/vue-element-tools.js', 'dist/vue-element-tools.umd.cjs']; const missing = files.filter((file) => !existsSync(file)); if (missing.length) throw new Error('missing: ' + missing.join(', '))\"",
    "pack:check": "npm run build && npm run verify:dist && npm pack --dry-run"
  },
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/vue-element-tools.js",
      "require": "./dist/vue-element-tools.umd.cjs"
    }
  },
  "peerDependencies": {
    "vue": "^3.5.0"
  }
}
```

产物路径由两组配置直接对应：`rootDir: "./src"` 加 `outDir: "./dist"`，会把 `src/index.ts` 的声明写到 `dist/index.d.ts`；`fileName` 函数则固定生成 `dist/vue-element-tools.js` 和 `dist/vue-element-tools.umd.cjs`。这三个路径和 `types`、`exports`、`verify:dist` 完全一致。发布前跑一下 `npm run pack:check`，少了任何一个入口，都会在打包预检之前失败。

> 构建配置约束：用了 Rolldown 的 Vite 版本配 `rolldownOptions`；还在用 Rollup 的版本配 `rollupOptions`。字段名、输出的扩展名和默认的 format，以 lockfile 对应版本的文档为准。Vue 可以作为本地开发依赖，同时也要放进 `peerDependencies`，免得使用方装出第二份 Vue。

发布前至少验证：干净安装、ESM/CJS 入口、`.d.ts`、样式导出、Vue 的 peer 范围、最小的使用示例，以及 `npm pack --dry-run` 的内容。

## 5. 应用级插件与全局能力

### 5.1 `globalProperties` 的位置

Vue 3 用 `app.config.globalProperties` 代替 Vue 2 的 `Vue.prototype`：

```ts
app.config.globalProperties.$formatMoney = (value: number) =>
  new Intl.NumberFormat('zh-CN', {
    style: 'currency',
    currency: 'CNY',
  }).format(value)
```

它在模板和 Options API 的 `this` 上能访问到。Composition API 里别为了读它去依赖 `getCurrentInstance().proxy`；普通工具直接 `import`，应用级的依赖优先用 `provide/inject`。全局属性太多会让来源看不清，也容易和第三方库重名。

确实要暴露全局属性的话，要扩充类型：

```ts
// src/types/vue.d.ts
export {}

declare module 'vue' {
  interface ComponentCustomProperties {
    $formatMoney(value: number): string
  }
}
```

### 5.2 插件契约

Vue 插件可以是函数，也可以是带 `install(app, options)` 的对象。常见的任务：

1. 注册全局组件或指令。
2. 通过 `app.provide()` 注入服务。
3. 极少量地扩展 `globalProperties`。

下面把全局 Loading 设计成一个显式注入的服务，而不是从组件 VNode 的内部字段里拿 `setupState`：

```ts
// plugins/loading.ts
import {
  inject,
  readonly,
  shallowRef,
  type App,
  type InjectionKey,
  type Plugin,
  type Ref,
} from 'vue'

export interface LoadingService {
  visible: Readonly<Ref<boolean>>
  show(): void
  hide(): void
}

const loadingKey: InjectionKey<LoadingService> = Symbol('loading')

export const loadingPlugin: Plugin = {
  install(app: App) {
    const visible = shallowRef(false)
    const service: LoadingService = {
      visible: readonly(visible),
      show: () => { visible.value = true },
      hide: () => { visible.value = false },
    }

    app.provide(loadingKey, service)
  },
}

export function useLoading(): LoadingService {
  const service = inject(loadingKey)
  if (!service) throw new Error('loadingPlugin 尚未安装')
  return service
}
```

根组件放一个声明式的 `<LoadingHost />` 读 `visible`。这样 DOM 的生命周期还是由 Vue 管，插件只负责应用级的服务。确实要命令式 `render()` 的话，就得处理挂载容器、`appContext`、重复调用、卸载清理和 SSR。

`app.use()` 会避免同一个插件对象被重复安装，并把额外的参数传给安装函数；它返回 app 本身，所以能链式调用。业务代码没必要照着 Vue 源码再实现一个 `use()`。

### 5.3 UI 库选择不是语法偏好比赛

选 Element Plus、Ant Design Vue、View UI 或 Vant 这类 UI 库时，至少评估：

- 对 Vue 3、TypeScript、无障碍和 SSR 的支持程度。
- 表格、表单、分页、弹层这些核心业务组件覆盖得怎么样。
- 按需导入、主题定制、包体积和更新频率。
- 设计规范跟产品匹不匹配，而不是哪个示例代码更好抄。
- 团队愿不愿意维护一层二次封装，以及升级时的回归成本。

全量 `app.use(UiLibrary)` 方便，但可能让初始包变大；自动按需导入的插件也是跟版本强相关的工具。安装命令、Volar 的类型配置和组件 API，都要查锁定的那个 UI 库版本的官方文档。

## 6. SFC CSS 的作用域与穿透

### 6.1 `scoped` 的编译模型

`<style scoped>` 不是 Shadow DOM。编译器会给当前组件的元素加上类似 `data-v-xxxx` 的属性，再把选择器改写成属性选择器：

```css
.panel { color: red; }

/* 概念上的编译结果 */
.panel[data-v-xxxx] { color: red; }
```

子组件的根元素会同时带上父、子两个作用域标记，方便父组件控制布局；子组件更深层的内部 DOM，不会自动匹配父作用域的选择器。

### 6.2 四种常用写法

```vue
<script setup lang="ts">
import { shallowRef } from 'vue'

const accent = shallowRef('#0f766e')
</script>

<template>
  <section class="panel">
    <slot />
  </section>
</template>

<style scoped>
.panel {
  color: v-bind(accent);
}

/* 修改子组件内部目标，谨慎依赖第三方内部类名 */
.panel :deep(.el-input__wrapper) {
  box-shadow: none;
}

/* 只选择由父组件传入当前 slot 的内容 */
:slotted(.notice) {
  font-weight: 700;
}

/* 在 scoped 块中声明真正的全局选择器 */
:global(body.is-modal-open) {
  overflow: hidden;
}
</style>
```

CSS Modules 则是把类名当作模块对象导入，适合渲染函数、TSX，或者需要显式类名映射的组件：

```vue
<script setup lang="ts">
import { useCssModule } from 'vue'

const classes = useCssModule()
</script>

<template>
  <section :class="classes.panel">内容</section>
</template>

<style module>
.panel {
  border: 1px solid #d0d7de;
}
</style>
```

样式覆盖的优先顺序：组件公开的 theme/token API -> CSS 变量 -> `::part`（Web Component）-> `:deep()`。直接依赖第三方的内部类名最脆弱，升级时一定要做视觉回归。

## 7. Utility-first CSS 与 Tailwind

原子类把单条 CSS 声明编进类名里，构建器只生成源码里实际用到的规则。好处是少写重复的声明、少为起名争论；代价是模板里的类名很密、动态类名的提取受限、设计约束要靠团队统一。

Tailwind CSS 4 在 Vite 项目里用单独的插件：

```bash
npm install tailwindcss @tailwindcss/vite
```

```ts
// vite.config.ts
```

## 8. Event Loop 与 Vue 更新调度

### 8.1 浏览器事件循环

JavaScript 主线程一次只执行一个任务。更准确的顺序是：

```text
取出一个 task（首段脚本、计时器回调、事件回调等）
  ↓ 执行到调用栈清空
清空 microtask 队列（Promise 回调、queueMicrotask 等）
  ↓
浏览器获得一次渲染机会
  ↓
进入下一个 task
```

- `Promise` 的构造器本身是同步执行的，`.then/.catch/.finally` 的回调进 microtask。
- `async` 函数在 `await` 之前是同步执行的，之后恢复执行的逻辑相当于 microtask；不能笼统地说"await 下面都是异步"。
- `setTimeout` 的回调进 task 队列；延迟时间是最早能被调度的时间，不是精确的执行时间。
- Web Worker 能在别的线程做计算，但不能直接操作页面 DOM，通信靠消息和结构化克隆/可转移对象。

### 8.2 Vue 为什么批量更新 DOM

给响应式状态赋值是立刻生效的，但 Vue 会把组件的更新任务放进调度队列，等当前同步代码跑完再统一刷新。所以连续改一千次，不会机械地重渲染一千次，而是尽量合并成一次组件更新。

```ts
for (let index = 0; index < 1000; index += 1) {
  count.value = index
}

// 数据此时已经是 999，DOM 刷新由调度器批处理。
```

`nextTick()` 返回的 Promise 在 Vue 当前的更新队列刷新后完成，适合读更新后的 DOM：

```vue
<script setup lang="ts">
import { nextTick, ref, shallowRef, useTemplateRef } from 'vue'

interface Message {
  id: number
  text: string
}

const messages = ref<Message[]>([])
const draft = shallowRef('')
const list = useTemplateRef<HTMLElement>('list')

async function sendMessage() {
  const text = draft.value.trim()
  if (!text) return

  messages.value.push({ id: Date.now(), text })
  draft.value = ''

  await nextTick()
  list.value?.scrollTo({
    top: list.value.scrollHeight,
    behavior: 'smooth',
  })
}
</script>

<template>
  <section ref="list" class="message-list">
    <p v-for="message in messages" :key="message.id">
      {{ message.text }}
    </p>
  </section>

  <input v-model="draft" @keyup.enter="sendMessage">
</template>
```

副作用本来就是由某个响应式值触发的话，可以用后置的 watcher：

```ts
watch(
  () => messages.value.length,
  () => {
    list.value?.scrollTo({ top: list.value.scrollHeight })
  },
  { flush: 'post' },
)
```

几条重要的边界：

- `nextTick()` 等的是 Vue 的 DOM patch，不保证浏览器已经画完了。
- 要在下一帧做视觉测量或动画的话，先 `await nextTick()`，再等 `requestAnimationFrame()`。
- 别把 `nextTick()` 当成"DOM 不对就随手加一下"的修复。先确认这个操作是不是真的依赖更新后的 DOM。
- 读完布局马上又写布局，可能造成强制同步布局；复杂动画优先用 CSS/Transition，或者合理地分帧。

## 9. 自检清单

- [ ] 只有必须直接操作 DOM 的行为才写成自定义指令，并在卸载时清理资源。
- [ ] Composable 的输入、返回值和副作用边界都是明确的，不用藏起来的全局选择器。
- [ ] 应用级依赖优先用 `provide/inject`，`globalProperties` 保持少量并补全类型。
- [ ] 发布库时外置 Vue、声明 peer 版本、发布 `.d.ts`，并验证使用方。
- [ ] 样式覆盖优先用公开的 token/API，`:deep()` 用到的第三方内部类名有回归测试。
- [ ] Tailwind、Vite 库模式和 Vue 宏都按 lockfile 对应的版本查文档。
- [ ] `nextTick()` 只用来等 Vue 更新完成，别和"下一帧已经画完"混为一谈。
