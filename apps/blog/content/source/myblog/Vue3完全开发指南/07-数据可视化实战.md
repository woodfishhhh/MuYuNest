# Vue 3 数据可视化实战

一个可靠的三栏数据大屏，核心不是“把图画出来”，而是打通完整的数据链路：

```text
上游数据源
    ↓
Node/Express 适配层：请求、裁剪、统一结构
    ↓
Vue API 层：处理 HTTP、超时和错误
    ↓
Pinia：保存原始业务状态
    ↓
computed：派生地图、表格、指标、饼图和折线图数据
    ↓
ECharts / Vue 组件：只负责展示和交互
```

## 1. 先确定数据边界

从公开页面的 Network 面板观察接口并用 API 客户端验证请求之前，要先完成三项判断：

1. 数据是否允许复用，是否有许可、署名或非商业限制。
2. 接口是否稳定，字段是否可能缺失，能否承受自己的请求频率。
3. 浏览器是否应直接访问上游。涉及密钥、跨域或字段清洗时，应由自己的服务端适配。

不要把“没有 Referer、Cookie 或鉴权校验”理解成可以任意使用。技术上可访问不等于获得了数据使用授权。

### 1.1 前后端职责

| 层 | 主要职责 | 不应承担 |
| --- | --- | --- |
| Express 适配层 | 调上游、设置超时、校验响应、裁剪字段 | 页面状态与图表配置 |
| Vue API 层 | 统一请求入口、解析 HTTP 错误 | 长期保存全局状态 |
| Pinia | 保存原始数据、加载和错误状态 | 直接操作 DOM 或 ECharts |
| `computed` | 生成各视图需要的数据 | 发请求、写 Store |
| 图表组件 | 初始化、更新、销毁图表 | 猜测接口字段 |

### 1.2 数据类型

数据可以收敛为省级列表、城市明细、全国总量和每日新增。只定义真正使用的字段，不必把上游几百个字段全部复制进业务类型。

```ts
export interface MetricGroup {
  localConfirm: number;
  nowConfirm: number;
  confirm: number;
  noInfect: number;
  importedCase: number;
  dead: number;
}

export interface CityStat {
  id: string;
  name: string;
  todayConfirm: number;
  totalConfirm: number;
  totalHeal: number;
  totalDead: number;
}

export interface ProvinceStat {
  id: string;
  name: string;
  nowConfirm: number;
  children: CityStat[];
}

export interface TrendPoint {
  date: string;
  value: number;
}

export interface Coordinate {
  longitude: number;
  latitude: number;
}

export interface DashboardPayload {
  chinaAdd: MetricGroup;
  chinaTotal: MetricGroup;
  provinces: ProvinceStat[];
  cityTop: CityStat[];
  trend: TrendPoint[];
}
```

字段命名应在适配层统一。上游即使使用 `today.confirm`、`total.confirm` 等嵌套结构，组件也不应到处重复解构这些细节。

## 2. Node 适配层

Express 适配层可以保持很薄，但必须补上游超时、状态检查、数据校验和错误响应：

```ts
import express from 'express';

const app = express();
const upstreamUrl = process.env.UPSTREAM_URL;

if (!upstreamUrl) {
  throw new Error('UPSTREAM_URL is required');
}

app.get('/api/dashboard', async (_request, response) => {
  try {
    const upstream = await fetch(upstreamUrl, {
      signal: AbortSignal.timeout(8_000),
      headers: { accept: 'application/json' },
    });

    if (!upstream.ok) {
      throw new Error('upstream returned ' + upstream.status);
    }

    const raw: unknown = await upstream.json();
    const data = normalizeDashboardPayload(raw);
    response.json({ data });
  } catch (error) {
    console.error('dashboard upstream failed', error);
    response.status(502).json({ message: '数据源暂时不可用' });
  }
});

app.listen(3333, '127.0.0.1');
```

`normalizeDashboardPayload()` 是边界校验函数。生产项目可用已有的 schema 校验工具；没有工具时也至少逐项判断对象、数组和数值，不能用一次类型断言假装外部 JSON 已经可信。

开发阶段若前端与接口端口不同，优先使用 Vite 代理，让浏览器始终请求同源的 `/api`：

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:3333',
        changeOrigin: true,
      },
    },
  },
});
```

CORS 是浏览器同源策略的访问控制机制，不是服务端鉴权。若必须由 Express 开 CORS，应只允许明确的前端 Origin，而不是无条件放开所有来源。

## 3. API 层与 Pinia

### 3.1 请求函数

```ts
// src/api/dashboard.ts
import type { DashboardPayload } from '@/types/dashboard';

interface ApiEnvelope<T> {
  data: T;
}

export async function fetchDashboard(
  signal?: AbortSignal,
): Promise<DashboardPayload> {
  const response = await fetch('/api/dashboard', { signal });

  if (!response.ok) {
    throw new Error('加载失败：HTTP ' + response.status);
  }

  const body = (await response.json()) as ApiEnvelope<DashboardPayload>;
  return body.data;
}
```

### 3.2 Store 只保存源状态

```ts
// src/stores/dashboard.ts
import { defineStore } from 'pinia';
import { shallowRef } from 'vue';
import { fetchDashboard } from '@/api/dashboard';
import type { DashboardPayload } from '@/types/dashboard';

export const useDashboardStore = defineStore('dashboard', () => {
  const data = shallowRef<DashboardPayload | null>(null);
  const loading = shallowRef(false);
  const error = shallowRef<string | null>(null);
  let latestRequestId = 0;

  async function load(signal?: AbortSignal): Promise<void> {
    const requestId = ++latestRequestId;
    loading.value = true;
    error.value = null;

    try {
      const nextData = await fetchDashboard(signal);
      if (requestId !== latestRequestId) return;
      data.value = nextData;
    } catch (cause) {
      if (requestId !== latestRequestId) return;
      if (cause instanceof DOMException && cause.name === 'AbortError') return;
      error.value = cause instanceof Error ? cause.message : '未知错误';
    } finally {
      if (requestId === latestRequestId) loading.value = false;
    }
  }

  return { data, loading, error, load };
});
```

页面使用 `storeToRefs()` 保持 Store 属性的响应性：

```vue
<script setup lang="ts">
import { onMounted, onUnmounted } from 'vue';
import { storeToRefs } from 'pinia';
import DashboardShell from '@/components/DashboardShell.vue';
import { useDashboardStore } from '@/stores/dashboard';

const store = useDashboardStore();
const { data, loading, error } = storeToRefs(store);
const controller = new AbortController();

onMounted(() => {
  void store.load(controller.signal);
});

onUnmounted(() => {
  controller.abort();
});
</script>

<template>
  <p v-if="loading">正在加载数据...</p>
  <p v-else-if="error" role="alert">{{ error }}</p>
  <DashboardShell v-else-if="data" :data="data" />
  <p v-else>暂无数据</p>
</template>
```

请求是异步的，不能在 `load()` 完成前直接读取深层字段。用 `null` 表示“尚未加载”，比用空对象再大量非空断言更诚实。`latestRequestId` 还保证并发刷新时只有最后一次请求能写入数据和结束 `loading`，避免旧响应覆盖新响应。

## 4. 大屏组件划分

三栏布局适合拆成这些单一职责组件：

```text
DashboardView.vue          页面数据编排
└─ DashboardShell.vue      三栏布局
   ├─ MetricBoard.vue      六项全国指标
   ├─ DistributionPie.vue  城市 Top N 占比
   ├─ TrendLine.vue        趋势
   ├─ ChinaMap.vue         地图与省份选择
   └─ CityTable.vue        当前省份城市明细
```

`ChinaMap` 通过 `selected` 事件把省份 ID 传给父组件；父组件更新 `selectedProvinceId`，再把对应明细通过 Props 传给 `CityTable`。这是“Props 下行、事件上行”，图表组件无需直接修改全局 Store。

```vue
<script setup lang="ts">
import { computed, shallowRef } from 'vue';
import ChinaMap from '@/components/ChinaMap.vue';
import CityTable from '@/components/CityTable.vue';
import DistributionPie from '@/components/DistributionPie.vue';
import MetricBoard from '@/components/MetricBoard.vue';
import TrendLine from '@/components/TrendLine.vue';
import { chinaCoordinates } from '@/data/china-coordinates';
import type { DashboardPayload } from '@/types/dashboard';

const props = defineProps<{ data: DashboardPayload }>();
const selectedProvinceId = shallowRef(
  props.data.provinces[0]?.id ?? '',
);

const selectedCities = computed(
  () =>
    props.data.provinces.find(
      (province) => province.id === selectedProvinceId.value,
    )?.children ?? [],
);
</script>

<template>
  <main class="dashboard">
    <section class="dashboard-left">
      <MetricBoard
        :today="props.data.chinaAdd"
        :total="props.data.chinaTotal"
      />
      <DistributionPie :items="props.data.cityTop" />
      <TrendLine :items="props.data.trend" />
    </section>

    <ChinaMap
      :provinces="props.data.provinces"
      :coordinates="chinaCoordinates"
      @selected="selectedProvinceId = $event"
    />

    <CityTable :items="selectedCities" />
  </main>
</template>

<style scoped>
.dashboard {
  min-height: 100dvh;
  display: grid;
  grid-template-columns: minmax(18rem, 24rem) minmax(32rem, 1fr) minmax(22rem, 28rem);
  gap: 1rem;
}

@media (max-width: 1100px) {
  .dashboard {
    grid-template-columns: 1fr;
  }
}
</style>
```

## 5. ECharts 地图的生命周期

中国地图需要 GeoJSON、地区经纬度表和 `echarts.registerMap()`。地图 GeoJSON 并不随 ECharts 自动附带，必须确认来源、版本和使用许可。

经纬度表作为普通数据模块导出，键名必须和 `ProvinceStat.name`、GeoJSON 地区名保持一致：

```ts
// src/data/china-coordinates.ts
import type { Coordinate } from '@/types/dashboard';

export const chinaCoordinates = {
  北京: { longitude: 116.405285, latitude: 39.904989 },
  上海: { longitude: 121.472644, latitude: 31.231706 },
  广东: { longitude: 113.280637, latitude: 23.125178 },
  // 其余省级行政区按同一来源和命名规范补齐。
} as const satisfies Readonly<Record<string, Coordinate>>;
```

ECharts 实例属于外部对象，适合放进 `shallowRef`，避免 Vue 深度代理其内部结构。组件还要负责：

- DOM 挂载后再 `init`。
- Props 改变时调用 `setOption`。
- 容器尺寸改变时调用 `resize`。
- 组件卸载时断开观察器并 `dispose`。

```vue
<script setup lang="ts">
import { onBeforeUnmount, onMounted, shallowRef, useTemplateRef, watch } from 'vue';
import * as echarts from 'echarts';
import chinaGeoJson from '@/assets/china.json';
import type { Coordinate, ProvinceStat } from '@/types/dashboard';

interface TooltipParam {
  name?: string;
  value?: unknown;
}

const props = defineProps<{
  provinces: ProvinceStat[];
  coordinates: Readonly<Record<string, Coordinate>>;
}>();

const emit = defineEmits<{
  selected: [provinceId: string];
}>();

const container = useTemplateRef<HTMLDivElement>('map');
const chart = shallowRef<echarts.ECharts | null>(null);
let resizeObserver: ResizeObserver | null = null;

echarts.registerMap(
  'china',
  chinaGeoJson as Parameters<typeof echarts.registerMap>[1],
);

function buildPoints() {
  return props.provinces.flatMap((province) => {
    const coordinate = props.coordinates[province.name];
    if (!coordinate) return [];

    return [{
      id: province.id,
      name: province.name,
      value: [
        coordinate.longitude,
        coordinate.latitude,
        province.nowConfirm,
      ],
    }];
  });
}

function render() {
  chart.value?.setOption({
    tooltip: {
      trigger: 'item',
      formatter: (input: TooltipParam | TooltipParam[]) => {
        const params = Array.isArray(input) ? input[0] : input;
        const value = Array.isArray(params.value) ? params.value[2] : 0;
        return (params.name ?? '') + '：' + value;
      },
    },
    geo: {
      map: 'china',
      roam: true,
      label: { show: true, fontSize: 10 },
      itemStyle: {
        areaColor: '#123b5d',
        borderColor: '#7dd3fc',
      },
      emphasis: {
        itemStyle: { areaColor: '#2563eb' },
      },
    },
    series: [{
      type: 'effectScatter',
      coordinateSystem: 'geo',
      symbolSize: (value: unknown) => {
        const count = Array.isArray(value) ? Number(value[2]) : 0;
        return Math.max(8, Math.min(30, Math.sqrt(count)));
      },
      data: buildPoints(),
    }],
  });
}

onMounted(() => {
  if (!container.value) return;

  chart.value = echarts.init(container.value);
  chart.value.on('click', (params) => {
    const province = props.provinces.find(
      (item) => item.name === params.name,
    );
    if (province) emit('selected', province.id);
  });

  resizeObserver = new ResizeObserver(() => chart.value?.resize());
  resizeObserver.observe(container.value);
  render();
});

watch(() => props.provinces, render);

onBeforeUnmount(() => {
  resizeObserver?.disconnect();
  chart.value?.dispose();
  chart.value = null;
});
</script>

<template>
  <section class="map-panel" aria-label="全国数据地图">
    <div ref="map" class="map-canvas" />
  </section>
</template>

<style scoped>
.map-panel,
.map-canvas {
  width: 100%;
  min-height: 38rem;
}
</style>
```

早期 ECharts 配置中的 `normal`、`hoverAnimation` 等写法已经变化。升级后应按当前控制台告警和锁定版本的类型提示迁移，不要简单删除到“没有报错”为止。

## 6. 城市表格与稳定 Key

地图点击后展示所选省份的城市数据。表头和字段要一一对应：

| 地区 | 今日新增 | 累计确诊 | 累计治愈 | 累计死亡 |
| --- | ---: | ---: | ---: | ---: |

```vue
<script setup lang="ts">
import type { CityStat } from '@/types/dashboard';

const props = defineProps<{ items: CityStat[] }>();
</script>

<template>
  <table class="city-table">
    <thead>
      <tr>
        <th>地区</th>
        <th>今日新增</th>
        <th>累计确诊</th>
        <th>累计治愈</th>
        <th>累计死亡</th>
      </tr>
    </thead>

    <TransitionGroup name="row" tag="tbody">
      <tr v-for="item in props.items" :key="item.id">
        <td>{{ item.name }}</td>
        <td>{{ item.todayConfirm }}</td>
        <td>{{ item.totalConfirm }}</td>
        <td>{{ item.totalHeal }}</td>
        <td>{{ item.totalDead }}</td>
      </tr>
    </TransitionGroup>
  </table>
</template>

<style scoped>
.city-table {
  width: 100%;
  border-collapse: collapse;
}

.city-table th,
.city-table td {
  padding: 0.65rem;
  text-align: center;
  white-space: nowrap;
}

.row-enter-active,
.row-leave-active {
  transition: opacity 180ms ease, transform 180ms ease;
}

.row-enter-from,
.row-leave-to {
  opacity: 0;
  transform: translateY(0.5rem);
}
</style>
```

`index` 不是稳定 Key。切换省份时，相同索引会让 Vue 复用错误行，动画和局部状态都会错位。优先使用接口 ID；没有 ID 时，在适配层生成由稳定业务字段组成的键，而不是在每次渲染时随机生成。

## 7. 指标、饼图与折线图

### 7.1 指标看板

六项指标由“今日变化”和“累计值”组成。模板只消费整理后的数组：

```ts
const metricCards = computed(() => [
  {
    key: 'local-confirm',
    label: '本土现有确诊',
    delta: props.today.localConfirm,
    value: props.total.localConfirm,
  },
  {
    key: 'now-confirm',
    label: '现有确诊',
    delta: props.today.nowConfirm,
    value: props.total.nowConfirm,
  },
  {
    key: 'confirm',
    label: '累计确诊',
    delta: props.today.confirm,
    value: props.total.confirm,
  },
  {
    key: 'no-infect',
    label: '无症状感染者',
    delta: props.today.noInfect,
    value: props.total.noInfect,
  },
  {
    key: 'imported',
    label: '境外输入',
    delta: props.today.importedCase,
    value: props.total.importedCase,
  },
  {
    key: 'dead',
    label: '累计死亡',
    delta: props.today.dead,
    value: props.total.dead,
  },
]);
```

这是纯派生数据，应该用 `computed`，不需要 `watch` 再手动写入另一个 Ref。

### 7.2 饼图

城市 Top 10 先按指标排序，再转换成 ECharts 的 `{ name, value }`：

```ts
const pieData = computed(() =>
  [...props.items]
    .sort((left, right) => right.todayConfirm - left.todayConfirm)
    .slice(0, 10)
    .map((item) => ({
      name: item.name,
      value: item.todayConfirm,
    })),
);
```

“前十条”必须先明确排序依据；接口返回顺序未必等于 Top 10。总量为零、负数或缺失时也要在边界层处理。

### 7.3 折线图

折线图的横轴与数值数组必须同序：

```ts
const lineOption = computed(() => ({
  tooltip: { trigger: 'axis' },
  xAxis: {
    type: 'category',
    data: props.items.map((item) => item.date),
  },
  yAxis: { type: 'value', minInterval: 1 },
  series: [{
    type: 'line',
    smooth: true,
    showSymbol: false,
    data: props.items.map((item) => item.value),
  }],
}));
```

真实趋势应使用按日期排序的时间序列，不要把“城市 Top 10”误标为时间趋势。图表配置不能替代业务语义校验。

## 8. 初始化顺序与常见故障

### 图表空白

按顺序检查：

1. 容器是否已经挂载。
2. 容器是否有非零宽高。
3. 地图是否已 `registerMap()`。
4. `setOption()` 的系列类型与组件是否已引入。
5. 数据中的地区名是否和 GeoJSON、经纬度表一致。

### 数据请求成功，页面仍报空对象错误

不要在请求完成前读取深层属性。使用 `DashboardPayload | null`、加载分支和可选链，并让子组件只在数据存在时挂载。

### 地图切换后表格动画不完整

检查 `:key` 是否来自稳定业务 ID。使用数组索引会让旧节点被错误复用。

### 窗口缩放后图表变形

ECharts 不会自动理解 CSS 布局变化。观察容器尺寸并调用 `chart.resize()`，卸载时断开 `ResizeObserver`。

### 接口跨域

开发环境使用 Vite proxy；生产环境由 Nginx 把 `/api` 反向代理到 Node 服务。不要把“允许所有 Origin”当成默认修复。

## 9. 本地运行

在来源可信、已经完成代码审查的项目根目录，先分别阅读 Web 与 Node 的 `package.json`，确认脚本和所需环境变量，再安装锁定依赖：

```bash
npm --prefix node ci
npm --prefix web ci
```

分别在两个终端启动服务：

```bash
npm --prefix node run dev
```

```bash
npm --prefix web run dev
```

如果仓库没有锁文件才使用 `npm install`。启动后至少验证：

- Node 的 `/api/dashboard` 返回预期结构。
- Vue 页面有加载、失败和空数据状态。
- 地图首次渲染、点击切换、窗口缩放均正常。
- 表格 Key 稳定，饼图和折线图字段语义正确。
- `npm run build` 与类型检查通过。

## 10. 数据链路

```text
上游数据
  → Node 边界校验与结构归一化
  → API 请求状态与错误处理
  → Pinia 保存源状态
  → computed 派生地图、表格和图表数据
  → 地图 selected 事件更新省份 ID
  → 明细表和其他视图同步刷新
```

可视化项目最容易堆成一个巨大的 `App.vue`。真正可维护的做法，是把外部数据校验、源状态、派生数据和图表生命周期分开；图表只是最后一层输出。
