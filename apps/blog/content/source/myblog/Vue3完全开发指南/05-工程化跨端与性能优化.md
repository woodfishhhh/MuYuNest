# Vue 3 工程化、跨端与性能优化

## 1. 跨端不是“一套代码零成本运行”

Vue 负责组件与响应式，目标平台由外层运行时决定：

```text
Vue 组件与业务逻辑
        │
        ├─ 浏览器       普通 Web / H5 / PWA
        ├─ WebView      Ionic + Capacitor -> Android / iOS
        ├─ Chromium     Electron -> Windows / macOS / Linux
        └─ 编译型框架   uni-app 等 -> 小程序 / 多端产物
```

选择框架前先回答：

| 问题 | 影响 |
| --- | --- |
| 是否必须复用现有 Web 团队和页面 | 倾向 WebView/Hybrid |
| 是否依赖相机、蓝牙、推送、后台任务 | 检查原生插件能力和维护状态 |
| 是否追求复杂动画、长列表和高帧率 | 评估原生/Flutter/React Native，而非只看开发速度 |
| 是否要发布小程序 | 评估目标平台编译链和审核限制 |
| 是否接受每个平台单独调试与签名 | 所有真实跨端项目都需要 |

“Write once” 只能复用一部分业务代码。导航、权限、文件系统、通知、键盘、安全区、返回手势、商店审核和性能预算仍然是平台问题。

## 2. Ionic Vue 与 Capacitor

Ionic 提供移动端 UI、手势与导航组件；Capacitor 把 Web 应用放入原生壳，并通过插件桥接设备 API。它仍是 WebView 渲染，不会把 Vue 组件自动编译为平台原生控件。

典型流程：

```bash
# 脚手架命令以当前 Ionic CLI 为准
ionic start mobile-app tabs --type vue

cd mobile-app
npm run build

# Capacitor 平台初始化/同步/打开
npx cap add android
npx cap sync android
npx cap open android
```

每次 Web 产物或原生插件变化后重新 `cap sync`。开发服务器热更新、局域网真机调试、Android Gradle/JDK 版本和 iOS Xcode 要求变化很快，应从当前 Ionic/Capacitor 文档生成命令，不能把旧版 `ionic capacitor copy/open` 当成永久接口。

### 2.1 原生能力的调用链

```text
Vue 页面
  ↓ 调用 Capacitor Plugin
JavaScript Bridge
  ↓
Android / iOS 原生实现
  ↓
系统权限、硬件或平台服务
```

实现相机功能不只安装 npm 包，还要：

1. 在 Android Manifest / iOS 配置中声明权限。
2. 在运行时解释并请求权限。
3. 处理拒绝、永久拒绝和系统设置返回。
4. 在真机验证，不把浏览器 mock 当成原生验收。

### 2.2 构建环境

- `ANDROID_HOME`/Android SDK、JDK 与 Gradle 插件版本要匹配。
- iOS 构建与签名需要 macOS、Xcode 和 Apple 开发者配置。
- 真机调试开启开发者模式只适用于开发设备；发布包必须关闭调试入口。
- API 地址不能写死 `localhost`：真机里的 `localhost` 指手机自己。
- 发布前验证离线启动、弱网、前后台切换、权限恢复、深链和升级安装。

## 3. 移动 H5 适配

### 3.1 视口与基础布局

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1, viewport-fit=cover"
>
```

`width=device-width` 让 CSS 视口对应设备宽度；`viewport-fit=cover` 允许页面延伸到刘海/圆角区域，随后用安全区变量留白。

```css
:root {
  color-scheme: light dark;
  --page-gutter: clamp(12px, 4vw, 24px);
  --control-font-size: 1rem;
}

*,
*::before,
*::after {
  box-sizing: border-box;
}

html,
body,
#app {
  min-height: 100%;
}

body {
  margin: 0;
  padding:
    env(safe-area-inset-top)
    max(var(--page-gutter), env(safe-area-inset-right))
    env(safe-area-inset-bottom)
    max(var(--page-gutter), env(safe-area-inset-left));
}

.page {
  min-height: 100dvh;
}
```

单位边界：

- `%` 通常相对包含块，不等于视口。
- `vw/vh` 相对视口；移动浏览器地址栏变化时优先评估 `dvh/svh/lvh`。
- `rem` 相对根字号，适合可访问字号与整体节奏，不需要用 JS 持续重算。
- `clamp()` 可以同时给出最小、流体值和最大值，避免在超宽/超窄屏无限缩放。
- 设计稿像素是视觉参考，不是要求把每个 `px` 机械转换成 `vw`。

### 3.2 三栏布局

```css
.mobile-header {
  display: grid;
  grid-template-columns: minmax(44px, auto) 1fr minmax(44px, auto);
  align-items: center;
  min-height: 48px;
}

.mobile-header__title {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
  text-align: center;
}
```

Flex 可以实现左右固定、中间 `flex: 1`；Grid 则能直接描述三列，并通过 `min-width: 0` 让长标题正确收缩。

### 3.3 PostCSS 像素转换的风险

PostCSS 会把 CSS 解析成 AST，插件可遍历声明并重写值。直接对任意声明执行 `parseFloat(value)` 只适合解释原理，生产中会误处理这些情况：

```css
box-shadow: 0 1px 3px rgba(0, 0, 0, .2);
border: 1px solid;
background: url("icon-20px.svg");
transform: translateX(calc(100% - 12px));
```

成熟方案需要值解析器、属性白名单/黑名单、最小转换阈值、媒体查询策略、第三方依赖排除和精度配置。优先使用维护中的插件并锁定版本，不要用正则或 `parseFloat()` 重写任意声明。

### 3.4 全局主题和字号

```ts
// composables/useDisplayPreferences.ts
import { shallowRef, watchEffect } from 'vue'

type FontScale = 'compact' | 'normal' | 'large'

const scale = shallowRef<FontScale>(
  (localStorage.getItem('font-scale') as FontScale | null) ?? 'normal',
)

const values: Record<FontScale, string> = {
  compact: '0.9375rem',
  normal: '1rem',
  large: '1.125rem',
}

watchEffect(() => {
  document.documentElement.style.setProperty(
    '--control-font-size',
    values[scale.value],
  )
  localStorage.setItem('font-scale', scale.value)
})

export function useDisplayPreferences() {
  return { scale }
}
```

CSS 自定义属性负责传播，Vue 只修改根变量。不要用它绕过浏览器缩放，也不要把正文固定得小于用户可读范围。

## 4. UnoCSS 原子化引擎

UnoCSS 按源码中实际出现的 token 按需生成 CSS。它不是“把所有框架打包在一起”，而是规则、预设、转换器和提取器组成的引擎。

```bash
npm install -D unocss
```

```ts
// vite.config.ts
import UnoCSS from 'unocss/vite'
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue(), UnoCSS()],
})
```

```ts
// uno.config.ts
import {
  defineConfig,
  presetAttributify,
  presetIcons,
  presetWind3,
} from 'unocss'

export default defineConfig({
  presets: [
    presetWind3(),
    presetAttributify(),
    presetIcons(),
  ],
  rules: [
    ['panel-border', { border: '1px solid #d0d7de' }],
    [/^square-(\d+)$/, ([, size]) => ({
      width: `${size}px`,
      height: `${size}px`,
    })],
  ],
  shortcuts: {
    'toolbar-button':
      'inline-flex items-center justify-center square-36 panel-border',
  },
})
```

```ts
// src/main.ts
import 'virtual:uno.css'
```

旧版 UnoCSS 的 `uno.css`、预设名称和导入路径已经变化。当前 Vite 集成使用 `unocss/vite` 和 `virtual:uno.css`；预设仍会演进，必须按 lockfile 查文档。

动态类同样要让提取器看见完整 token：

```ts
const statusClass = {
  success: 'text-emerald-700 bg-emerald-50',
  warning: 'text-amber-800 bg-amber-50',
  error: 'text-red-700 bg-red-50',
} as const
```

运行时任意拼接类名时使用 safelist 或自定义 extractor，并给生产构建补视觉回归。Devtools 中临时写出的类不一定进入正式 CSS。

## 5. `h()` 与渲染函数

`h()` 创建 VNode，模板最终也会被编译成渲染函数。但 SFC 模板通常在构建期完成编译，并能得到静态提升、patch flag 等优化，所以“手写 `h()` 跳过模板编译，因此更快”不是一般结论。

渲染函数适合：

- 节点结构由数据/算法高度动态生成。
- 无头组件、表格列渲染器等需要把 VNode 当值传递。
- 写底层组件库或 JSX/TSX。

普通业务 UI 仍优先模板，可读性和编译优化通常更好。

```ts
// components/ActionButton.ts
import { defineComponent, h, type PropType } from 'vue'

type Tone = 'primary' | 'danger'

export const ActionButton = defineComponent({
  name: 'ActionButton',
  props: {
    tone: {
      type: String as PropType<Tone>,
      default: 'primary',
    },
  },
  emits: {
    activate: () => true,
  },
  setup(props, { emit, slots }) {
    return () => h(
      'button',
      {
        type: 'button',
        class: ['action-button', `action-button--${props.tone}`],
        onClick: () => emit('activate'),
      },
      slots.default?.(),
    )
  },
})
```

`h(type, props, children)` 的第二个参数同时承载 DOM 属性、组件 props 和 `onXxx` 事件；列表 VNode 仍需要稳定 `key`。不要读取/修改 VNode 内部字段，它们不是公共 API。

## 6. Electron：主进程、预加载与渲染进程

Electron 把 Chromium 与 Node.js 打包为桌面运行时：

```text
主进程 main
  创建窗口、文件系统、系统菜单、原生能力
        │ IPC（白名单消息 + 参数校验）
预加载 preload
  contextBridge 暴露最小 API
        │
渲染进程 renderer
  Vue 页面；按普通不可信 Web 页面处理
```

### 6.1 安全窗口配置

生产环境必须启用上下文隔离和 Web 安全，并把渲染进程当作不可信页面处理：

```ts
// electron/main.ts
import {
  app,
  BrowserWindow,
  ipcMain,
  shell,
  type IpcMainInvokeEvent,
} from 'electron'
import { fileURLToPath } from 'node:url'
import { dirname, join, resolve } from 'node:path'

const __dirname = dirname(fileURLToPath(import.meta.url))
const rendererEntry = resolve(__dirname, '../renderer/index.html')
const devServerUrl = process.env.VITE_DEV_SERVER_URL
const devOrigin = devServerUrl ? new URL(devServerUrl).origin : null
const allowedExternalOrigins = new Set([
  'https://support.example.com',
])

function parseUrl(rawUrl: string): URL | null {
  try {
    return new URL(rawUrl)
  } catch {
    return null
  }
}

function isAllowedRendererUrl(rawUrl: string): boolean {
  const url = parseUrl(rawUrl)
  if (!url) return false

  if (devOrigin && url.origin === devOrigin) return true
  if (url.protocol !== 'file:') return false

  url.search = ''
  url.hash = ''
  return resolve(fileURLToPath(url)) === rendererEntry
}

function assertTrustedSender(event: IpcMainInvokeEvent): void {
  const frame = event.senderFrame
  if (!frame || frame !== event.sender.mainFrame) {
    throw new Error('IPC 只接受主框架请求')
  }

  if (!isAllowedRendererUrl(frame.url)) {
    throw new Error('非法 IPC 来源')
  }
}

function createWindow(): BrowserWindow {
  const window = new BrowserWindow({
    width: 1100,
    height: 760,
    webPreferences: {
      preload: join(__dirname, 'preload.js'),
      nodeIntegration: false,
      contextIsolation: true,
      sandbox: true,
      webSecurity: true,
    },
  })

  window.webContents.on('will-navigate', (event, navigationUrl) => {
    if (!isAllowedRendererUrl(navigationUrl)) event.preventDefault()
  })

  window.webContents.setWindowOpenHandler(({ url: requestedUrl }) => {
    const url = parseUrl(requestedUrl)
    if (url?.protocol === 'https:' && allowedExternalOrigins.has(url.origin)) {
      void shell.openExternal(url.toString())
    }
    return { action: 'deny' }
  })

  window.webContents.session.setPermissionRequestHandler(
    (_webContents, _permission, callback) => callback(false),
  )

  if (devServerUrl) {
    void window.loadURL(devServerUrl)
  } else {
    void window.loadFile(rendererEntry)
  }

  return window
}

app.whenReady().then(() => {
  createWindow()
})

ipcMain.handle('preferences:load', (event) => {
  assertTrustedSender(event)
  return { theme: 'system' as const }
})
```

原则：

- 不给渲染进程开放 Node.js。
- 保持 `contextIsolation: true` 与 sandbox。
- 不关闭 `webSecurity` 来逃避跨域；修复服务端 CORS 或主进程受控请求。
- 导航只允许已知渲染入口；新窗口始终拒绝，外部链接经明确 Origin 白名单后交给系统浏览器。
- 加 CSP，并只加载可信本地内容或 HTTPS 白名单内容。
- IPC 主进程校验发送者、频道和参数，不能暴露任意 `ipcRenderer.send`。

### 6.2 预加载桥接

```ts
// electron/preload.ts
import { contextBridge, ipcRenderer } from 'electron'

export interface DesktopApi {
  loadPreferences(): Promise<{ theme: 'light' | 'dark' | 'system' }>
}

const api: DesktopApi = {
  loadPreferences: () => ipcRenderer.invoke('preferences:load'),
}

contextBridge.exposeInMainWorld('desktop', api)
```

```ts
// src/types/electron.d.ts
import type { DesktopApi } from '../../electron/preload'

declare global {
  interface Window {
    desktop: DesktopApi
  }
}

export {}
```

```vue
<script setup lang="ts">
import { onMounted, shallowRef } from 'vue'

const theme = shallowRef<'light' | 'dark' | 'system'>('system')

onMounted(async () => {
  theme.value = (await window.desktop.loadPreferences()).theme
})
</script>
```

桥接 API 应是一项业务动作一个方法，而不是把整个 Electron/Node API 挂到 `window`。

### 6.3 构建与发布

自行拼装 Vite 插件、`child_process.spawn`、文件监听和 electron-builder 管线有助于理解开发服务器与主进程的关系，但维护成本和安全风险都高。新项目优先从 Electron Forge 或维护中的 Electron + Vite 模板开始，再按需求扩展。

```text
开发：renderer dev server + main/preload 编译 + Electron 启动
构建：renderer 静态产物 + main/preload 产物
打包：应用代码 + Electron runtime -> 平台应用
制品：签名/公证 -> 安装包 -> 发布/自动更新
```

发布不止“能生成 exe”：

- Windows/macOS 代码签名，macOS 还需 notarization。
- 每个平台/架构验证安装、覆盖升级和卸载。
- 原生 Node 模块按 Electron ABI 重建。
- 自动更新包和元数据同样签名并走 HTTPS。
- 依赖、Chromium 与 Electron 保持在受支持版本。

> **版本说明**：Electron 默认安全行为、Node/Chromium 版本、Forge/Vite 插件和打包器字段经常变化。不要使用 `contextIsolation: false`、`webSecurity: false`、伪造 `node_modules` 等旧技巧；以当前 Electron Security Checklist 与打包工具文档为准。

## 7. Vue 编译宏的版本线

编译宏只在 `<script setup>` 中使用，通常无需导入，构建时会被编译掉。

| 能力 | 版本 | 作用 |
| --- | --- | --- |
| `defineProps` / `defineEmits` | `<script setup>` 基础能力 | 声明 props 与事件 |
| 泛型组件 `generic="T"` | Vue 3.3+ | 让组件 props/slots 共享泛型 |
| `defineOptions` | Vue 3.3+ | 在 setup 块内声明组件选项 |
| `defineSlots` | Vue 3.3+ | 给插槽名称和参数做类型提示 |
| `defineModel` | Vue 3.4+ | 声明组件 `v-model` 契约 |
| 响应式 props 解构 | Vue 3.5+ | `defineProps()` 解构变量保持响应式 |

`defineModel` 在 Vue 3.3 中需要显式开启，在 Vue 3.4+ 已正式可用。

```vue
<!-- GenericSelect.vue -->
<script setup lang="ts" generic="T extends { id: string }">
const props = defineProps<{
  items: T[]
  labelOf: (item: T) => string
}>()

const selectedId = defineModel<string | null>({ required: true })

const emit = defineEmits<{
  select: [item: T]
}>()

defineOptions({
  inheritAttrs: false,
})

defineSlots<{
  option(props: { item: T; selected: boolean }): unknown
}>()
</script>

<template>
  <ul v-bind="$attrs">
    <li v-for="item in props.items" :key="item.id">
      <button
        type="button"
        @click="selectedId = item.id; emit('select', item)"
      >
        <slot
          name="option"
          :item="item"
          :selected="selectedId === item.id"
        >
          {{ props.labelOf(item) }}
        </slot>
      </button>
    </li>
  </ul>
</template>
```

注意：

- `defineProps` 只能选择运行时声明或类型声明，不能两种混用。
- 类型到运行时 props 的转换基于 AST，不支持把整个 props 对象写成任意复杂条件类型。
- `defineModel({ default })` 而父组件没有传值时，可能造成父子初始值不同步；双向契约通常用 `required` 或由父组件提供初值。
- Vue 3.4 及以下用 `withDefaults()`；Vue 3.5+ 可使用响应式 props 解构默认值。
- 宏版本必须和 `vue`、`@vue/compiler-sfc`、语言服务版本一致。

## 8. Vite 环境变量

### 8.1 模式与文件优先级

```text
.env                  所有模式
.env.local            所有模式，本机私有，忽略提交
.env.[mode]           指定模式
.env.[mode].local     指定模式，本机私有，忽略提交
```

```dotenv
# .env.development
VITE_API_BASE_URL=/api
VITE_ENABLE_FIXTURE=true
```

```ts
const apiBaseUrl = import.meta.env.VITE_API_BASE_URL
const fixtureEnabled = import.meta.env.VITE_ENABLE_FIXTURE === 'true'

if (import.meta.env.DEV && fixtureEnabled) {
  // 只在开发构建保留的分支
}
```

内置值包括 `MODE`、`BASE_URL`、`DEV`、`PROD`、`SSR`。自定义变量默认只有 `VITE_` 前缀会暴露给客户端，并且值都是字符串。

### 8.2 给环境变量补类型

```ts
// src/vite-env.d.ts
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
  readonly VITE_ENABLE_FIXTURE: 'true' | 'false'
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

环境变量不是运行时配置中心：Vite 在构建时静态替换 `import.meta.env.*`。同一个构建产物若要部署到多个环境并在启动时切换地址，应由服务器注入 JSON/HTML 配置，而不是期待修改 `.env` 后旧产物自动变化。

### 8.3 配置文件中读取

```ts
// vite.config.ts
import { defineConfig, loadEnv } from 'vite'

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), 'VITE_')

  return {
    server: {
      proxy: {
        '/api': {
          target: env.VITE_DEV_API_TARGET,
          changeOrigin: true,
        },
      },
    },
  }
})
```

安全边界：所有进入客户端的 `VITE_*` 都能在打包后的 JavaScript 中看到，不能存数据库密码、私钥或真正的服务端 API secret。修改 `.env` 后重启开发服务器。

## 9. 从零理解 Webpack 5

从零搭建 Webpack 的价值不是替代 Vite，而是理解模块图：

```text
entry
  ↓ 解析 import/require
module rules + loaders       把 .vue/.ts/.css 等转换成模块
  ↓
dependency graph
  ↓ plugins                  注入 HTML、定义变量、优化和输出
output                       带 hash 的 JS/CSS/assets
```

**Loader** 针对匹配到的模块做转换，链条从右向左执行；**Plugin** 通过编译生命周期处理更广泛的构建任务。

一个教学型最小配置：

```js
// webpack.config.mjs
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import HtmlWebpackPlugin from 'html-webpack-plugin'
import { VueLoaderPlugin } from 'vue-loader'
import webpack from 'webpack'
```

### 9.1 Vite 与 Webpack 不应硬套配置

- Vite 开发期基于原生 ESM 和插件转换，生产构建当前正在从 Rollup 体系演进到 Rolldown。
- Webpack 从入口构建完整模块图，loader/plugin 是核心扩展面。
- 两者的 alias、代理、环境变量和代码分割概念相似，字段和插件不能直接互换。

外部 CDN 可以减小应用 bundle，但会增加网络依赖、CSP/SRI、版本一致性和离线问题。先分析包体，再决定按需导入、懒加载、拆包或 CDN，不要把 `externals` 当成默认优化。

## 10. 性能优化：先测量，再改瓶颈

### 10.1 指标分层

当前 Core Web Vitals 关注：

| 指标 | 含义 | 良好目标（第 75 百分位） |
| --- | --- | --- |
| LCP | 最大内容完成绘制 | <= 2.5s |
| INP | 用户交互响应延迟 | <= 200ms |
| CLS | 页面意外布局偏移 | <= 0.1 |

FCP、TTFB 是诊断指标；TBT 是实验室中观察主线程阻塞的指标。TTI 已不再是当前 Core Web Vitals。一次 Lighthouse 分数只是一份实验室快照，不能替代真实用户监控。

```text
真实用户数据（RUM）发现问题
  ↓
Performance / Lighthouse / Network 定位
  ↓
建立可复现基线和预算
  ↓
只改主要瓶颈
  ↓
同条件复测 + 业务回归
```

### 10.2 包体与加载路径

- 使用构建分析器找大依赖，不凭感觉删包。
- 路由与重型面板使用动态导入。
- UI 库按需导入，但验证自动导入插件是否真的 tree-shake。
- 生产 source map 是否上传到错误平台、是否公开，由安全与诊断需求决定。
- 给 JS、CSS、字体、图片分别设预算；提高 warning limit 不是优化。

```ts
import { defineAsyncComponent } from 'vue'

export const HeavyChart = defineAsyncComponent(
  () => import('./HeavyChart.vue'),
)
```

### 10.3 Vue 更新成本

保持 props 稳定，让子组件只在真正相关的值变化时更新：

```vue
<!-- 父组件先算出 active，而不是让所有行依赖 activeId -->
<UserRow
  v-for="user in users"
  :key="user.id"
  :user="user"
  :active="user.id === activeId"
/>
```

- 派生值用 `computed`，不要在模板反复 filter/sort。
- 巨大且按不可变方式替换的数据用 `shallowRef`，避免深层代理成本。
- 永远不再变化的子树可用 `v-once`。
- 大型列表中依赖集合明确时，测量后再用 `v-memo`。
- 热路径中过度拆成大量小组件也有开销；先用 Profiler 证明。

### 10.4 大列表、图片和 Worker

虚拟列表只渲染视口附近条目，但还要考虑动态高度、键盘焦点、滚动定位和可访问性。优先选择成熟虚拟化库或 UI 库能力，不要只用 `IntersectionObserver` 粗略删除 DOM。

图片优化：

```html
<img
  src="/covers/course-800.webp"
  srcset="/covers/course-480.webp 480w, /covers/course-800.webp 800w"
  sizes="(max-width: 600px) 100vw, 800px"
  width="800"
  height="450"
  loading="lazy"
  decoding="async"
  alt="Vue 3 指南封面"
>
```

明确 `width/height` 可预留比例、降低 CLS；首屏 LCP 图片不要盲目 lazy load，应设置正确优先级。

CPU 密集计算可以放入 Worker：

```ts
const worker = new Worker(
  new URL('./report.worker.ts', import.meta.url),
  { type: 'module' },
)

worker.postMessage({ rows })
worker.addEventListener('message', ({ data }) => {
  result.value = data
})
```

Worker 不能直接操作 DOM；传输超大对象也有序列化成本，必要时使用 Transferable。

### 10.5 PWA 不是自动加速开关

Service Worker 能离线缓存和拦截请求，也会带来旧资源、缓存失效和升级一致性问题。按资源类型选择策略：

- 带 hash 静态资源：Cache First。
- HTML/导航：Network First 或带回退策略。
- API：只缓存明确允许的公开、可过期响应。
- 用户隐私数据：默认不进共享缓存。

PWA 插件配置、Workbox API 和浏览器限制均版本敏感；必须测试首次安装、离线、更新、回滚和清缓存。

## 11. Web Components 与 Vue

Web Components 主要包含：

- Custom Elements：注册带连字符的自定义元素。
- Shadow DOM：封装内部 DOM 与样式边界，不等于 JavaScript 沙箱。
- `<template>`：保存可克隆的惰性 DOM 模板。

原生自定义元素生命周期：

| 回调 | 时机 |
| --- | --- |
| `connectedCallback` | 插入文档 |
| `disconnectedCallback` | 离开文档 |
| `adoptedCallback` | 移动到另一个 document |
| `attributeChangedCallback` | `observedAttributes` 中的属性变化 |

Vue 可以用 `defineCustomElement()` 输出原生元素：

```vue
<!-- UserBadge.ce.vue -->
<script setup lang="ts">
defineProps<{
  id: string
  name: string
  active?: boolean
}>()

const emit = defineEmits<{
  select: [id: string]
}>()
</script>

<template>
  <button type="button" @click="emit('select', id)">
    {{ name }}{{ active ? '（在线）' : '' }}
  </button>
</template>

<style>
button {
  font: inherit;
}
</style>
```

```ts
// elements.ts
import { defineCustomElement } from 'vue'
import UserBadge from './UserBadge.ce.vue'

export const UserBadgeElement = defineCustomElement(UserBadge)

if (!customElements.get('user-badge')) {
  customElements.define('user-badge', UserBadgeElement)
}
```

发布组件库时还要生成类型声明，不能只输出浏览器可执行文件。安装与 Vue 版本匹配的 `vue-tsc`，并创建专用配置以覆盖应用项目常见的 `noEmit: true`：

`tsconfig.types.json`：

```json
{
  "extends": "./tsconfig.app.json",
  "compilerOptions": {
    "noEmit": false,
    "declaration": true,
    "emitDeclarationOnly": true,
    "outDir": "./dist/types"
  },
  "include": ["src/**/*.ts", "src/**/*.vue"]
}
```

再把声明生成接入库构建：

```json
{
  "scripts": {
    "build": "vite build && npm run build:types",
    "build:types": "vue-tsc -p tsconfig.types.json"
  }
}
```

`package.json` 的 `types`/`exports.types` 应指向生成的入口声明，并在发布前从一个空白 TypeScript 消费项目验证导入、属性和事件类型。

`.ce.vue` 让官方 SFC 工具把样式内联进 Shadow Root。Vue 3.5+ 的 `defineCustomElement` 还增加了 `configureApp`、`shadowRoot` 等选项，旧版不能照抄。

消费第三方 Custom Element 时，在 Vite 的 Vue 编译插件中配置：

```ts
vue({
  template: {
    compilerOptions: {
      isCustomElement: (tag) => tag.startsWith('user-'),
    },
  },
})
```

HTML attribute 只能表达字符串；对象应作为 DOM property 传入：

```vue
<user-card :user.prop="{ id: '1', name: 'Ada' }" />
```

不要把对象 `JSON.stringify()` 后塞进 attribute，除非组件协议明确规定文本 JSON。Custom Event、slot 语义、表单参与、SSR 和 Shadow DOM 样式入口都需要单独设计。

## 12. CORS 与开发代理

### 12.1 同源策略

浏览器的 origin 由 **scheme + host + port** 组成，任一不同就是跨源。CORS 是服务器通过响应头授权浏览器向前端脚本暴露跨源响应的协议；它不是认证机制，也不限制服务端到服务端请求。

复杂请求可能先发预检：

```text
OPTIONS /orders
Origin: https://app.example.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: content-type, authorization
```

服务端要明确返回允许的 origin、method、headers，并正确缓存预检。JSONP 只借助 `<script>` 的跨源加载能力支持 GET，缺少现代安全和错误语义，只适合维护遗留接口。

### 12.2 凭据请求

```ts
await fetch('https://api.example.com/session', {
  credentials: 'include',
})
```

服务端需要：

```http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Vary: Origin
```

带凭据时不能把 `Access-Control-Allow-Origin` 写成 `*`。Cookie 还受 `SameSite`、`Secure`、Domain/Path 与第三方 Cookie 策略约束；“CORS 头正确”不保证 Cookie 一定发送。

### 12.3 Vite 开发代理

```ts
// vite.config.ts
import { defineConfig } from 'vite'

export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:9999',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
      '/socket.io': {
        target: 'ws://localhost:9999',
        ws: true,
      },
    },
  },
})
```

浏览器只请求同源的 Vite 开发服务器，Vite 再从 Node 侧转发到 API。`rewrite` 是否需要取决于后端真实路由；若后端本来就是 `/api/users`，不要删前缀。

该代理只存在于 `vite dev`：

```text
开发：Browser -> Vite proxy -> API
生产：Browser -> Nginx/BFF/API Gateway -> API
                     或
      Browser -> API（服务端正确配置 CORS）
```

生产选择同源反向代理还是跨源 CORS，要结合 Cookie、缓存、限流、WebSocket、日志和部署边界统一设计。不能把开发代理配置当成上线方案。

## 13. 上线检查

- [ ] 跨端方案经过真机、权限、弱网、前后台和发布签名验证。
- [ ] 移动页面有正确 viewport、安全区、流体边界与可访问字号。
- [ ] 原子 CSS 的动态 token 能被生产构建提取，且有视觉回归。
- [ ] Electron 保持隔离和 sandbox，只通过窄 IPC 暴露能力。
- [ ] Vue 编译宏、Vite、Webpack loader/plugin 与 lockfile 版本一致。
- [ ] `VITE_*` 不含秘密，多环境构建与运行时配置边界清楚。
- [ ] 性能有真实基线、预算和复测，不以单次 Lighthouse 分数收工。
- [ ] Web Component 的 property、event、slot 和样式协议明确。
- [ ] 开发代理与生产 CORS/反向代理分别配置并做带 Cookie 的真实请求验证。
