# Vue 3 动画与高级组件模式

## 1. 先判断动画属于哪一类

Vue 提供的工具各有边界：

| 需求 | 首选工具 |
| --- | --- |
| 单个元素或组件进入、离开 | `<Transition>` |
| 列表项新增、删除、重排 | `<TransitionGroup>` |
| 元素一直存在，只切换强调效果 | 动态 class + CSS animation |
| 进度、颜色、坐标等连续状态变化 | 响应式状态 + CSS transition |
| 时间线、数字补间、复杂编排 | GSAP 等成熟动画库 |

动画首先要保证状态、键和生命周期正确，再谈视觉效果。默认优先动画 `transform` 与 `opacity`；频繁动画 `width`、`height`、`top`、`margin` 会触发布局计算，成本通常更高。

## 2. `<Transition>` 的六个 CSS 状态

`Transition` 不会凭空制造动画，它在进入和离开阶段添加、移除约定 class：

| 阶段 | class | 含义 |
| --- | --- | --- |
| Enter | `fade-enter-from` | 插入前的起点 |
| Enter | `fade-enter-active` | 整个进入阶段，通常声明 transition |
| Enter | `fade-enter-to` | 进入终点 |
| Leave | `fade-leave-from` | 离开起点 |
| Leave | `fade-leave-active` | 整个离开阶段 |
| Leave | `fade-leave-to` | 离开终点 |

```vue
<script setup lang="ts">
import { ref } from 'vue'

const visible = ref(true)
</script>

<template>
  <button type="button" @click="visible = !visible">切换</button>

  <Transition name="fade-slide">
    <section v-if="visible" class="panel">
      内容
    </section>
  </Transition>
</template>

<style scoped>
.panel {
  padding: 1rem;
  border: 1px solid #d9dce1;
}

.fade-slide-enter-active,
.fade-slide-leave-active {
  transition: opacity 180ms ease, transform 180ms ease;
}

.fade-slide-enter-from {
  opacity: 0;
  transform: translateY(8px);
}

.fade-slide-leave-to {
  opacity: 0;
  transform: translateY(-8px);
}

@media (prefers-reduced-motion: reduce) {
  .fade-slide-enter-active,
  .fade-slide-leave-active {
    transition: none;
  }
}
</style>
```

`v-if` 会真正插入和移除节点；`v-show` 通过 `display` 切换，也可以触发 Transition，但组件不会卸载。

### 2.1 同类型节点切换与 mode

相同标签之间切换时提供不同 `key`，否则 Vue 可能复用原节点，不产生预期的进入/离开过程：

```vue
<Transition name="fade" mode="out-in">
  <p :key="status">{{ status }}</p>
</Transition>
```

- 默认情况下，进入与离开可能同时发生。
- `mode="out-in"` 先完成离开，再开始进入，适合页面和 Tab 切换。
- `mode="in-out"` 先进入后离开，较少使用。
- `<Transition>` 只应有一个直接子节点；列表动画应使用 `<TransitionGroup>`。

### 2.2 自定义 class 与第三方 CSS 动画

当第三方库不遵循 Vue 的命名约定时，可以把每个阶段映射到已有 class：

```vue
<Transition
  enter-active-class="animate__animated animate__fadeIn"
  leave-active-class="animate__animated animate__fadeOut"
  :duration="400"
>
  <div v-if="visible" class="animated-panel">内容</div>
</Transition>

<style scoped>
.animated-panel {
  animation-duration: 400ms;
}
</style>
```

`duration` 可以是毫秒数字，也可以分别指定：

```vue
<Transition :duration="{ enter: 300, leave: 180 }">
  <div v-if="visible">内容</div>
</Transition>
```

显式 duration 应与真实 CSS 动画时长一致，否则 Vue 可能过早清理 class 或延迟移除节点。

> **版本提示**：Animate.css 的 class 前缀与包版本有关，例如 v4 常见 `animate__`。不要直接照搬旧版类名，应查当前安装版本文档。

## 3. JavaScript 动画钩子与 GSAP

进入阶段有 `before-enter`、`enter`、`after-enter`、`enter-cancelled`；离开阶段有对应的 `before-leave`、`leave`、`after-leave`、`leave-cancelled`。`leave-cancelled` 只在可取消的离开场景中出现，例如 `v-show`。

使用 JavaScript 动画库时设 `:css="false"`，避免 Vue 同时等待 CSS；`enter` 与 `leave` 必须在动画完成时调用 `done`：

```vue
<script setup lang="ts">
import gsap from 'gsap'
import { ref } from 'vue'

const visible = ref(true)

function onBeforeEnter(element: Element) {
  gsap.set(element, { opacity: 0, y: 12 })
}

function onEnter(element: Element, done: () => void) {
  gsap.to(element, {
    opacity: 1,
    y: 0,
    duration: 0.24,
    ease: 'power2.out',
    onComplete: done,
  })
}

function onLeave(element: Element, done: () => void) {
  gsap.to(element, {
    opacity: 0,
    y: -12,
    duration: 0.18,
    ease: 'power2.in',
    onComplete: done,
  })
}

function onCancelled(element: Element) {
  gsap.killTweensOf(element)
}
</script>

<template>
  <Transition
    :css="false"
    @before-enter="onBeforeEnter"
    @enter="onEnter"
    @leave="onLeave"
    @enter-cancelled="onCancelled"
    @leave-cancelled="onCancelled"
  >
    <div v-if="visible">内容</div>
  </Transition>
</template>
```

动画被快速反向切换时应停止旧 tween，否则多个动画会争用同一属性。

### 3.1 `appear`

默认只在后续进入/离开时动画。添加 `appear` 后，组件首次渲染也执行进入动画：

```vue
<Transition appear name="fade-slide">
  <WelcomePanel />
</Transition>
```

需要单独控制首帧时，可使用 `appear-from-class`、`appear-active-class`、`appear-to-class` 或对应 JavaScript hooks。

## 4. `<TransitionGroup>`：列表增删与移动

`TransitionGroup` 面向多个同级列表项。每个直接子节点都必须有稳定、唯一 key，不能依赖会随排序变化的数组下标。

```vue
<script setup lang="ts">
import { ref } from 'vue'

interface Task {
  id: number
  title: string
}

const nextId = ref(3)
const tasks = ref<Task[]>([
  { id: 1, title: '理解进入动画' },
  { id: 2, title: '理解移动动画' },
])

function addTask() {
  tasks.value.push({ id: nextId.value, title: `任务 ${nextId.value}` })
  nextId.value++
}

function removeTask(id: number) {
  tasks.value = tasks.value.filter(task => task.id !== id)
}
</script>

<template>
  <button type="button" @click="addTask">新增</button>

  <TransitionGroup name="task" tag="ul" class="task-list">
    <li v-for="task in tasks" :key="task.id">
      {{ task.title }}
      <button type="button" @click="removeTask(task.id)">删除</button>
    </li>
  </TransitionGroup>
</template>

<style scoped>
.task-enter-active,
.task-leave-active,
.task-move {
  transition: opacity 180ms ease, transform 180ms ease;
}

.task-enter-from,
.task-leave-to {
  opacity: 0;
  transform: translateX(12px);
}

.task-leave-active {
  position: absolute;
}
</style>
```

`tag="ul"` 指定真实 wrapper；`TransitionGroup` 不支持 `mode`。`.task-move` 处理幸存列表项的位置变化。

### 4.1 FLIP 心智模型

Vue 的移动过渡可以用 FLIP 理解：

```text
First   记录更新前位置
Last    应用新列表并记录更新后位置
Invert  先用 transform 抵消位置差，让节点视觉上仍在旧位置
Play    移除抵消 transform，通过 transition 动到新位置
```

这就是随机排序后，网格项能平滑移动而非瞬间跳位的原因。只要 key 不稳定，前后节点身份无法对应，FLIP 也无从计算。

## 5. 状态补间

数字不是 DOM 的进入/离开，适合监听目标值并让动画库修改一个中间响应式对象：

```vue
<script setup lang="ts">
import { reactive, ref, watch } from 'vue'
import gsap from 'gsap'

const target = ref(0)
const tweened = reactive({ value: 0 })

watch(target, value => {
  gsap.to(tweened, {
    value,
    duration: 0.45,
    ease: 'power2.out',
    overwrite: true,
  })
})
</script>

<template>
  <input v-model.number="target" type="number" />
  <output>{{ tweened.value.toFixed(0) }}</output>
</template>
```

简单进度条不需要 GSAP，动态 style 加 CSS transition 即可；复杂补间、时间线或中断控制再引入动画库。

## 6. provide/inject：跨层级上下文

provide/inject 适合主题、表单上下文、当前用户能力、组件库内部协调等“祖先定义、深层后代消费”的依赖。它不是任意全局状态的替代品。

### 6.1 类型化 InjectionKey

```ts
// theme-context.ts
import type { InjectionKey, Ref } from 'vue'

export type Theme = 'light' | 'dark'

export interface ThemeContext {
  theme: Readonly<Ref<Theme>>
  setTheme(theme: Theme): void
}

export const themeKey: InjectionKey<ThemeContext> = Symbol('theme')
```

Provider 保留修改权，只把只读状态和明确动作向下提供：

```vue
<script setup lang="ts">
import { provide, readonly, ref } from 'vue'
import { themeKey } from './theme-context'
import type { Theme } from './theme-context'

const theme = ref<Theme>('light')

function setTheme(next: Theme) {
  theme.value = next
}

provide(themeKey, {
  theme: readonly(theme),
  setTheme,
})
</script>

<template>
  <slot />
</template>
```

后代组件显式处理缺失 Provider：

```vue
<script setup lang="ts">
import { inject } from 'vue'
import { themeKey } from './theme-context'

const themeContext = inject(themeKey)

if (!themeContext) {
  throw new Error('ThemeToggle 必须位于 ThemeProvider 内')
}
</script>

<template>
  <button
    type="button"
    @click="themeContext.setTheme(
      themeContext.theme.value === 'light' ? 'dark' : 'light'
    )"
  >
    切换主题
  </button>
</template>
```

每个组件实例的 provides 都能以父级 provides 为后备，因此最近祖先可以覆盖同一个 key。这个行为可类比原型链查找，但业务代码不应依赖内部实例字段。

## 7. 兄弟组件通信

优先把共享状态提升到最近共同父组件：

```text
SiblingA --emit--> Parent --prop--> SiblingB
```

这种方式虽然多一次中转，却保留了明确的数据所有者。若事件跨越多个不相关分支、没有持久状态含义，可以使用事件总线；需要可追踪的全局状态则应使用 Pinia 等 Store。

### 7.1 手写发布订阅的最小结构

事件总线的核心是 `Map<EventName, Set<Handler>>`：

```ts
type Handler<T> = (payload: T) => void

class EventBus<Events extends object> {
  private handlers = new Map<keyof Events, Set<Handler<unknown>>>()

  on<K extends keyof Events>(event: K, handler: Handler<Events[K]>) {
    const set = this.handlers.get(event) ?? new Set()
    set.add(handler as Handler<unknown>)
    this.handlers.set(event, set)
  }

  off<K extends keyof Events>(event: K, handler: Handler<Events[K]>) {
    this.handlers.get(event)?.delete(handler as Handler<unknown>)
  }

  emit<K extends keyof Events>(event: K, payload: Events[K]) {
    this.handlers.get(event)?.forEach(handler => handler(payload))
  }
}
```

生产项目应优先使用经过验证的小型库，而不是继续扩充手写版本的 once、通配符、错误隔离和清理语义。

### 7.2 typed mitt

```ts
// bus.ts
import mitt from 'mitt'

export type AppEvents = {
  'user:selected': { id: number }
  'notification:show': { message: string; level: 'info' | 'error' }
}

export const bus = mitt<AppEvents>()
```

```vue
<script setup lang="ts">
import { onMounted, onUnmounted } from 'vue'
import { bus } from './bus'

function onUserSelected(payload: { id: number }) {
  console.log('selected:', payload.id)
}

onMounted(() => {
  bus.on('user:selected', onUserSelected)
})

onUnmounted(() => {
  bus.off('user:selected', onUserSelected)
})
</script>
```

不要为了访问总线而依赖 `getCurrentInstance().proxy.$bus`。直接导入 typed singleton 更清晰，也更易测试。最容易遗漏的是卸载时 `off`，遗漏会造成重复响应和内存滞留。

## 8. TSX 组件

模板是 Vue 的默认选择：语义清晰、编译优化充分、设计协作成本低。TSX 更适合高度动态的渲染结构、组件库底层或模板难以表达的程序化 UI。

Vite 项目使用官方 JSX 插件：

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'

export default defineConfig({
  plugins: [vue(), vueJsx()],
})
```

```tsx
// CounterButton.tsx
import { defineComponent, ref } from 'vue'

export default defineComponent({
  name: 'CounterButton',
  props: {
    initial: {
      type: Number,
      default: 0,
    },
  },
  emits: {
    change: (value: number) => Number.isFinite(value),
  },
  setup(props, { emit }) {
    const count = ref(props.initial)

    function increment() {
      count.value++
      emit('change', count.value)
    }

    return () => (
      <button type="button" onClick={increment}>
        {count.value}
      </button>
    )
  },
})
```

TSX 与模板的关键差异：

- ref 不会像模板中那样自动解包，通常要写 `.value`。
- 条件渲染使用三元表达式或 `&&`，列表使用 `array.map()`。
- 事件写成 `onClick` 等 JSX prop，传入函数而不是调用结果。
- 属性和插槽是 JavaScript 值，复杂渲染很灵活，但也更容易把模板变成难读的逻辑程序。

手写 Vite/Babel transform 插件时，稳定的处理模型是：

```text
Vite transform(code, id)
  ↓ 仅处理 .tsx
Babel parse / transform
  ↓ Vue JSX plugin 转换
生成浏览器与 Vue runtime 可执行代码
```

真实项目不要复制教学版编译插件。文件过滤、source map、HMR、JSX pragma、缓存和错误位置映射都很复杂，应使用 `@vitejs/plugin-vue-jsx`。

## 9. 自动导入

`unplugin-auto-import` 可以自动注入 `ref`、`computed` 等 API，并生成类型声明：

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import AutoImport from 'unplugin-auto-import/vite'

export default defineConfig({
  plugins: [
    vue(),
    AutoImport({
      imports: ['vue'],
      dts: 'src/auto-imports.d.ts',
    }),
  ],
})
```

它减少 import 行数，也隐藏了依赖来源。团队应统一规则，并把生成的 `.d.ts` 纳入类型检查；小型项目或公开示例通常显式导入更易理解。

> **版本提示**：自动导入插件的包名、Vite 入口和配置项会更新。生成声明文件的路径与是否提交版本库，应由项目约定决定，而不是照抄旧版配置。

## 10. 组件 `v-model`

`v-model` 是一组 prop 与 update event 的契约。默认展开为：

```vue
<Editor
  :model-value="content"
  @update:model-value="content = $event"
/>
```

### 10.1 Vue 3.4+：`defineModel`

```vue
<!-- SearchInput.vue -->
<script setup lang="ts">
const model = defineModel<string>({ default: '' })
</script>

<template>
  <input v-model="model" type="search" />
</template>
```

父组件直接绑定：

```vue
<SearchInput v-model="query" />
```

多个 model 使用参数区分：

```vue
<!-- UserNameEditor.vue -->
<script setup lang="ts">
const firstName = defineModel<string>('firstName', { required: true })
const lastName = defineModel<string>('lastName', { required: true })
</script>

<template>
  <input v-model="firstName" />
  <input v-model="lastName" />
</template>
```

```vue
<UserNameEditor
  v-model:first-name="user.firstName"
  v-model:last-name="user.lastName"
/>
```

### 10.2 自定义修饰符

```vue
<!-- CapitalizeInput.vue -->
<script setup lang="ts">
import { computed } from 'vue'

const [model, modifiers] = defineModel<string, 'capitalize'>({ default: '' })

const normalizedModel = computed({
  get: () => model.value,
  set: value => {
    model.value = modifiers.capitalize
      ? value.charAt(0).toUpperCase() + value.slice(1)
      : value
  },
})
</script>

<template>
  <input v-model="normalizedModel" />
</template>
```

```vue
<CapitalizeInput v-model.capitalize="name" />
```

修饰符是组件公共 API。名称要表达稳定语义，不要把任意内部开关都塞成 modifier。

### 10.3 Vue 3.4 以前：显式 props/emits

```vue
<script setup lang="ts">
const props = defineProps<{
  modelValue: string
}>()

const emit = defineEmits<{
  'update:modelValue': [value: string]
}>()

function onInput(event: Event) {
  emit('update:modelValue', (event.target as HTMLInputElement).value)
}
</script>

<template>
  <input :value="props.modelValue" @input="onInput" />
</template>
```

> **版本提示**：`defineModel()` 在 Vue 3.4+ 推荐使用。旧项目仍使用 `modelValue` + `update:modelValue`；两种写法表达的是同一契约。Vue 2 默认是 `value` + `input`，不能与 Vue 3 写法混用。

### 10.4 避免默认值失同步

子组件给 `defineModel` 设置默认值，而父组件绑定值一开始是 `undefined` 时，父子初始状态可能不一致。公共组件应尽量要求父组件提供明确初值，或在契约中清楚说明默认行为。

## 11. 复习清单

1. 为一个单元素弹窗写 CSS Transition，并实现 reduced-motion 降级。
2. 用 `TransitionGroup` 实现列表增删和随机排序，验证使用 index key 时为什么移动结果不可靠。
3. 用 GSAP 实现可中断的数字补间和进入/离开动画，确保取消与完成回调都正确。
4. 建立 typed provide/inject 上下文，状态只读，所有修改经过 Provider 动作。
5. 比较“提升状态”“mitt”“Pinia”三种兄弟通信方案，说明各自的状态所有权和清理责任。
6. 分别用模板和 TSX 写同一个计数器，比较条件渲染、事件、ref 解包与可读性。
7. 用 `defineModel` 实现默认 model、具名 model 和自定义修饰符，再写出对应的 props/emits 展开形式。
