# Vue 3 基础与响应式系统

## 1. 从工程到页面更新

Vue 应用的主链路可以压缩成四层：

```text
SFC 源码
  ↓ Vite + @vitejs/plugin-vue
模板编译为 render 函数
  ↓ 执行 render
生成 VNode 树
  ↓ patch / keyed diff
更新真实 DOM

响应式状态
  ↓ track 建立依赖
组件渲染副作用
  ↓ trigger 调度更新
重新执行 render，并 patch 差异
```

Composition API 的价值不只是“换一种语法”，而是把同一业务关注点的状态、派生值、副作用和生命周期放在一起，并允许进一步抽成 composable。

## 2. 创建 Vue 3 工程

Vue 工程可以从 Vite 通用模板或 Vue 专用脚手架创建。现代项目优先使用官方 `create-vue`：

```bash
npm create vue@latest
cd my-vue-app
npm install
npm run dev
```

如果只需要最小 Vite + Vue 模板，也可以使用：

```bash
npm create vite@latest my-vue-app -- --template vue-ts
```

常见脚本的职责：

| 脚本 | 作用 |
| --- | --- |
| `dev` | 启动开发服务器和热更新 |
| `build` | 类型检查后构建生产资源，具体命令以项目模板为准 |
| `preview` | 本地预览已经构建出的生产资源 |

`npm run dev` 能找到本地安装的 `vite`，是因为 npm 执行脚本时会把项目的 `node_modules/.bin` 临时加入 `PATH`。不要为此把 Vite 全局安装到系统环境。

> **版本提示**：Node 14/16、旧版 `npm init vue@latest` 和早期编辑器插件组合已经过时。Node 最低版本、脚手架交互项和 VS Code 扩展名称会随 Vite、Vue 与 Volar 更新，实际项目应以当前官方模板和依赖的 `engines` 为准。

### 2.1 Node.js 在前端工具链中的位置

Node.js 为 Vite、编译器插件、测试工具和包管理脚本提供 JavaScript 运行时；它不是浏览器，也不提供页面 DOM。开发服务器和构建过程运行在 Node.js 中，构建后的 SPA 主要运行在浏览器中，SSR、CLI 或 Electron 主进程则属于另外的运行边界。

```text
JavaScript/TypeScript 工具代码
    ↓ V8 执行 JavaScript
Node.js
    ↓ libuv 组织事件循环、异步 I/O 与线程池任务
文件系统 / 网络 / 子进程
```

Node 的 JavaScript 执行线程与 libuv 的异步能力不是一回事。“主线程执行回调”不等于所有 I/O 都在主线程同步等待。学习前端工程化时只需先建立这个边界，不必把 V8、libuv 的内部源码当成使用 Vite 的前置条件。

```bash
node --version
npm --version
```

选择仍在支持周期且满足项目 `engines` 的 Node 版本；确有多项目版本切换需求时再使用适合当前操作系统的版本管理器。

### 2.2 目录边界

```text
my-vue-app/
├─ public/              原样复制、以根路径访问的静态资源
├─ src/
│  ├─ assets/           进入模块依赖图、可被构建工具处理的资源
│  ├─ components/       可复用组件
│  ├─ App.vue           根组件，负责组合而非堆积全部业务
│  └─ main.ts           创建并挂载应用
├─ index.html           Vite 的 HTML 入口
├─ package.json         依赖与脚本
├─ tsconfig*.json       TypeScript 配置
└─ vite.config.ts       Vite 插件与构建配置
```

`public` 中的文件不会经过模块导入、哈希命名或打包优化；只有确实需要固定 URL 的资源才放进去。业务图片通常应从 `src/assets` 导入。

### 2.3 应用入口与 SFC

```ts
// src/main.ts
import { createApp } from 'vue'
import App from './App.vue'
import './assets/main.css'

createApp(App).mount('#app')
```

单文件组件把行为、视图和局部样式放在同一组件边界中。推荐顺序是 `script -> template -> style`：

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'

const firstName = ref('张')
const lastName = ref('三')
const fullName = computed(() => `${firstName.value}${lastName.value}`)
</script>

<template>
  <p class="profile-name">{{ fullName }}</p>
</template>

<style scoped>
.profile-name {
  font-weight: 600;
}
</style>
```

`<script setup>` 中的顶层变量、导入和函数可直接用于模板，不需要手动 `return`。`scoped` 会给选择器和当前组件节点增加作用域标记，但它不是 Shadow DOM，也不等于绝对的样式隔离。

## 3. 模板语法与指令

模板表达式运行在组件上下文中，适合读取属性、调用轻量函数和做简单表达式。复杂筛选、排序和分支应放进 `computed`，不要塞进模板。

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'

interface Todo {
  id: number
  title: string
  done: boolean
}

const query = ref('')
const todos = ref<Todo[]>([
  { id: 1, title: '理解 ref', done: true },
  { id: 2, title: '练习 watch', done: false },
])

const visibleTodos = computed(() => {
  const keyword = query.value.trim().toLowerCase()
  return todos.value.filter(todo =>
    todo.title.toLowerCase().includes(keyword),
  )
})

function toggle(todo: Todo) {
  todo.done = !todo.done
}
</script>

<template>
  <input v-model.trim="query" placeholder="搜索" />

  <ul v-if="visibleTodos.length">
    <li v-for="todo in visibleTodos" :key="todo.id">
      <button type="button" @click="toggle(todo)">
        {{ todo.done ? '已完成' : '待完成' }}：{{ todo.title }}
      </button>
    </li>
  </ul>
  <p v-else>没有匹配项</p>
</template>
```

常用指令的边界：

| 指令 | 核心行为 | 注意点 |
| --- | --- | --- |
| `v-bind` / `:` | 动态绑定属性、class、style | class 可用对象或数组组织 |
| `v-on` / `@` | 监听事件 | `.stop`、`.prevent`、`.once` 等修饰符声明事件策略 |
| `v-model` | 表单值与状态同步的语法糖 | `.trim`、`.number`、`.lazy` 改变输入处理 |
| `v-if` | 条件为假时不挂载或卸载节点 | 切换成本较高，初始条件为假时不渲染 |
| `v-show` | 始终挂载，仅切换 `display` | 初始成本较高，适合频繁切换 |
| `v-for` | 渲染集合 | 使用稳定、唯一、代表实体身份的 `key` |
| `v-once` | 后续更新跳过该子树 | 只用于确定永远不变的内容 |
| `v-memo` | 依赖数组未变时跳过子树更新 | 是定向性能工具，不应代替正确的数据建模 |

不要在同一元素上同时使用 `v-if` 和 `v-for`。筛选列表应先用 `computed` 生成结果，再遍历结果。

`v-html` 会直接写入 HTML，不会把字符串编译成 Vue 组件。绝不能把未可信、未清洗的用户输入交给 `v-html`，否则会形成 XSS 风险。

## 4. VNode、patch 与 keyed diff

需要区分三个概念：

1. **模板 AST**：编译器解析模板时使用的中间结构。
2. **render 函数**：编译结果，运行时用它创建 VNode。
3. **VNode**：描述元素、组件、属性和子节点的 JavaScript 对象，也就是运行时的虚拟 DOM 节点。

因此“虚拟 DOM 就是 AST”并不准确。模板 AST 属于编译阶段，VNode 属于运行时渲染阶段。

```text
template
  ↓ parse
模板 AST
  ↓ transform + codegen
render 函数
  ↓ execute
VNode
```

Vue 编译器还会标记动态节点、提升静态节点，并生成 patch flag。更新时，运行时可集中处理真正可能变化的部分，而不是盲目比较整棵树。

### 4.1 `key` 表示身份

```vue
<li v-for="user in users" :key="user.id">
  <input v-model="user.name" />
</li>
```

`key` 不是为了“消除警告”，而是告诉 diff 算法新旧 VNode 是否代表同一个业务实体。用数组下标作 key 时，一旦中间插入、删除或排序，节点身份会随位置漂移，输入状态和组件局部状态可能被复用到错误条目。

Vue 3 处理 keyed children 时，可把核心过程理解为：

1. 从头同步相同节点。
2. 从尾同步相同节点。
3. 若旧序列已耗尽，挂载剩余新节点。
4. 若新序列已耗尽，卸载剩余旧节点。
5. 中间乱序区建立 `key -> newIndex` 映射，复用可复用节点，卸载不存在的节点。
6. 对复用节点的新索引序列求最长递增子序列，已经保持相对顺序的节点不移动，其余节点从后向前插入或移动。

最长递增子序列的意义是：在得到正确结果的前提下，尽量减少真实 DOM 移动次数。具体源码变量与内部函数会随 Vue 版本变化，理解阶段职责比记行号更可靠。

## 5. `ref`、`reactive` 与浅层响应式

响应式状态应保持最小：可直接推导的值交给 `computed`，副作用交给 watcher。

| API | 适合场景 | 更新方式 |
| --- | --- | --- |
| `ref` | 基本类型；需要整体替换的对象或数组 | 脚本中读写 `.value` |
| `reactive` | 主要按属性原地修改的对象、数组、Map、Set | 直接读写属性，不可替换代理变量本身 |
| `shallowRef` | 外部实例、巨型不可变数据、只关心根引用替换 | 替换 `.value` 才触发更新 |
| `shallowReactive` | 只跟踪第一层属性的容器 | 嵌套对象保持非响应式 |
| `readonly` | 向消费者暴露只读代理 | 原始响应式源变化时仍会同步 |

```vue
<script setup lang="ts">
import { computed, reactive, ref, shallowRef } from 'vue'

interface Profile {
  name: string
  skills: string[]
}

const count = ref(0)
const profile = reactive<Profile>({
  name: '小满',
  skills: ['Vue'],
})

// 适合保存图表、编辑器等第三方实例，避免深度代理其内部字段。
const chart = shallowRef<{ resize(): void } | null>(null)

const skillCount = computed(() => profile.skills.length)

function loadProfile(next: Profile) {
  // 保留 reactive 代理身份，同时更新字段。
  Object.assign(profile, next)
}
</script>
```

`reactive` 返回 Proxy。下面的写法只是让局部变量指向新数组，原代理与依赖关系被丢掉：

```ts
let rows = reactive<string[]>([])

// 不推荐：rows 不再指向原来的响应式代理。
rows = ['A', 'B']
```

如果列表经常整体替换，直接建模为 `ref<Row[]>([])` 更自然：

```ts
const rows = ref<string[]>([])
rows.value = ['A', 'B']
```

### 5.1 `shallowRef` 与 `triggerRef`

```ts
import { shallowRef, triggerRef } from 'vue'

const config = shallowRef({ theme: { dark: false } })

config.value.theme.dark = true // 深层修改不会自行触发依赖
triggerRef(config)             // 明确通知依赖重新运行

// 更推荐不可变式替换，数据流更清晰。
config.value = {
  ...config.value,
  theme: { ...config.value.theme, dark: true },
}
```

当组件因其他响应式状态更新而重新渲染时，模板也可能“顺便”读到浅层对象已经被修改的值。这不代表深层修改本身具备响应性，不能据此判断 `shallowRef` 失效。

### 5.2 `customRef`

`customRef` 把依赖跟踪和触发时机交给调用方，适合输入防抖等需要控制通知节奏的场景：

```ts
import { customRef } from 'vue'

function useDebouncedRef<T>(initial: T, delay = 300) {
  let value = initial
  let timer: ReturnType<typeof setTimeout> | undefined

  return customRef<T>((track, trigger) => ({
    get() {
      track()
      return value
    },
    set(next) {
      clearTimeout(timer)
      timer = setTimeout(() => {
        value = next
        trigger()
      }, delay)
    },
  }))
}
```

## 6. `toRef`、`toRefs` 与 `toRaw`

直接解构 `reactive` 对象会复制当前属性值，基本类型因此脱离代理访问：

```ts
const state = reactive({ name: '小满', age: 23 })
const { name } = state // name 是当下的字符串，不再响应 state.name
```

`toRef` 为某一个属性建立双向联动的 ref，`toRefs` 则逐个转换全部可枚举属性：

```ts
import { reactive, toRef, toRefs } from 'vue'

const state = reactive({ name: '小满', age: 23 })

const name = toRef(state, 'name')
name.value = '大满' // state.name 同步变化

const { age } = toRefs(state)
age.value++        // state.age 同步变化
```

`toRaw(proxy)` 返回代理背后的原始对象，常用于临时与不接受 Proxy 的外部库交互或做身份比较。它不会把原代理永久“取消响应式”，也不应长期持有后绕过代理修改：

```ts
import { reactive, toRaw } from 'vue'

const state = reactive({ count: 0 })
const raw = toRaw(state)

raw.count++ // 修改发生了，但绕过代理，通常不会触发 Vue 更新
```

## 7. 模板引用

模板 ref 用于聚焦输入框、测量元素或调用子组件显式暴露的命令式 API；它不应替代 props/emits 数据流。

```vue
<script setup lang="ts">
import { onMounted, useTemplateRef } from 'vue'

const input = useTemplateRef<HTMLInputElement>('input')

onMounted(() => {
  input.value?.focus()
})
</script>

<template>
  <input ref="input" />
</template>
```

> **版本提示**：`useTemplateRef()` 是 Vue 3.5+ API。更早的 Vue 3 项目使用 `const input = ref<HTMLInputElement | null>(null)`，模板中的 `ref="input"` 保持不变。

## 8. 响应式系统的最小模型

Vue 3 使用 Proxy 拦截属性读取和写入，依赖关系可抽象为：

```text
WeakMap<target,
  Map<key,
    Set<ReactiveEffect>
  >
>
```

- 读取 `proxy.foo` 时，`track(target, 'foo')` 把当前活跃 effect 记录到集合。
- 写入 `proxy.foo` 时，`trigger(target, 'foo')` 找到集合并调度 effect。
- `WeakMap` 不会仅因依赖表持有 target 而阻止其垃圾回收。

下面是教学用骨架，不包含 Vue 源码中的 effect 栈、分支依赖清理、数组和集合类型处理、调度器、递归保护等完整逻辑：

```ts
type Effect = () => void

const targetMap = new WeakMap<object, Map<PropertyKey, Set<Effect>>>()
let activeEffect: Effect | undefined

function effect(fn: Effect) {
  activeEffect = fn
  try {
    fn()
  } finally {
    activeEffect = undefined
  }
}

function track(target: object, key: PropertyKey) {
  if (!activeEffect) return

  let depsMap = targetMap.get(target)
  if (!depsMap) {
    depsMap = new Map()
    targetMap.set(target, depsMap)
  }

  let dep = depsMap.get(key)
  if (!dep) {
    dep = new Set()
    depsMap.set(key, dep)
  }

  dep.add(activeEffect)
}

function trigger(target: object, key: PropertyKey) {
  const effects = targetMap.get(target)?.get(key)
  effects && [...effects].forEach(run => run())
}

function reactive<T extends object>(target: T): T {
  return new Proxy(target, {
    get(raw, key, receiver) {
      const value = Reflect.get(raw, key, receiver)
      track(raw, key)
      return value
    },
    set(raw, key, value, receiver) {
      const oldValue = Reflect.get(raw, key, receiver)
      const changed = Reflect.set(raw, key, value, receiver)
      if (changed && !Object.is(oldValue, value)) trigger(raw, key)
      return changed
    },
  })
}
```

使用 `Reflect.get/set(..., receiver)` 可以保留访问器中的正确接收者语义；`set` 也自然返回 Proxy trap 需要的布尔结果。

## 9. `computed`：带缓存的派生状态

```ts
import { computed, reactive } from 'vue'

const cart = reactive([
  { id: 1, price: 20, quantity: 2 },
  { id: 2, price: 15, quantity: 1 },
])

const total = computed(() =>
  cart.reduce((sum, item) => sum + item.price * item.quantity, 0),
)
```

计算属性有三个关键性质：

1. getter 应保持纯净，不发请求、不写状态、不派发事件。
2. 只有被读取时才需要求值，并缓存上一次结果。
3. 依赖变化后先标记为失效，下次读取再重新计算。

需要可写计算属性时显式提供 `get/set`：

```ts
const firstName = ref('张')
const lastName = ref('三')

const fullName = computed({
  get: () => `${firstName.value} ${lastName.value}`,
  set: value => {
    const [first = '', last = ''] = value.trim().split(/\s+/, 2)
    firstName.value = first
    lastName.value = last
  },
})
```

源码中的脏标记、订阅者和调度细节会随版本演进；稳定心智模型是“依赖失效时通知，读取时按需重算并缓存”。

## 10. `watch` 与 `watchEffect`

`watch` 适合“明确知道观察谁，并需要新旧值”的副作用；`watchEffect` 适合“运行过程中自动收集同步读取的依赖”。

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'

interface User {
  id: number
  name: string
}

const userId = ref(1)
const user = ref<User | null>(null)
const loading = ref(false)

watch(
  userId,
  async (id, _previousId, onCleanup) => {
    const controller = new AbortController()
    onCleanup(() => controller.abort())

    loading.value = true
    try {
      const response = await fetch(`/api/users/${id}`, {
        signal: controller.signal,
      })
      user.value = await response.json() as User
    } finally {
      if (!controller.signal.aborted) loading.value = false
    }
  },
  { immediate: true },
)
</script>
```

监听 `reactive` 的单个属性时必须传 getter：

```ts
const form = reactive({ profile: { name: '', age: 0 } })

watch(
  () => form.profile.name,
  name => console.log('name changed:', name),
)
```

直接深度监听同一对象时，嵌套属性修改通常会让 `newValue` 与 `oldValue` 指向同一对象；watcher 不会自动保存完整历史快照。若业务确实需要前后快照，应监听克隆后的派生值，或在状态层记录变更。

```ts
import { ref, watchEffect } from 'vue'

const query = ref('')

const stop = watchEffect(onCleanup => {
  const controller = new AbortController()
  onCleanup(() => controller.abort())

  void fetch(`/api/search?q=${encodeURIComponent(query.value)}`, {
    signal: controller.signal,
  })
})

// 不再需要监听时：
stop()
```

`watchEffect` 只会自动收集回调同步执行期间读取的依赖。异步回调中，第一个 `await` 之后才读取的值不会在本轮成为依赖。

### 10.1 flush 时机

| 配置 | 时机 | 典型用途 |
| --- | --- | --- |
| `flush: 'pre'` | 默认；组件 DOM 更新前 | 普通业务副作用 |
| `flush: 'post'` | 当前组件 DOM 更新后 | 读取更新后的 DOM |
| `flush: 'sync'` | 依赖改变时同步执行 | 极少数需要同步一致性的轻量逻辑，避免批量变更导致频繁运行 |

深度遍历可能很昂贵。优先监听最小 getter，而不是为了省事给大型对象统一加 `deep: true`。

## 11. 组件生命周期

Composition API 中，`setup` 自身承担 Options API 的 `beforeCreate/created` 阶段逻辑。常用顺序：

```text
setup
  ↓
onBeforeMount
  ↓ 首次 patch
onMounted
  ↓ 响应式依赖变化
onBeforeUpdate
  ↓ 更新 patch
onUpdated
  ↓ 条件移除或父组件卸载
onBeforeUnmount
  ↓ 清理渲染副作用和 DOM
onUnmounted
```

```vue
<script setup lang="ts">
import { onMounted, onUnmounted, ref } from 'vue'

const width = ref(window.innerWidth)

function updateWidth() {
  width.value = window.innerWidth
}

onMounted(() => {
  window.addEventListener('resize', updateWidth, { passive: true })
})

onUnmounted(() => {
  window.removeEventListener('resize', updateWidth)
})
</script>
```

- `onBeforeMount` 时组件 DOM 尚未插入。
- `onMounted` 后才适合访问当前组件创建的 DOM。
- `onBeforeUpdate` 看到的是更新前 DOM，`onUpdated` 看到的是更新后 DOM。
- 不要在 `onUpdated` 中无条件修改会触发本组件渲染的状态，否则可能形成更新循环。
- `onRenderTracked` 与 `onRenderTriggered` 用于开发期分析渲染依赖，不是业务逻辑钩子。

`v-if` 移除组件会触发卸载；`v-show` 只改样式，不会卸载组件。
