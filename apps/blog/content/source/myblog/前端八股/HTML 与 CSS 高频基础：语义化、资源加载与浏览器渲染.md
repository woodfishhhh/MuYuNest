图片没写替代文本，读屏软件就不知道它在表达什么；样式表发现得太晚，首屏就得等；JavaScript 频繁改布局，浏览器又要重新算位置。

HTML 标签决定结构和语义，CSS 决定怎么展示，资源加载的顺序和 DOM、CSSOM 的变化，则直接影响首屏和交互的性能。

## 一、HTML 元素的基础分类

按默认的显示行为、有没有子内容，一般把元素分成行内元素、块级元素和空元素。

### 1. 行内元素

常见的行内元素：

- `span`
- `img`
- `input`

这类元素一般不独占一行。img 和 input 属于可替换元素，它们的尺寸行为和普通的文本行内元素不完全一样。

### 2. 块级元素

常见的块级元素：

- `div`
- `footer`
- `header`
- `section`
- `p`
- `h1` 到 `h6`

块级元素默认独占一行，适合做结构划分。

### 3. 空元素

空元素本身没有闭合的内容，比如：

- `br`
- `hr`

空元素没有结束标签，也不包含子节点。

### 4. display 可以改变元素表现形式

HTML 标签有默认的显示行为，但不是写死的，可以用 `display` 改变它怎么呈现：

```css
div {
  display: inline;
}

div {
  display: inline-block;
}

div {
  display: block;
}
```

注意：`display` 改的是表现，不改标签的语义。一个 `div` 就算写成了 `inline`，它在语义上也还不是行内文本标签。

## 二、页面引入样式时，`link` 和 `@import` 有什么区别

两种写法都能引入样式，区别在于浏览器什么时候发现这个资源。

### 1. 语法位置不同

- `link` 是 HTML 标签，直接写在页面结构里
- `@import` 是 CSS 语法，一般写在样式表里面

### 2. 浏览器处理时机不同

浏览器解析页面时，会先认出 `link` 对应的外部样式资源；`@import` 要等当前的 CSS 下载并解析完，才能接着发现、加载它引用的样式。

所以：

- `link` 一般更早参与页面渲染
- `@import` 更容易把样式的依赖链拉长

### 3. 兼容性不同

`link` 的兼容性和资源发现时机都更稳，页面里的外部样式一般优先用它引入。

### 4. 实战建议

除非是很特殊的样式组织需求，日常开发优先用 `link`，或者交给打包工具统一构建，别在业务代码里大量用 `@import`。

## 三、相似标签的语义边界

### 1. `title` 和 `h1` 的区别

两个都重要，但作用完全不一样。

- `title` 是页面标题，主要给浏览器标签页、搜索引擎结果页用，概括整个页面
- `h1` 是正文里的一级主题，强调当前页面内容的主题

可以这么理解：

- `title` 像"页面对外的总标题"
- `h1` 像"正文内容的主标题"

在 SEO 里两个都重要，但各管各的，不能互相代替。

### 2. `b` 和 `strong` 的区别

- `b` 偏表现，主要就是加粗
- `strong` 偏语义，表示这段内容"很重要"

只是视觉上加粗的话，用 `b` 或者 CSS；要表达强调的语义，优先用 `strong`。

### 3. `i` 和 `em` 的区别

- `i` 偏表现，默认斜体
- `em` 偏语义，表示强调

常见的用法：

- `i` 多见于字体图标或者样式化的文本
- `em` 更适合术语、重点词这类有强调语义的地方

一句话：能用样式解决的不一定有语义；有语义需求时，尽量用语义标签。

## 四、`img` 的 `title` 和 `alt` 有什么区别

### 1. 展示层区别

- `title`：一般在鼠标移到图片上时显示提示文字
- `alt`：图片加载失败时显示的替代文本

### 2. 可访问性和 SEO 的区别

`alt` 更重要，它不只是"图片挂了的时候显示一句话"，还给搜索引擎、屏幕阅读器、弱网环境和无图模式提供图片的语义说明。

所以：

- `title` 偏补充提示
- `alt` 偏必要描述

图片承载了内容信息的话，`alt` 要认真写；纯装饰的图片可以用空的 `alt=""`，让辅助技术跳过它。

## 五、常见图片格式怎么选

图片格式要在体积、清晰度、透明通道和动画能力之间取舍。

### 1. PNG

- 无损压缩
- 体积一般比 `jpg/jpeg` 大
- 适合图标、透明背景、小的 UI 图形

### 2. JPG / JPEG

- 有损压缩
- 体积一般更小
- 适合照片、色彩复杂的图片、大图展示

### 3. GIF

- 支持动图
- 色彩表现有限
- 适合简单的动画，但现在很多场景都被视频或更高效的格式代替了

### 4. WebP

- 有损、无损压缩都支持
- 体积一般更小
- 适合大多数 Web 场景

按页面用途选，可以先对照这几条：

- UI 图标或透明素材，优先考虑 `png` 或 `svg`
- 照片优先考虑 `jpg` 或 `webp`
- 页面上的大图，优先压缩、升级格式

## 六、从 CSS 到页面显示：浏览器渲染发生了什么

页面拿到 HTML 和 CSS 以后不会直接变成像素，浏览器要先建树，再算布局和绘制结果。

一个页面大致经过这几步：

1. 解析 HTML，构建 DOM 树
2. 解析 CSS，构建 CSSOM
3. DOM 和 CSSOM 合并成渲染树
4. 做布局，算出元素的几何信息
5. 做绘制，把像素画到屏幕上

JavaScript 要是在这个过程中频繁改 DOM 或样式，就可能多出额外的计算成本。

## 七、回流与重绘是什么

样式变了以后要不要重新算布局，是区分回流和重绘的关键。

### 1. 重绘（Repaint）

重绘是元素的样式变了，但不影响布局位置，比如：

- 改颜色
- 改背景
- 改阴影

这类变化不用重新算文档流的位置，但还是要重新绘制。

### 2. 回流（Reflow / 重排）

回流发生在元素的几何属性、位置或结构变化时，比如：

- 改宽高
- 增删 DOM
- 改字体大小
- 改定位、影响到布局
- 读了某些布局属性后又连着写样式

回流比重绘更重，因为它要重新算布局，布局完一般还会触发重绘。

### 3. 二者关系

两者的关系：

- 回流一定可能伴随重绘
- 重绘不一定触发回流

所以前端优化里一般优先避免频繁回流。

## 八、如何减少回流与重绘

### 1. 合并样式修改

别一条条零散地改样式，尽量批量改，比如切换 class。

### 2. 减少频繁读写交替

读布局信息和写样式交替进行时，浏览器为了返回当前的几何信息，可能会强制同步布局。

### 3. 对复杂模块做隔离

比如动画元素用 `transform`、`opacity`，一般比直接改 `top`、`left` 友好。

### 4. 控制 DOM 数量

这跟虚拟列表、组件拆分、按需渲染都有关系。DOM 一多，样式计算和布局计算都会跟着涨。

## 九、从页面现象回到渲染链路

首屏样式出来得太晚，先查外部 CSS 是什么时候被发现的；图片下载成本太高，再按内容和透明度的需求调整格式；交互时卡顿，就看 JavaScript 是不是在反复改 DOM、交替读写布局属性。

这三类现象分别对应资源发现、传输体积和布局计算。先把问题落到具体的阶段，才能判断该改标签、换资源策略，还是减少回流。

性能之外还有两条边界别搞混：`title` 和 `h1` 承担的是不同的标题语义，`link` 和 `@import` 的资源发现时机也不一样。
