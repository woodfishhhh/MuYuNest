一张图片没有替代文本，读屏软件就不知道它表达什么；样式表发现太晚，首屏就会等待；JavaScript 频繁修改布局，浏览器又要重新计算位置。

HTML 标签决定结构和语义，CSS 决定展示方式，资源加载顺序和 DOM、CSSOM 的变化则直接影响首屏与交互性能。

## 一、HTML 元素的基础分类

按默认显示行为和是否包含子内容，基础页面中常把元素分为行内元素、块级元素和空元素。

### 1. 行内元素

常见的行内元素有：

- `span`
- `img`
- `input`

这类元素通常不独占一行。img 和 input 属于可替换元素，它们的尺寸行为和普通文本行内元素不完全相同。

### 2. 块级元素

常见的块级元素有：

- `div`
- `footer`
- `header`
- `section`
- `p`
- `h1` 到 `h6`

块级元素默认会独占一行，适合做结构划分。

### 3. 空元素

空元素本身没有闭合内容，例如：

- `br`
- `hr`

空元素没有结束标签，也不包含子节点。

### 4. display 可以改变元素表现形式

HTML 标签本身有默认显示行为，但并不是写死的。我们可以通过 `display` 改变它的呈现方式：

```css
div {
  display: inline;
}

div {
  display: inline-block;
}

div {
  display: block;
}
```

这里要分清一件事：`display` 改变的是表现，不会改变标签的语义。也就是说，一个 `div` 就算被写成 `inline`，它依旧不是语义上的行内文本标签。

## 二、页面引入样式时，`link` 和 `@import` 有什么区别

两种写法都能引入样式，差别在于资源何时被浏览器发现。

### 1. 语法位置不同

- `link` 是 HTML 标签，直接写在页面结构里
- `@import` 是 CSS 语法，一般写在样式表内部

### 2. 浏览器处理时机不同

浏览器解析页面时，会优先识别 `link` 对应的外部样式资源；`@import` 则需要先把当前 CSS 下载并解析后，才能继续发现并加载它引用的样式。

这意味着：

- `link` 往往更早参与页面渲染
- `@import` 更容易拉长样式依赖链

### 3. 兼容性不同

`link` 的兼容性和资源发现时机更稳定，页面中的外部样式通常优先用它引入。

### 4. 实战建议

如果不是处理非常特殊的样式组织需求，日常开发里优先使用 `link` 或打包工具统一构建，而不是在业务代码里大量使用 `@import`。

## 三、相似标签的语义边界

### 1. `title` 和 `h1` 的区别

它们都很重要，但作用完全不同。

- `title` 是页面标题，主要给浏览器标签页、搜索引擎结果页和页面整体概括使用
- `h1` 是页面正文中的一级主题，强调当前页面内容的核心主题

可以这样理解：

- `title` 更像“页面对外的总标题”
- `h1` 更像“正文内容的主标题”

在 SEO 语境里，二者都重要，但职责不同，不能互相替代。

### 2. `b` 和 `strong` 的区别

- `b` 更偏表现层，主要是加粗
- `strong` 更偏语义层，表示该内容“很重要”

如果只是纯视觉加粗，可以用 `b` 或者 CSS；如果是强调语义，优先用 `strong`。

### 3. `i` 和 `em` 的区别

- `i` 偏表现，默认斜体
- `em` 偏语义，表示强调

常见的使用方式是：

- `i` 更常见于字体图标或样式化文本
- `em` 更适合术语、重点词、强调语义

这就是“能用样式解决的，不一定有语义；有语义需求时，尽量用语义标签”。

## 四、`img` 的 `title` 和 `alt` 有什么区别

### 1. 展示层区别

- `title`：通常在鼠标移入图片时显示提示文字
- `alt`：图片加载失败时显示替代文本

### 2. 可访问性和 SEO 的区别

`alt` 更重要，因为它不只是“图片挂了时显示一句话”，而是给搜索引擎、屏幕阅读器、弱网环境和无图模式提供图片语义说明。

也就是说：

- `title` 更偏补充提示
- `alt` 更偏必要描述

如果图片承载内容信息，`alt` 应该认真写；如果图片纯装饰，可以使用空的 `alt=""`，让辅助技术忽略它。

## 五、常见图片格式怎么选

图片格式要在体积、清晰度、透明通道和动画能力之间取舍。

### 1. PNG

- 无损压缩
- 体积一般比 `jpg/jpeg` 更大
- 适合图标、透明背景、小型 UI 图形

### 2. JPG / JPEG

- 有损压缩
- 体积通常更小
- 适合照片、复杂色彩图片、大图展示

### 3. GIF

- 支持动图
- 色彩表现有限
- 适合简单动画，但现代前端很多场景会被视频或更高效格式替代

### 4. WebP

- 同时支持有损和无损压缩
- 通常体积更小
- 适合大多数 Web 场景

按页面用途选择时，可以先用下面的对照：

- UI 图标或透明素材优先考虑 `png` 或 `svg`
- 照片优先考虑 `jpg` 或 `webp`
- 页面大图优先做压缩和格式升级

## 六、从 CSS 到页面显示：浏览器渲染发生了什么

页面收到 HTML 和 CSS 后不会直接变成像素。浏览器要先建树，再计算布局和绘制结果。

一个页面大致经历这些步骤：

1. 浏览器解析 HTML，构建 DOM 树
2. 浏览器解析 CSS，构建 CSSOM
3. DOM 和 CSSOM 合并成渲染树
4. 执行布局，计算元素几何信息
5. 执行绘制，把像素画到屏幕上

如果 JavaScript 在这个过程中频繁改动 DOM 或样式，就可能触发额外的计算成本。

## 七、回流与重绘是什么

样式变化会不会重新计算布局，是区分回流和重绘的关键。

### 1. 重绘（Repaint）

重绘指的是元素样式改变了，但不影响布局位置，例如：

- 修改颜色
- 修改背景
- 修改阴影

这类变化不需要重新计算文档流位置，但仍然需要重新绘制。

### 2. 回流（Reflow / 重排）

回流发生在元素几何属性、位置或结构变化时，例如：

- 改变宽高
- 增删 DOM
- 改变字体大小
- 改变定位影响布局
- 读取某些布局属性后又连续写入样式

回流比重绘更重，因为它会重新走布局计算，而布局之后通常还会触发重绘。

### 3. 二者关系

二者的关系是：

- 回流一定可能伴随重绘
- 重绘不一定触发回流

所以前端优化里通常优先避免频繁回流。

## 八、如何减少回流与重绘

### 1. 合并样式修改

不要零散地一条条改样式，尽量批量修改，例如切换 class。

### 2. 减少频繁读写交替

读取布局信息和写入样式交替进行时，浏览器可能为了返回当前几何信息而强制同步布局。

### 3. 对复杂模块做隔离

比如动画元素使用 `transform`、`opacity`，通常比直接改 `top`、`left` 更友好。

### 4. 控制 DOM 数量

这和虚拟列表、组件拆分、按需渲染都有关系。DOM 多了，样式计算和布局计算都会跟着上涨。

## 九、从页面现象回到渲染链路

首屏样式出现太晚时，先检查外部 CSS 是何时被发现的；图片下载成本过高时，再根据内容和透明度需求调整格式。交互时出现卡顿，则看 JavaScript 是否在反复修改 DOM、交替读写布局属性。

这三类现象分别对应资源发现、传输体积和布局计算。问题落到具体阶段后，才能判断应该改标签、换资源策略，还是减少回流。

性能之外还有两条边界不能混：`title` 与 `h1` 承担不同的标题语义，`link` 与 `@import` 也有不同的资源发现时机。
