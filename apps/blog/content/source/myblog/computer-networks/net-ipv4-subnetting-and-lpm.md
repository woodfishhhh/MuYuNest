在大型局域网或企业内网规划中，把整段 IPv4 地址直接分配给单个广播域既浪费地址又容易引发广播风暴。本文把定长子网划分（FLSM）、可变长子网掩码（VLSM）的二进制计算步骤，以及路由器查表转发时的最长前缀匹配原则串在一起，直接用例题走通从地址分配到路由查表的完整链路。

## 为什么需要划分子网

**划分子网的本质是从 32 位 IPv4 地址的主机位里“借位”充当子网位，用增加子网数量换取每个子网的可用主机数收缩，同时把广播流量关在更小的广播域内。**

- **按需切分地址块**：传统的分类地址颗粒度太粗（例如一个 C 类网段固定 254 个可用主机地址），小部门直接占用整段会造成大量空置。
- **隔离广播域**：同一子网内的 ARP 广播或广播报文会泛洪到所有主机，切分后广播被边界路由器拦在各自子网内。
- **简化安全隔离与排错**：不同部门（如研发、财务）落在不同前缀下，防火墙 ACL 和故障定位可以直接按子网边界收敛。

## 子网掩码、块大小与计算公式

**计算子网划分时抓紧两个等式：剩余主机位 $n$ 决定每块总地址数 $2^n$（可用主机数 $2^n - 2$），而子网前缀长度永远等于 $32 - n$。**

IPv4 地址长 32 位，由网络前缀与主机号两部分组成。子网掩码同样为 32 位二进制，用连续的 `1` 标出网络位（含子网位），连续的 `0` 标出主机位，例如 `255.255.255.0` 在 CIDR 斜线记法下写成 `/24`。

在现代支持全 0 和全 1 子网的网络中，假设从原本的主机位借出 $m$ 位作为子网位，剩余 $n$ 位作为主机位：

- **可划分的子网数**：$2^m$（早期严格遵循有类路由的旧教材才减 2，现代 CIDR 网络均支持全 0/全 1 子网）。
- **每个子网的总 IP 数（块大小，Block Size）**：$2^n$，或者直接用 `256 - 最后一个非 255 的掩码字节` 心算（例如掩码 `255.255.255.224`，块大小 $= 256 - 224 = 32$）。
- **每个子网的可用主机数**：$2^n - 2$，减掉的 2 个地址分别是**网络地址**（主机位全 `0`，块起始地址）和**广播地址**（主机位全 `1`，下一块起始地址减 1）。

举例：`192.168.1.0/24` 借 3 位变为 `/27`，可切出 $2^3 = 8$ 个子网，每块大小 $2^5 = 32$，每个子网可分配主机数 $32 - 2 = 30$ 台。

## 五步实战划分子网（定长 FLSM）

**划分子网时必须保证每个子网的起始地址是“块大小”的整数倍，否则网络前缀位和主机位边界对不上，路由器无法正确聚合或识别。**

标准五步操作流程：

1. **统计需求**：确定至少需要几个子网，以及单个子网最多容纳多少台主机。
2. **反推主机位 $n$**：找到最小的 $n$ 满足 $2^n - 2 \ge \text{最大主机数}$，于是目标前缀长度为 $32 - n$。
3. **算出块大小**：$\text{Block Size} = 2^n$。
4. **切分地址范围**：从主网起始地址开始按块大小累加，依次写出网络地址、可用主机范围（首地址 +1 到末地址 -1）和广播地址。
5. **复核对齐**：确认子网数、单网主机数和掩码对齐均满足需求。

### 实战例题：均分 4 个支持 50 台主机的子网

**题目**：将 `192.168.10.0/24` 划分为 4 个子网，每个子网至少支持 50 台主机。

1. 确定主机位：需满足 $2^n - 2 \ge 50$，取 $n = 6$（$2^6 - 2 = 62 \ge 50$）。
2. 确定掩码：前缀长度 $= 32 - 6 = 26$，即 `/26`（点分十进制 `255.255.255.192`）。
3. 计算块大小：$2^6 = 64$（或 $256 - 192 = 64$）。
4. 列出 4 个子网：

| 子网 | 网络地址 | 可用主机范围 | 广播地址 |
| --- | --- | --- | --- |
| 1 | `192.168.10.0/26` | `192.168.10.1` ~ `192.168.10.62` | `192.168.10.63` |
| 2 | `192.168.10.64/26` | `192.168.10.65` ~ `192.168.10.126` | `192.168.10.127` |
| 3 | `192.168.10.128/26` | `192.168.10.129` ~ `192.168.10.190` | `192.168.10.191` |
| 4 | `192.168.10.192/26` | `192.168.10.193` ~ `192.168.10.254` | `192.168.10.255` |

## 变长子网掩码（VLSM）分配原则

**使用 VLSM 在同一主网下切分不同大小的部门网段时，必须遵循“先大后小”的分配顺序，否则先切出的小块会把原本连续的大块对齐边界拆碎。**

例如把主网 `192.168.1.0/24` 分给三个规模悬殊的部门：

1. **部门 A（需 60 台主机）**：选 $n=6$（`/26`，64 个地址），先占走 `192.168.1.0` ~ `192.168.1.63`。
2. **部门 B（需 20 台主机）**：选 $n=5$（`/27`，32 个地址），紧接着从 64 对齐边界分配 `192.168.1.64` ~ `192.168.1.95`。
3. **部门 C（需 10 台主机）**：选 $n=4$（`/28`，16 个地址），从 96 对齐边界分配 `192.168.1.96` ~ `192.168.1.111`。

总共只消耗了 $64 + 32 + 16 = 112$ 个地址，剩下的 `192.168.1.112` ~ `.255` 仍完整留给后续扩展。

## 最长前缀匹配原则与路由查表

**当目的 IP 同时命中路由表里的多条重叠前缀时，路由器永远选择前缀长度（掩码位数）最长的那一条，因为更长的前缀代表更精确的局部路由。**

假设一台路由器的转发表中有三条重叠路由：

- `192.168.0.0/16` → 下一跳 `R1`（覆盖 `192.168.0.0` ~ `192.168.255.255`）
- `192.168.1.0/24` → 下一跳 `R2`（覆盖 `192.168.1.0` ~ `192.168.1.255`）
- `0.0.0.0/0` → 下一跳 `R3`（默认路由，覆盖全网，匹配优先级最低）

当一个目的地址为 `192.168.1.10` 的分组到达时，以上三条全部满足前缀匹配，但 `/24` 比 `/16` 和 `/0` 更具体，因此路由器把分组转给 `R2`。

### 二进制逐位匹配判定示例

判断目的 IP 是否匹配一条路由条目 `网络地址/前缀长度`，严格做法是把目的 IP 与路由前缀都展开成二进制，比较前 `前缀长度` 位是否完全一致（等价于将目的 IP 与掩码做按位与运算后看结果是否等于该网络地址）。

**示例**：目的 IP `128.96.40.151`，路由条目 `128.96.40.0/25`（前 25 位必须一致）：

```text
路由前缀 128.96.40.0/25 前 25 位：
10000000.01100000.00101000.0   ← 第 25 位（第 4 字节最高位）为 0

目的 IP 128.96.40.151 前 25 位：
10000000.01100000.00101000.1   ← 151 = 10010111，第 25 位为 1
```

两者的第 25 位不相等，因此 `128.96.40.151` **不匹配** `128.96.40.0/25`（它属于另一半地址块 `128.96.40.128/25`）。

在实际的高速路由器硬件中，为了支持每秒数百万次查表而不逐条线性比对，通常会在控制面把路由前缀组织成前缀树（Trie）或压缩前缀树（Patricia Trie），再在数据面刷入硬件三态内容可寻址存储器（TCAM）实现单周期并行最长匹配。

## 常见易错点对照

| 常见误区 | 正确结论 |
| --- | --- |
| 默认“可用子网数 = $2^m - 2$” | 现代 CIDR 与支持 `ip subnet-zero` 的设备直接使用 $2^m$ |
| 把块最后一个地址分给主机 | 主机位全 `1` 是本子网广播地址，不可分配 |
| 子网起始地址任意挑选 | 必须对齐到块大小整数倍（如 `/26` 只能从 `.0`、`.64`、`.128`、`.192` 起步） |
| 只看十进制数字接近就判匹配 | 必须按二进制前缀位或 `IP & Mask == Net` 严格比对 |

日常验证子网切分或排查主机路由时，可以直接使用 Linux 下的 `ipcalc` 工具做交叉校验。
