操作系统决定哪些作业能进内存、哪个就绪进程拿到 CPU 时间片，以及多个并发进程争抢有限资源时怎样避免互相卡死。本文系统梳理三级调度分工、调度评价指标与六大经典调度算法，随后切入死锁的四个必要条件、四类应对策略、最少防死锁资源数公式以及银行家算法的完整两段式校验流程。

## 处理机调度层次

**处理机调度按时间尺度与内存驻留状态分为三级：高级调度决定作业进内存（无到有），中级调度把挂起进程换出/换回外存，低级调度负责从就绪队列挑进程上 CPU 执行（频率最高）。**

| 调度层次 | 别名 | 核心功能 | 调度频率 |
| --- | --- | --- | --- |
| 高级调度 | 作业调度 / 长期调度 | 从外部后备作业池挑选任务分配内存并放入**就绪队列** | 低（分钟级及以上） |
| 中级调度 | 内存调度 | 将内存中暂不能运行的挂起进程调至外存对换区，缓解内存紧张 | 中（高于高级，低于低级） |
| 低级调度 | 进程调度 / 时间片调度 | 从内存就绪队列选进程分配 CPU 执行权 | 高（最频繁，系统核心调度） |

## 调度评价指标与系统目标

**同一个调度算法放到不同系统里评价截然不同：批处理系统盯紧周转时间与吞吐量，分时系统优先保障交互响应时间，实时系统首要保证截止时间与最坏情况可预测性。**

### 所有系统的共同目标

1. **CPU 利用率**：$CPU利用率 = \frac{CPU执行任务时间}{总时间} \times 100\%$，反映处理器处于有效计算状态的时间比例；
2. **公平性**：让每个进程都有执行机会，避免长期得不到资源；
3. **平衡性**：协调处理器、内存和 I/O 设备负载，避免一处过载而另一处闲置；
4. **策略强制执行**：调度器严格按既定规则分配 CPU，保证多任务并发符合预期。

### 三类典型系统的侧重指标

- **批处理系统**：
  1. **平均周转时间短**：周转时间 $T = \text{进程完成时间} - \text{进程提交时间}$，平均周转时间 $\overline{T} = \frac{\sum_{i=1}^n T_i}{n}$，衡量任务从提交到完成平均等多久；
  2. **平均带权周转时间合理**：带权周转时间 $W = \frac{\text{周转时间 } T}{\text{进程实际执行时间 } t}$，平均带权周转时间 $\overline{W} = \frac{\sum_{i=1}^n W_i}{n}$，衡量等待成本相对于任务本身运行时间的倍率（恒 $\ge 1$）；
  3. **系统吞吐量高**：$\text{吞吐量} = \text{单位时间内完成的任务数}$；
  4. **高 CPU 利用率**。
- **分时系统**：追求快**响应时间**（$\text{响应时间} = \text{用户发起请求到系统首次给出反馈的总时间}$）与**均衡性**（防止单个任务长期霸占处理器）。
- **实时系统**：必须满足**截止时间**（错过截止时间可能导致结果失效甚至安全事故）与**可预测性**（重点关注最坏情况下的响应时间上界）。

## 六大经典调度算法取舍

**抢占式 SJF（最短剩余时间优先）能给出理论上最小的平均等待时间，但连续到来的短作业会让长作业彻底饥饿；高响应比优先（HRRN）把等待时间写进分子拉高长作业优先级，而通用分时系统（Linux/Unix）则靠多级反馈队列折中吞吐与响应。**

### 1. 先来先服务（FCFS）

- **规则**：按进程到达就绪队列的先后顺序非抢占式执行。
- **利弊与场景**：实现最简单且不会饥饿，但会出现“护航效应”——长作业排在最前面时，后面一大批短作业和 I/O 密集型任务只能干等，平均带权周转时间飙升。

### 2. 短作业/短进程优先（SJF / SPF）

- **规则**：优先调度预计执行时间最短的任务（非抢占式为 SJF；允许新来的更短任务抢占当前运行进程的称为最短剩余时间优先 SRTN）。
- **利弊与场景**：在所有非抢占算法中平均等待和平均周转时间最优；缺点是实际运行时间往往只能估算，且源源不断的短任务会让长进程**饥饿**，同时未考虑任务紧迫度。

### 3. 优先级调度

- **规则**：每个进程带有优先级（注意题干规定“数字越小优先级越高”还是相反）。
- **两维分类**：
  - **是否抢占**：抢占式（高优先级就绪时立即剥夺低优先级进程 CPU）vs 非抢占式（等当前进程主动让出或完成）；
  - **优先级是否动态变化**：静态优先级（创建时固定，通常交互型 > 非交互型、I/O 型 > 计算型）vs 动态优先级（随等待时间或已占用 CPU 时长动态升降）。
- **风险**：静态优先级叠加高负载时，低优先级进程可能发生饥饿。

### 4. 高响应比优先（HRRN）

- **响应比公式**：

$$响应比\ HRR = \frac{等待时间 + 要求服务时间}{要求服务时间} = 1 + \frac{等待时间}{要求服务时间}$$

- **权衡**：作业等待时间相同时，短作业分母小、响应比高（保留 SJF 优势）；长作业只要等得够久，分子增大后响应比照样会超过刚到的短作业（彻底避免饥饿）。代价是每次调度都要重算所有就绪进程响应比。

### 5. 时间片轮转（RR）

- **规则**：就绪队列按 FIFO 排队，每个进程每次只拿固定时间片 $q$，用完未结束则被时钟中断剥夺并插回就绪队列尾部。
- **参数 $q$ 的影响**：
  1. $q$ **过小**：上下文切换极其频繁，系统开销剧增；
  2. $q$ **过大**（大于大多数任务执行时间）：退化为 FCFS，失去分时交互响应优势。

### 6. 多级反馈队列（MLFQ）

- **规则**：设置多条优先级递减的就绪队列，优先级越高分配的时间片 $q$ 越小。新进程先入最高优先级队列按 RR 运行；时间片耗尽未完成则降级到下一级队列，仅当高优先级队列全空时才调度低级队列，且低级队列运行时可被新进入高级队列的进程抢占。
- **适配特性**：短进程在高优先级队列一轮即可跑完，I/O 密集型进程每次阻塞唤醒回到高级队列响应极快，长计算型进程沉降到低级队列用较大时间片减少切换开销；若配合周期性优先级提升（Aging），还能防止长进程饥饿。

## 死锁原因与四类处理策略

**死锁的本质是并发环境下多进程形成循环等待链；破坏四个必要条件之一属于“死锁预防”，分配前用银行家算法检查安全序列属于“死锁避免”，允许发生后再破环属于“死锁检测与解除”。**

### 死锁定义与四个必要条件（缺一不可）

多个进程/线程竞争有限资源时，各自占用一部分资源不放，同时又在等待对方手里的剩余资源，导致全部推进停滞即为死锁。死锁成立必须同时满足四个必要条件：

1. **互斥条件**：至少存在一类临界资源，同一时刻只能被一个进程占用。
2. **请求与保持条件**：进程已经持有部分资源不释放，同时还在请求新的资源。
3. **不可剥夺条件**：已分配给进程的资源不能被强行抢走，只能由持有者使用完毕主动释放。
4. **环路等待条件**：存在进程等待环路 $\{P_0, P_1, \dots, P_k\}$，每个进程都在等待下一个进程所持有的资源。

### 四类处理思路对比

1. **死锁预防（静态破坏四个必要条件之一）**：
   - 破坏互斥：将临界资源改造为共享或采用 SPOOLing 虚拟化（多数硬件临界资源难以直接改造）；
   - 破坏请求与保持：要求进程启动前一次性申请全部所需资源，或申请新资源前必须先释放已占资源（资源利用率低，易饥饿）；
   - 破坏不可剥夺：申请新资源受阻时主动释放已有资源，或允许高优先级进程强抢；
   - 破坏环路等待：对所有资源类型统一编号，规定进程必须严格**按编号递增顺序**申请资源（工程上最常用于多层锁排序防死锁）。
2. **死锁避免（动态安全性检查）**：不提前限制申请规则，而是在每次分配前运行**银行家算法**试探——只有分配后系统仍能找出至少一条**安全序列** $P_1, P_2, \dots, P_n$（满足每个进程的 $Need_i \le Available$，依次执行完毕并归还 $Allocation_i$），才允许正式分配；否则让请求方等待。代价是必须预先获知每个进程的最大资源需求 `Max`。
3. **死锁检测与解除**：放行分配，后台定期分析资源分配图（每类资源仅 1 个实例时，有环即死锁；每类有多实例时，有环只是死锁的必要信号，需进一步化简检测算法确认）。确认死锁后通过**资源抢占**、**终止部分环路进程**或**进程回滚**强行破环。
4. **死锁忽略（鸵鸟策略）**：当死锁概率极低而防范/检测代价远超故障损失时，直接交由人工重启或超时恢复（如常规桌面系统常采取的整体策略取舍，系统底层核心资源仍会做并发保护）。

## 统考高频计算题型与银行家算法步骤

**算题先画状态与时间线：算周转时间先排出甘特图完成时刻；算银行家算法先分清 `合法性/可用性预检` 和 `安全性检查` 两段，切忌没更新矩阵就直接判安全。**

### 1. 引发进程调度的常见事件

判断核心是“事件是否让 CPU 空闲，或改变了就绪队列状态”。常见触发点包括：中断处理结束、当前进程阻塞（I/O 请求或等锁）、进程执行完毕退出、时间片用完、更高优先级进程进入就绪队列。

### 2. 避免死锁的最少资源数计算

在“系统中共有 $n$ 个进程竞争同一类可重用资源，每个进程最多需要 $m$ 个该资源”的条件下，避免死锁的最少资源总数为：

$$N = n \times (m - 1) + 1$$

- **推导逻辑**：考虑最坏推进情况——所有 $n$ 个进程都恰好拿到了 $m - 1$ 个资源而卡在最后 1 个缺口上。此时系统里只要再多出 **1 个**空闲资源，就必然能让至少一个进程凑够 $m$ 个资源顺利跑完并归还全部 $m$ 个资源，从而盘活剩余所有进程。例如 $n$ 个进程各需 2 个资源，最少需要 $n \times 1 + 1 = n + 1$ 个。

### 3. 调度算法平均周转时间与带权周转时间计算步骤

1. 按题目调度规则（FCFS / SJF / SRTN / HRRN / RR）依次排出各进程的执行时间线（甘特图），注意区分到达时间与是否可抢占；
2. 读出每个进程的完成时间，计算 $T_i = \text{完成时间} - \text{到达时间}$ 与 $W_i = \frac{T_i}{t_i}$；
3. 汇总求平均值 $\overline{T}$ 与 $\overline{W}$（通常忽略进程上下文切换开销）。

### 4. 银行家算法完整两段式检验

给定可用资源向量 $Available$、最大需求矩阵 $Max$、已分配矩阵 $Allocation$、剩余需求矩阵 $Need = Max - Allocation$：

#### （1）安全性检查（判定某状态是否安全）

1. 初始化工作向量 $Work = Available$，完成标记 $Finish[i] = \text{false}$。
2. 扫描寻找同时满足 $Finish[i] = \text{false}$ 且 $Need[i] \le Work$ 的进程 $P_i$。
3. 若找到，模拟 $P_i$ 运行完毕并释放全部已占资源：$Work = Work + Allocation[i]$，$Finish[i] = \text{true}$，将该进程记入安全序列后回到第 2 步继续扫描。
4. 若最终所有进程的 $Finish[i]$ 均为 $\text{true}$，则存在安全序列、系统处于安全状态；否则处于不安全状态（注意：不安全状态不一定立刻死锁，只是存在死锁风险）。

#### （2）资源请求判别（进程 $P_i$ 提出请求 $Request[i]$）

1. **合法性检查**：检验 $Request[i] \le Need[i]$ 是否成立，超出声明最大需求直接报错拒绝。
2. **可用性检查**：检验 $Request[i] \le Available$ 是否成立，当前剩余资源不足则让 $P_i$ 阻塞等待。
3. **试探性分配**：临时更新三个状态：
   - $Available = Available - Request[i]$
   - $Allocation[i] = Allocation[i] + Request[i]$
   - $Need[i] = Need[i] - Request[i]$
4. **安全性校验**：对试探后的新状态运行上述安全性检查。若能找到安全序列则正式提交分配；若处于不安全状态则**全部回滚**至第 3 步之前的原状态，令 $P_i$ 等待。
