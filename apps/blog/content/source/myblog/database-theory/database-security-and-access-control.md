数据库安全的核心防线要依次解决三件事：确认来者是谁（身份鉴别）、限制对方能碰哪些对象（存取控制），以及在事故发生后能还原操作链路（安全审计）。光靠应用层代码拦截并不够，一旦凭证泄露或有人直连数据库实例，必须依赖 DBMS 自身的多层控制机制兜底。

## 安全评估标准与整体控制框架

早期的安全评估体系中，美国国防部 TCSEC（1985 年）和国际通用准则 CC（1999 年）划定了数据库产品的安全基线：

| TCSEC 等级 | 对应的安全能力里程碑 | CC 对应参考 |
| :--- | :--- | :--- |
| D | 最低级，不满足更高标准的所有系统 | — |
| C1 | 初级自主安全保护，实现基本的 DAC，隔离用户与数据 | EAL2 |
| C2 | 安全产品的最低实用档：细化 DAC，具备身份注册、审计与资源隔离 | EAL3 |
| B1 | 真正意义上的安全产品：对数据打密级标记，引入强制存取控制（MAC） | EAL4 |
| B2 / B3 / A1 | 依次引入形式化安全模型、访问监控器与完整形式化设计验证 | EAL5 ~ EAL7 |

在实际运行环境中，DBMS 的安全防线是一条串联链路：用户身份鉴别 → DBMS 存取控制 → 操作系统级文件保护 → 传输链路加密 → 静态密码与数据存储加密。其中 DBMS 内部主线围绕“事前授权与身份验证、事中权限检查、事后审计追溯”展开。

## 用户身份鉴别与账号分级

系统为每个用户分配用户名和全生命周期唯一的内部标识号。根据安全等级要求，常用四类鉴别方式：

| 鉴别方式 | 机制特点 | 典型适用场景 |
| :--- | :--- | :--- |
| 静态口令 | 口令简单或结合数字证书构成双因子 | 常规业务账号登录 |
| 动态口令 | 一次一密、定时或按事件动态变化 | 临时运维访问、高敏感接口 |
| 生物特征识别 | 依赖指纹、掌纹、虹膜等唯一生理特征 | 高安全等级门禁与内核操作 |
| 智能卡 | 不可复制硬件介质，常配合 PIN 码使用 | 线下专用终端与涉密环境 |

标准 SQL 在建号层面也划分了明确的能力边界，禁止普通业务账号持有建库或全局管理权：

- **超级用户**：`CREATE USER <用户名> WITH SUPERUSER [PASSWORD <密码>];` 拥有全库全部权限，只能由初始化超级用户创建。
- **建库用户**：`CREATE USER <用户名> WITH CREATEDB [PASSWORD <密码>];` 可创建新数据库及模式并作为属主授权。
- **普通用户**：`CREATE USER <用户名> PASSWORD <密码>;` 初始无权，仅能执行被显式授予的对象操作。

## 自主存取控制（DAC）

**自主存取控制（DAC，C1/C2 级）允许对象创建者或管理员把权限精准授给指定用户，也允许通过 `WITH GRANT OPTION` 控制权限能否二次转授。**

存取控制子系统的工作流分为两步：先通过授权语句把权限规则写入数据字典；用户每次发起 SQL 请求时，DBMS 查数据字典校验权限，不合法直接拒绝。

### 1. GRANT 授权与转授边界

```sql
GRANT 权限1[, 权限2, ...]
ON 对象名
TO 用户1[, 用户2, ... | PUBLIC]
[WITH GRANT OPTION];
```

- `PUBLIC` 表示授予全体用户；针对特定列授权（如只允许修改学号或成绩）时需显式写明列名，例如 `UPDATE(Grade)`。
- 拥有授权资格的主体仅限三类：DBA、数据库对象创建者，以及获得该权限时附带了 `WITH GRANT OPTION` 的用户。

### 2. REVOKE 收回与级联陷阱

```sql
REVOKE 权限1[, 权限2, ...]
ON 对象名
FROM 用户1[, 用户2, ... | PUBLIC]
[CASCADE | RESTRICT];
```

`REVOKE` 默认采用 `RESTRICT` 策略：如果被收回权限的用户已经把该权限转授给了下游其他用户，收回操作会直接报错失败；改用 `CASCADE` 则会沿着转授链级联收回目标用户及其下游的全部同名权限。

```sql
-- 1. 授予 U1 查询 Student 表的权限
GRANT SELECT ON TABLE Student TO U1;

-- 2. 授予 U5 插入 SC 表的权限并允许转授
GRANT INSERT ON TABLE SC TO U5 WITH GRANT OPTION;

-- 3. 级联收回 U5 及被 U5 转授用户的插入权限
REVOKE INSERT ON TABLE SC FROM U5 CASCADE;
```

## 强制存取控制（MAC）

自主存取控制虽然灵活，但无法阻止拥有读权限的用户把敏感数据复制写进自己创建的公开表里从而导致泄露。对保密要求极高的军政或核心金融系统，必须在 DAC 之上再叠加 B1 级别的强制存取控制（MAC）。

MAC 把系统元素划分为两类，并各自打上不可剥离的敏感级标记（从高到低依次为：绝密 PS > 机密 S > 可信 C > 公开 P）：

- **主体**：系统中的活动实体（用户及代表用户运行的进程），拥有**许可证级别**。
- **客体**：系统中的被动实体（文件、基本表、视图、索引），拥有**密级**。

**MAC 的核心铁律是“下读上写”：主体许可证级别必须高于等于客体密级才能读取，必须低于等于客体密级才能写入。**

1. **读规则（No Read Up）**：仅当 $\text{主体许可证级别} \ge \text{客体密级}$ 时，主体才允许读取该客体。
2. **写规则（No Write Down）**：仅当 $\text{主体许可证级别} \le \text{客体密级}$ 时，主体才允许写入该客体。

禁止“向下写”看似反直觉，实则极其关键——它防止高权限进程把绝密数据降级写入公开表造成隐蔽泄密。由于密级标记与数据本身强绑定，无论数据如何复制或转存，敏感标记都会随数据流转，未达标的主体始终无法触碰。

## 基于角色的存取控制（RBAC）与视图隔离

当系统存在成百上千名员工时，逐人执行 `GRANT`/`REVOKE` 极易出现权限遗漏或离职未清理。**角色（Role）是一组权限的命名集合**，把岗位权限打包给角色、再把角色分配给用户，可以大幅降低授权维护成本。

### 角色管理语法

1. 创建角色：`CREATE ROLE <角色名>;`
2. 为角色授予对象权限：`GRANT <权限> ON <对象> TO <角色名>;`
3. 将角色授予用户或其他角色：`GRANT <角色名1> TO <用户/角色名2> [WITH ADMIN OPTION];` 其中 `WITH ADMIN OPTION` 控制受授者能否继续转授该角色。
4. 收回角色权限或收回用户持有的角色：
   - `REVOKE <权限> ON <对象> FROM <角色名>;`
   - `REVOKE <角色名> FROM <用户/其他角色>;`

```sql
CREATE ROLE R1;
GRANT SELECT, UPDATE, INSERT ON TABLE Student TO R1;
GRANT R1 TO 王平, 张明;
REVOKE R1 FROM 王平;
```

### 结合视图做行列级隔离

角色解决的是“表级/列级操作集”的复用，若要按业务行（例如只看本院系学生）做精细隔离，需配合带 `WITH CHECK OPTION` 的视图：

```sql
CREATE VIEW <视图名> AS <查询语句> [WITH CHECK OPTION];
```

```sql
CREATE VIEW CS_Student AS
SELECT * FROM Student WHERE Smajor = '计算机科学技术'
WITH CHECK OPTION;

GRANT SELECT ON CS_Student TO 王平;
GRANT ALL PRIVILEGES ON CS_Student TO 张明;
```

通过只向业务用户开放 `CS_Student` 视图的访问权并收回基表 `Student` 权限，就能把其他专业记录与敏感字段屏蔽在视图之外，且 `WITH CHECK OPTION` 会拦截通过视图把记录篡改成其他专业的操作。

## 安全审计（C2 级及以上的事后防线）

事前的权限拦截无法防范合法账号的越界滥用或内部人员误删数据。C2 级及以上的 DBMS 必须提供审计功能，把用户的连接、权限变更和敏感表操作连同操作人、时间戳与执行结果一并写入专用审计日志，交由独立审计员审查：

- **开启与取消审计**：`AUDIT <操作类型> ON <对象> [BY ACCESS];` 与 `NOAUDIT <操作类型> ON <对象>;`。
- **审计粒度**：分为用户级审计（表属主针对自己名下对象的操作监控）和系统级审计（DBA 监控登录尝试、系统权限变更等全局事件）。

开启全量审计会明显消耗 CPU 与磁盘 I/O，生产环境通常只针对核心资金表、权限变更和异常登录开启。**审计日志本身必须执行“先安全转储、再删除清理”的硬约束，且仅允许审计员查阅与转储，任何普通用户甚至 DBA 都无权篡改或直接抹除审计记录。**

把这几层机制按场景组合就能看清各自的分工：身份鉴别守住入口，DAC 与 RBAC 负责日常细粒度分权，视图收紧行列可见范围，MAC 守住高密级系统的防泄密底线，审计则在事后留存不可抵赖的操作证据。
