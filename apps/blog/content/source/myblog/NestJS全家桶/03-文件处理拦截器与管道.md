# NestJS 文件处理、拦截器与管道

文件上传难的一般不是接收 `multipart/form-data`，而是文件名、目录、类型限制和公开访问策略。下面先跑通一条完整链路，再处理统一响应、异常和 DTO 校验。

## 上传文件

Express 平台下 Nest 用 Multer 处理文件。框架的适配包一般已经装了，只要补上 Multer 的类型声明：

```bash
npm i -D @types/multer
```

先在模块里配磁盘存储：

```ts
// upload/upload.module.ts
import { BadRequestException, Module } from '@nestjs/common';
import { MulterModule } from '@nestjs/platform-express';
import { diskStorage } from 'multer';
import { randomUUID } from 'node:crypto';
import { mkdirSync } from 'node:fs';
import { join } from 'node:path';
import { UploadController } from './upload.controller';

const uploadDir = join(process.cwd(), 'uploads');
mkdirSync(uploadDir, { recursive: true });

@Module({
  imports: [
    MulterModule.register({
      storage: diskStorage({
        destination: uploadDir,
        filename: (_request, file, callback) => {
          const extensions: Record<string, string> = {
            'image/jpeg': '.jpg',
            'image/png': '.png',
            'image/webp': '.webp',
          };
          const extension = extensions[file.mimetype];
          callback(null, `${randomUUID()}${extension}`);
        },
      }),
      limits: {
        fileSize: 5 * 1024 * 1024,
      },
      fileFilter: (_request, file, callback) => {
        const allowed = /^image\/(jpeg|png|webp)$/.test(file.mimetype);
        callback(
          allowed ? null : new BadRequestException('只允许上传 JPEG、PNG 或 WebP'),
          allowed,
        );
      },
    }),
  ],
  controllers: [UploadController],
})
export class UploadModule {}
```

用 `process.cwd()` 而不是 `__dirname`：编译后目录会从 `src` 变成 `dist`，用 `__dirname` 文件可能存到意想不到的地方。`mkdirSync(..., { recursive: true })` 保证第一次启动时目录存在。

文件名别直接用 `originalname`：

- 原始名称可能重复，后上传的会覆盖旧文件。
- 名称里可能有路径分隔符或控制字符。
- 中文名换个客户端、换个编码就可能乱码。
- 文件名证明不了真实的文件类型。

Controller 用 `FileInterceptor` 接收单个文件：

```ts
// upload/upload.controller.ts
import {
  BadRequestException,
  Controller,
  MaxFileSizeValidator,
  ParseFilePipe,
  Post,
  UploadedFile,
  UseInterceptors,
} from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';

@Controller('uploads')
export class UploadController {
  @Post()
  @UseInterceptors(FileInterceptor('file'))
  upload(
    @UploadedFile(
      new ParseFilePipe({
        fileIsRequired: true,
        validators: [
          new MaxFileSizeValidator({ maxSize: 5 * 1024 * 1024 }),
        ],
        exceptionFactory: (message) => new BadRequestException(message),
      }),
    )
    file: Express.Multer.File,
  ) {
    return {
      filename: file.filename,
      size: file.size,
      mimeType: file.mimetype,
      url: `/static/${file.filename}`,
    };
  }
}
```

请求里的字段名必须是 `file`。多文件上传用 `FilesInterceptor('files', maxCount)` 和 `@UploadedFiles()`，不是给 `FileInterceptor` 加个 `s` 就行。

### 校验真实文件类型

`file.mimetype` 来自客户端，能伪造。`FileTypeValidator` 适合做入口过滤，敏感业务还要读文件头的魔数，保存前做病毒扫描或内容解码验证。允许传图片的话，至少用白名单，别只禁几个危险后缀。

```ts
import { FileTypeValidator } from '@nestjs/common';

new FileTypeValidator({
  fileType: /^image\/(jpeg|png|webp)$/,
});
```

生产环境一般还要把上传目录放到 Web 根目录之外，用对象存储。确认文件可以公开了，才返回公开 URL。

## 静态文件目录

用 Express 适配器时可以直接挂静态目录：

```ts
// main.ts
import { NestFactory } from '@nestjs/core';
import { NestExpressApplication } from '@nestjs/platform-express';
import { join } from 'node:path';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create<NestExpressApplication>(AppModule);

  app.useStaticAssets(join(process.cwd(), 'uploads'), {
    prefix: '/static/',
  });

  await app.listen(3000);
}

void bootstrap();
```

这样 `uploads/abc.png` 对应 `/static/abc.png`。只适合公开文件；用户的私有文件要走鉴权接口下载，不能把整个目录暴露出去。

## 下载文件

### 直接下载

Express 的 `Response.download()` 会设置附件响应头：

```ts
import { Controller, Get, Param, Res } from '@nestjs/common';
import { Response } from 'express';
import { basename, join } from 'node:path';

@Controller('files')
export class FilesController {
  @Get(':name/download')
  download(@Param('name') name: string, @Res() response: Response) {
    const safeName = basename(name);
    const filePath = join(process.cwd(), 'uploads', safeName);

    return response.download(filePath, safeName);
  }
}
```

`basename()` 只是最低限度的路径穿越防护。真实系统更稳的做法是路由接收数据库 ID，由服务端查出受控的文件路径，别让客户端直接拼磁盘路径。

### 流式返回

大文件别先整个读进内存。Nest 的 `StreamableFile` 能保留框架对响应的控制：

```ts
import {
  Controller,
  Get,
  NotFoundException,
  Param,
  StreamableFile,
} from '@nestjs/common';
import { createReadStream, existsSync } from 'node:fs';
import { basename, join } from 'node:path';

@Controller('files')
export class FilesController {
  @Get(':name/stream')
  stream(@Param('name') name: string) {
    const safeName = basename(name);
    const filePath = join(process.cwd(), 'uploads', safeName);

    if (!existsSync(filePath)) {
      throw new NotFoundException('文件不存在');
    }

    return new StreamableFile(createReadStream(filePath), {
      type: 'application/octet-stream',
      disposition: `attachment; filename="${encodeURIComponent(safeName)}"`,
    });
  }
}
```

流的好处是边读边发，内存占用不会跟着文件大小线性涨。要打包多个文件，就用 ZIP/TAR 库把归档流直接接到响应上，别先把所有文件读进内存。

浏览器端接收二进制响应：

```ts
async function downloadFile(url: string, filename: string) {
  const response = await fetch(url);
  if (!response.ok) {
    throw new Error(`下载失败：${response.status}`);
  }

  const blob = await response.blob();
  const objectUrl = URL.createObjectURL(blob);
  const anchor = document.createElement('a');

  anchor.href = objectUrl;
  anchor.download = filename;
  anchor.click();
  URL.revokeObjectURL(objectUrl);
}
```

这里容易忘了 `URL.revokeObjectURL()`，连续下载几次，浏览器就一直占着 Blob 对应的内存。

## RxJS 与拦截器

Nest 的拦截器围绕 `Observable` 工作。一个 Observable 能连续发出值，订阅者通过 `next`、`error` 和 `complete` 接收三类通知：

```ts
import { interval, map, take } from 'rxjs';

interval(500)
  .pipe(
    take(5),
    map((value) => ({ value })),
  )
  .subscribe({
    next: console.log,
    error: console.error,
    complete: () => console.log('done'),
  });
```

`pipe()` 把操作符串成一条数据处理链。拦截器里的 `next.handle()` 就是 Controller 返回结果对应的 Observable，所以能用 `map()` 统一改写响应。

```ts
// common/response.interceptor.ts
import {
  CallHandler,
  ExecutionContext,
  Injectable,
  NestInterceptor,
} from '@nestjs/common';
import { Observable, map } from 'rxjs';

export interface ApiResponse<T> {
  success: true;
  data: T;
}

@Injectable()
export class ResponseInterceptor<T>
  implements NestInterceptor<T, ApiResponse<T>>
{
  intercept(
    _context: ExecutionContext,
    next: CallHandler<T>,
  ): Observable<ApiResponse<T>> {
    return next.handle().pipe(
      map((data) => ({
        success: true as const,
        data,
      })),
    );
  }
}
```

在根模块里通过 Provider 注册，拦截器照样能用依赖注入：

```ts
import { APP_INTERCEPTOR } from '@nestjs/core';

@Module({
  providers: [
    {
      provide: APP_INTERCEPTOR,
      useClass: ResponseInterceptor,
    },
  ],
})
export class AppModule {}
```

别给所有响应机械地套壳。文件流、SSE、重定向和已经手动操作 `@Res()` 的接口，一般要跳过统一格式化，不然二进制流可能被转成 JSON，或者出现重复写响应。

## 异常过滤器

异常过滤器把抛出的错误转成稳定的 HTTP 响应，`HttpException` 和未知异常都要处理：

```ts
// common/http-exception.filter.ts
import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpException,
  HttpStatus,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const context = host.switchToHttp();
    const request = context.getRequest<Request>();
    const response = context.getResponse<Response>();

    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    const detail =
      exception instanceof HttpException
        ? exception.getResponse()
        : 'Internal server error';

    response.status(status).json({
      success: false,
      statusCode: status,
      path: request.url,
      timestamp: new Date().toISOString(),
      error: detail,
    });
  }
}
```

注册方式：

```ts
import { APP_FILTER } from '@nestjs/core';

{
  provide: APP_FILTER,
  useClass: HttpExceptionFilter,
}
```

未知异常别把堆栈、SQL、绝对路径这些内部信息直接返回给客户端。服务端日志可以记完整错误，公开响应只给稳定的错误码和安全的描述。

## 管道转换

HTTP 路径参数和查询参数的原始值都是字符串。Pipe 能在 Controller 执行前完成转换和校验：

```ts
import {
  Controller,
  Get,
  Param,
  ParseBoolPipe,
  ParseIntPipe,
  ParseUUIDPipe,
  Query,
} from '@nestjs/common';

@Controller('users')
export class UsersController {
  @Get(':id')
  findOne(
    @Param('id', new ParseUUIDPipe({ version: '4' })) id: string,
    @Query('page', ParseIntPipe) page: number,
    @Query('active', ParseBoolPipe) active: boolean,
  ) {
    return { id, page, active };
  }
}
```

转换失败时，内置 Pipe 直接抛 400，Controller 根本不会执行。别用 `Number(value)` 之后拿着 `NaN` 继续处理，也别把类型断言当成运行时转换。

## DTO 校验

安装校验和转换依赖：

```bash
npm i class-validator class-transformer
```

DTO 得是运行时存在的类，装饰器才能挂上元数据：

```ts
// auth/dto/create-user.dto.ts
import { Type } from 'class-transformer';
import {
  IsInt,
  IsNotEmpty,
  IsString,
  Length,
  Max,
  Min,
} from 'class-validator';

export class CreateUserDto {
  @IsString()
  @IsNotEmpty()
  @Length(5, 20)
  username!: string;

  @Type(() => Number)
  @IsInt()
  @Min(1)
  @Max(150)
  age!: number;
}
```

在应用入口打开全局校验：

```ts
import { ValidationPipe } from '@nestjs/common';

app.useGlobalPipes(
  new ValidationPipe({
    transform: true,
    whitelist: true,
    forbidNonWhitelisted: true,
  }),
);
```

- `transform`：按 DTO 元数据创建类实例，并转换能识别的基础类型。
- `whitelist`：去掉 DTO 里没有校验装饰器的字段。
- `forbidNonWhitelisted`：碰到多余字段直接返回 400，不是悄悄删掉。

Controller 只接收已经通过校验的数据：

```ts
@Post()
create(@Body() body: CreateUserDto) {
  return this.usersService.create(body);
}
```

### 自定义 Pipe 的边界

自定义 Pipe 适合处理内置能力管不到的转换，比如把逗号分隔的 ID 转成数组：

```ts
import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

@Injectable()
export class ParseIdListPipe implements PipeTransform<string, number[]> {
  transform(value: string): number[] {
    const ids = value.split(',').map(Number);

    if (ids.length === 0 || ids.some((id) => !Number.isInteger(id))) {
      throw new BadRequestException('ids 必须是逗号分隔的整数');
    }

    return ids;
  }
}
```

通用的 DTO 校验不用手写 `plainToInstance()` 和 `validate()`，全局 `ValidationPipe` 已经处理了这条链路。自定义 Pipe 里只留真正属于业务输入格式的转换逻辑。

## 请求生命周期

这几类能力放到一起，请求顺序可以简化成：

```text
请求
  -> Guard：是否允许访问
  -> Interceptor：进入 Controller 前的横切逻辑
  -> Pipe：转换并校验参数
  -> Controller / Service
  -> Interceptor：格式化正常返回值
  -> Exception Filter：捕获并格式化异常
  -> 响应
```

文件接口要多留意：上传由 Multer 拦截器解析，下载可能返回流。统一响应拦截器、异常过滤器和文件响应之间要划清边界，别把二进制内容当成普通 JSON 处理。
