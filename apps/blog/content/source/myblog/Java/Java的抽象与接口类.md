抽象类和接口都能约束子类，用途不一样：抽象类是一套能复用的父类模板，接口用来声明一个类型能做哪些事。选错了代码也能写，只是后面扩展会越来越别扭。

| 对比维度   | 抽象类（is what）                                  | 接口（can do）                                                |
| ---------- | ------------------------------------------------- | ------------------------------------------------------------ |
| 定义方式   | 使用 `abstract class`                             | 使用 `interface`                                            |
| 实现手段   | 子类通过 `extends` 继承                           | 实现类通过 `implements` 实现                                |
| 成员变量   | 可以包含普通变量和常量                            | 字段默认是 `public static final` 常量                        |
| 方法类型   | 可以同时包含抽象方法和已经实现的方法              | Java 8 起可包含默认方法和静态方法，后续版本也能声明私有方法 |
| 多继承支持 | 一个类只能继承一个直接父类                        | 一个类可以实现多个接口                                      |
| 设计侧重点 | 表达一组相关类型“是什么”，并复用共同状态和实现    | 表达某个类型“能做什么”，只约定对外能力                      |

## 它们有哪些共同点

- 都不能直接创建对象，都可以声明要子类完成的抽象方法。
- 继承抽象类或实现接口后，要把还没实现的方法都实现，否则这个类自己也得声明成抽象类。
- 都能用在多态里。调用方依赖抽象类型、不依赖具体实现，换实现时不用改调用代码。

## 真正影响选择的差异

抽象类能保存实例状态，也能写完整的方法实现，适合几个相关的类共享字段和流程。代价是 Java 的类只能单继承：继承了这个抽象类，就不能再继承别的类。

接口不保存对象的普通实例状态，适合把功能拆开。一个类可以同时实现多个接口，也可以继承别的类的同时实现接口，组合起来更灵活。

怎么选：这些类型要共享状态和实现，一般用抽象类；只需要约定一组行为，优先用接口。
