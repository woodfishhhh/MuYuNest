抽象类和接口都能约束子类，但解决的问题不同。抽象类更像一套可以复用的父类模板，接口则用来声明某个类型具备哪些能力。选错了也能写代码，只是后续扩展会越来越别扭。

| 对比维度   | 抽象类（is what）                                  | 接口（can do）                                                |
| ---------- | ------------------------------------------------- | ------------------------------------------------------------ |
| 定义方式   | 使用 `abstract class`                             | 使用 `interface`                                            |
| 实现手段   | 子类通过 `extends` 继承                           | 实现类通过 `implements` 实现                                |
| 成员变量   | 可以包含普通变量和常量                            | 字段默认是 `public static final` 常量                        |
| 方法类型   | 可以同时包含抽象方法和已经实现的方法              | Java 8 起可包含默认方法和静态方法，后续版本也能声明私有方法 |
| 多继承支持 | 一个类只能继承一个直接父类                        | 一个类可以实现多个接口                                      |
| 设计侧重点 | 表达一组相关类型“是什么”，并复用共同状态和实现    | 表达某个类型“能做什么”，只约定对外能力                      |

## 它们有哪些共同点

两者都不能直接创建对象，也都可以声明需要子类完成的抽象方法。一个类继承抽象类或实现接口后，必须实现尚未完成的方法；否则这个类本身也要声明为抽象类。

它们同样可以参与多态。调用方依赖抽象类型，而不是某个具体实现，替换实现时就不需要改动调用代码。

## 真正影响选择的差异

抽象类可以保存实例状态，也可以提供完整的方法实现，适合多个相关类共享字段和流程。代价是 Java 的类继承只有一条主线：继承了这个抽象类，就不能再继承另一个类。

接口不负责保存对象的普通实例状态，更适合拆分能力。一个类可以同时实现多个接口，也可以在继承其他类的同时实现接口，因此组合起来更灵活。

判断时可以先问两个问题：这些类型是否共享状态和实现？如果答案是肯定的，抽象类通常更合适；如果只需要约定一组行为，优先使用接口。
