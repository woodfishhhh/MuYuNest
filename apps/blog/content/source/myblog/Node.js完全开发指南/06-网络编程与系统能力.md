# 网络编程与系统能力

TCP 最先让人踩坑的不是连接，而是消息边界。客户端连着调两次 `write`，服务端可能一次就收到，也可能拆成三次收到。下面用换行符定义一个最小协议，并限制单条消息的大小：

```js
import net from 'node:net';

const MAX_FRAME_BYTES = 64 * 1024;

const server = net.createServer((socket) => {
  socket.setEncoding('utf8');
  let pending = '';

  socket.on('data', (chunk) => {
    pending += chunk;

    let newline = pending.indexOf('\n');
    while (newline !== -1) {
      const frame = pending.slice(0, newline);
      pending = pending.slice(newline + 1);

      if (Buffer.byteLength(frame) > MAX_FRAME_BYTES) {
        socket.destroy(new Error('frame too large'));
        return;
      }

      try {
        const message = JSON.parse(frame);
        socket.write(JSON.stringify({ ok: true, message }) + '\n');
      } catch {
        socket.write(JSON.stringify({ ok: false, error: 'invalid json' }) + '\n');
      }

      newline = pending.indexOf('\n');
    }

    if (Buffer.byteLength(pending) > MAX_FRAME_BYTES) {
      socket.destroy(new Error('frame too large'));
    }
  });

  socket.on('error', (error) => {
    console.error('socket error', error);
  });
});

server.on('error', (error) => {
  console.error('server error', error);
});

server.listen(3000, '127.0.0.1');
```

这个缓冲区属于单个连接，不能在所有客户端之间共用。换行协议适合文本；二进制或任意内容，更适合在消息头里写长度。没有边界、大小限制和错误处理的 TCP 服务，只是在演示数据刚好没被拆包时看起来正常。

## TCP 只交付字节流

Node.js 的 `net` 模块直接暴露了 TCP 的客户端和服务端：

```js
const client = net.createConnection(
  { host: '127.0.0.1', port: 3000 },
  () => {
    client.write(JSON.stringify({ type: 'hello' }) + '\n');
  },
);

client.setEncoding('utf8');
client.on('data', (chunk) => {
  console.log('server:', chunk);
});
client.on('end', () => {
  console.log('server closed the connection');
});
client.on('error', (error) => {
  console.error('client error', error);
});
```

TCP 保证同一个连接里的字节有序、可靠地到达，但不提供 JSON、请求路径或状态码。超时、心跳、重连、消息格式和版本兼容，都属于应用协议要管的事。

直接手写一段 HTTP 响应，能看清应用层做了什么：

```js
net.createServer((socket) => {
  socket.once('data', () => {
    const body = '<h1>Hello</h1>';
    const response = [
      'HTTP/1.1 200 OK',
      'Content-Type: text/html; charset=utf-8',
      `Content-Length: ${Buffer.byteLength(body)}`,
      'Connection: close',
      '',
      body,
    ].join('\r\n');

    socket.end(response);
  });
}).listen(3001);
```

空行分开响应头和响应体，`Content-Length` 要按字节算。HTTP 框架帮我们处理了请求解析、路由、编码、连接复用和一大堆异常分支，远不止包了一层 `socket.write`。

## Socket.IO 房间

实时聊天室别把成员状态塞进一个全局数组就再也不管。连接断开时要清理，消息要验证，房间广播的对象也要选对。

```js
import { createServer } from 'node:http';
import { Server } from 'socket.io';

const httpServer = createServer();
const io = new Server(httpServer, {
  cors: { origin: ['http://localhost:5173'] },
  maxHttpBufferSize: 64 * 1024,
});

const members = new Map();

io.on('connection', (socket) => {
  socket.on('join', async (input, reply) => {
    const ack = typeof reply === 'function' ? reply : () => {};

    if (
      typeof input?.name !== 'string' ||
      typeof input?.room !== 'string'
    ) {
      return ack({ ok: false, message: '成员信息不合法' });
    }

    const name = input.name.trim();
    const room = input.room.trim();

    if (!name || !room || name.length > 30 || room.length > 50) {
      return ack({ ok: false, message: '成员信息不合法' });
    }

    const previous = members.get(socket.id);
    if (previous && previous.room !== room) {
      await socket.leave(previous.room);
      socket.to(previous.room).emit('system', {
        text: `${previous.name} 离开房间`,
      });
    }

    await socket.join(room);
    members.set(socket.id, { name, room });
    socket.to(room).emit('system', { text: `${name} 加入房间` });
    ack({ ok: true });
  });

  socket.on('chat', (input, reply) => {
    const ack = typeof reply === 'function' ? reply : () => {};
    const member = members.get(socket.id);

    if (!member) return ack({ ok: false, message: '请先加入房间' });
    if (typeof input?.text !== 'string') {
      return ack({ ok: false, message: '消息内容不合法' });
    }

    const text = input.text.trim();
    if (!text || text.length > 500) {
      return ack({ ok: false, message: '消息内容不合法' });
    }

    io.to(member.room).emit('chat', {
      sender: member.name,
      text,
    });
    ack({ ok: true });
  });

  socket.on('disconnect', () => {
    const member = members.get(socket.id);
    members.delete(socket.id);

    if (member) {
      io.to(member.room).emit('system', {
        text: `${member.name} 离开房间`,
      });
    }
  });
});

httpServer.listen(3000);
```

广播范围容易写错：

| 调用 | 接收者 |
| --- | --- |
| `socket.emit()` | 当前连接 |
| `socket.broadcast.emit()` | 除当前连接外的所有连接 |
| `socket.to(room).emit()` | 房间内除当前连接外的成员 |
| `io.to(room).emit()` | 房间内所有成员 |

内存里的 `Map` 只适合单进程。多实例部署后，不同进程看不到彼此的成员和事件，需要 Redis Adapter 这类跨实例的通道。身份也不能只信客户端发来的 `name`，正式系统要在握手阶段校验 token，再把服务端确认过的用户放进 `socket.data`。

Socket.IO 有自己的握手、事件和回退协议，跟原生 WebSocket 不是一回事。客户端和服务端要用兼容的版本，拿一个裸的 WebSocket 客户端是连不上 Socket.IO 服务的。

## Puppeteer 抓动态页面

动态页面的内容往往要等脚本执行完、接口返回后才出现。固定的 `setTimeout` 又慢又不靠谱，要等具体的 DOM 条件，并保证浏览器最后一定关掉：

```js
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch({ headless: true });

try {
  const page = await browser.newPage();
  page.setDefaultTimeout(10_000);

  await page.goto('https://example.com', {
    waitUntil: 'domcontentloaded',
    timeout: 20_000,
  });

  await page.waitForSelector('.entry-list a.title');

  const titles = await page.$$eval('.entry-list a.title', (nodes) =>
    nodes
      .map((node) => node.textContent?.trim())
      .filter((value) => value),
  );

  console.log(titles);
} finally {
  await browser.close();
}
```

选择器是最脆弱的依赖。页面改版、登录弹窗、地区限制和反自动化策略都可能让它失效；失败日志里至少要有 URL、选择器和截图路径。抓取之前还要确认站点条款、`robots.txt`、隐私和访问频率，不能绕过权限。

大量文本不适合塞进命令行参数。Node.js 调 Python 生成词云时，用 stdin 传结构化输入，并检查退出码：

```js
import { spawn } from 'node:child_process';

function createWordCloud(titles) {
  return new Promise((resolve, reject) => {
    const child = spawn('python', ['./word-cloud.py'], {
      stdio: ['pipe', 'ignore', 'pipe'],
    });

    let stderr = '';
    child.stderr.setEncoding('utf8');
    child.stderr.on('data', (chunk) => {
      stderr += chunk;
    });

    child.on('error', reject);
    child.on('close', (code) => {
      if (code === 0) resolve();
      else reject(new Error(`python exited with ${code}: ${stderr}`));
    });

    child.stdin.end(JSON.stringify({ titles }));
  });
}
```

子进程的 stdout、stderr 和退出码是三个不同的信号。只打印 stderr 却不 reject Promise，调用方会以为任务成功了。中文词云还必须指定一个带中文字形的字体文件。

## 分片上传的身份和顺序

大文件分片不只是"切小"，还要能失败重传、校验完整性，并且不把整个文件装进内存。

浏览器用 `Blob.slice` 切片：

```js
function createChunks(file, chunkSize = 4 * 1024 * 1024) {
  const chunks = [];

  for (let start = 0; start < file.size; start += chunkSize) {
    chunks.push(file.slice(start, start + chunkSize));
  }

  return chunks;
}
```

每个分片至少要带上服务端生成的 `uploadId`、数字索引、总分片数和哈希。别直接拿用户的文件名拼临时路径：

```js
import fs from 'node:fs';
import fsp from 'node:fs/promises';
import path from 'node:path';
import { Readable } from 'node:stream';
import { pipeline } from 'node:stream/promises';

const uploadRoot = path.resolve('uploads');
const fileRoot = path.resolve('files');

app.post('/merge', async (req, res, next) => {
  try {
    const uploadId = req.body?.uploadId;
    const total = req.body?.total;

    if (
      typeof uploadId !== 'string'
      || !/^[a-f0-9-]{36}$/i.test(uploadId)
    ) {
      return res.status(400).json({ message: '上传 ID 不合法' });
    }

    if (
      typeof total !== 'number'
      || !Number.isInteger(total)
      || total <= 0
      || total > 10_000
    ) {
      return res.status(400).json({ message: '分片数量不合法' });
    }

    const chunkDir = path.join(uploadRoot, uploadId);
    const target = path.join(fileRoot, `${uploadId}.bin`);
    const chunks = await fsp.readdir(chunkDir);
    const indexes = chunks
      .map(Number)
      .filter(Number.isInteger)
      .sort((a, b) => a - b);

    if (
      indexes.length !== total ||
      indexes.some((value, index) => value !== index)
    ) {
      return res.status(409).json({ message: '分片不完整' });
    }

    await fsp.mkdir(fileRoot, { recursive: true });
    const output = fs.createWriteStream(target, { flags: 'wx' });
    const input = Readable.from((async function* readChunks() {
      for (const index of indexes) {
        yield* fs.createReadStream(path.join(chunkDir, String(index)));
      }
    })());

    await pipeline(input, output);

    await fsp.rm(chunkDir, { recursive: true });
    res.status(201).json({ uploadId });
  } catch (error) {
    next(error);
  }
});
```

字符串排序会把 `10` 排在 `2` 前面，合并之前一定要转成数字。`flags: 'wx'` 防止悄悄覆盖已有的目标文件。正式实现还要验证每一片和整个文件的哈希、限制并发数、记录已完成的索引，并清理长期没完成的上传。

这里容易炸在"合并失败后留下的半成品"。更稳的做法是先写到临时目标，校验完整文件的哈希后再原子重命名；失败了就删掉临时文件，保留能重试的分片。

## 下载必须流式返回

```js
import { pipeline } from 'node:stream/promises';

app.get('/files/:id', async (req, res, next) => {
  try {
    if (!/^[a-f0-9-]{36}$/i.test(req.params.id)) {
      return res.status(400).end();
    }

    const filePath = path.join(fileRoot, `${req.params.id}.bin`);
    const stat = await fsp.stat(filePath);

    res.setHeader('Content-Type', 'application/octet-stream');
    res.setHeader('Content-Length', String(stat.size));
    res.setHeader(
      'Content-Disposition',
      'attachment; filename="download.bin"',
    );

    await pipeline(fs.createReadStream(filePath), res);
  } catch (error) {
    if (error?.code === 'ENOENT') return res.status(404).end();
    next(error);
  }
});
```

用流的话，背压会从 HTTP 响应一路传回文件读取端，不用一次把整个文件加载进来。响应头发出去之后再出错，一般已经没法改成 JSON 错误了；这时要记录失败并终止连接。

合并接口返回 `{ uploadId }`。客户端用这个值请求对应的文件，再创建临时 URL：

```js
async function mergeAndDownload(uploadId, total) {
  const uploadResponse = await fetch('/merge', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ uploadId, total }),
  });
  if (!uploadResponse.ok) {
    throw new Error(`merge failed: ${uploadResponse.status}`);
  }

  const uploadResult = await uploadResponse.json();
  if (typeof uploadResult.uploadId !== 'string') {
    throw new Error('merge response has no uploadId');
  }

  const response = await fetch(
    `/files/${encodeURIComponent(uploadResult.uploadId)}`,
  );
  if (!response.ok) {
    throw new Error(`download failed: ${response.status}`);
  }

  const blob = await response.blob();
  const url = URL.createObjectURL(blob);
  const anchor = document.createElement('a');

  anchor.href = url;
  anchor.download = 'download.bin';
  anchor.click();
  URL.revokeObjectURL(url);
}
```

## HTTP 缓存语义

强缓存命中时不访问服务器，协商缓存会带上校验条件去问服务器：

| 策略 | 客户端行为 |
| --- | --- |
| `Cache-Control: public, max-age=60` | 60 秒内直接复用 |
| `Cache-Control: no-cache` | 可以存，但每次使用前验证 |
| `Cache-Control: no-store` | 不存储副本 |

`no-cache` 的意思不是"不缓存"。想要内容一变就立刻生效、没变时又能省掉响应体，可以用 ETag：

```js
import crypto from 'node:crypto';

app.get('/api/config', (req, res) => {
  const body = JSON.stringify({ theme: 'light' });
  const etag = `"${crypto.createHash('sha1').update(body).digest('hex')}"`;

  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('ETag', etag);

  if (req.headers['if-none-match'] === etag) {
    return res.status(304).end();
  }

  res.type('json').send(body);
});
```

`Last-Modified` 和 `If-Modified-Since` 用的是修改时间，粒度和时钟都可能导致误判；ETag 直接绑定内容或版本，一般更精确。带用户隐私的响应别标 `public`，鉴权响应能不能缓存也要单独想清楚。

## HTTP/2 的变化

HTTP/2 在一条连接上并发多个流，用二进制帧，并压缩重复的头部。`:method`、`:path`、`:status` 是伪首部。二进制帧不等于加密，保密性来自 TLS。

```js
import fs from 'node:fs';
import http2 from 'node:http2';

const server = http2.createSecureServer({
  key: fs.readFileSync('./localhost-key.pem'),
  cert: fs.readFileSync('./localhost-cert.pem'),
});

server.on('stream', (stream, headers) => {
  const method = headers[':method'];
  const requestPath = headers[':path'];

  stream.on('error', (error) => {
    console.error('h2 stream error', error);
  });

  stream.respond({
    ':status': 200,
    'content-type': 'application/json; charset=utf-8',
  });
  stream.end(JSON.stringify({ method, path: requestPath }));
});

server.on('sessionError', (error) => {
  console.error('h2 session error', error);
});

server.listen(9999);
```

本地的自签名证书只能用于开发。生产环境需要受信任的证书、正确的域名和 TLS 配置。多路复用减少了 HTTP/1.1 多连接带来的限制，但所有的流还是共用底层的 TCP 连接，丢包时照样可能互相影响。

## 短链接不是字符串截断

短链接服务存的是"短码 -> 原 URL"的映射，访问短码时返回重定向。表结构先保证短码唯一：

```sql
CREATE TABLE short_links (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  code VARCHAR(32) NOT NULL,
  target_url TEXT NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_short_links_code (code)
);
```

```js
import crypto from 'node:crypto';

const publicBase = process.env.PUBLIC_BASE_URL;
if (!publicBase) throw new Error('PUBLIC_BASE_URL is required');

const publicBaseUrl = new URL(publicBase);
if (!['http:', 'https:'].includes(publicBaseUrl.protocol)) {
  throw new Error('PUBLIC_BASE_URL must use http or https');
}

function parseTargetUrl(input) {
  const url = new URL(String(input));
  if (!['http:', 'https:'].includes(url.protocol)) {
    throw new Error('unsupported protocol');
  }
  return url.toString();
}

app.post('/short-links', async (req, res, next) => {
  try {
    const targetUrl = parseTargetUrl(req.body.url);

    for (let attempt = 0; attempt < 3; attempt += 1) {
      const code = crypto.randomBytes(6).toString('base64url');

      try {
        await db('short_links').insert({
          code,
          target_url: targetUrl,
        });

        return res.status(201).json({
          shortUrl: new URL(`/${code}`, publicBaseUrl).toString(),
        });
      } catch (error) {
        if (error.code !== 'ER_DUP_ENTRY') throw error;
      }
    }

    throw new Error('无法生成唯一短码');
  } catch (error) {
    next(error);
  }
});

app.get('/:code', async (req, res, next) => {
  try {
    const row = await db('short_links')
      .select('target_url', 'expires_at')
      .where({ code: req.params.code })
      .first();

    if (!row) return res.status(404).send('短链接不存在');
    if (row.expires_at && new Date(row.expires_at) <= new Date()) {
      return res.status(410).send('短链接已过期');
    }

    res.redirect(302, row.target_url);
  } catch (error) {
    next(error);
  }
});
```

随机短码还是可能冲突，最终由唯一索引说了算，应用收到冲突后重试。短链接的域名要来自受信任的 `PUBLIC_BASE_URL`，不能用客户端能影响的 `Host` 请求头。只允许 HTTP 和 HTTPS，能挡住 `javascript:` 这类危险协议；公开服务还要处理钓鱼链接、恶意域名、访问统计和滥用治理。

## 串口也是字节流

串口用来连打印机、扫描仪、传感器、电子秤或单片机。先枚举设备，别以为 `COM3` 永远不变：

```js
import { SerialPort } from 'serialport';

console.table(await SerialPort.list());

const port = new SerialPort({
  path: process.env.SERIAL_PATH ?? 'COM3',
  baudRate: Number(process.env.SERIAL_BAUD_RATE ?? 9600),
  autoOpen: false,
});

port.on('data', (buffer) => {
  console.log('device bytes:', buffer);
});

port.on('error', (error) => {
  console.error('serial error', error);
});

port.open((error) => {
  if (error) {
    console.error('open failed', error);
    return;
  }

  port.write('1', (writeError) => {
    if (writeError) console.error('write failed', writeError);
  });
});
```

`path` 只标识设备端口，`baudRate`、数据位、停止位和校验位还要和硬件一致。端口打开成功也不代表协议对了，双方还要约定编码、分隔符、校验和、命令响应和超时。

设备拔出、被别的进程占用、驱动异常、半包，都是正常的故障路径。串口连接要由一个模块独占，向业务层暴露"读重量""开灯"这样的命令，别让每个 HTTP 路由都直接去 `port.write`。这样重连、排队和协议解析才有唯一的负责人。

从 TCP、文件流到串口，Node.js 面对的都是有生命周期、有背压的资源。先定好边界，再说清楚谁创建、谁关闭、失败了怎么恢复，代码才不会只在顺利的路径上能跑。
