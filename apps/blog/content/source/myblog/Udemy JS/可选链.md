## 一、可选链的引入背景与核心问题（对应视频 00:00-03:15）

### 1.1 传统属性访问的痛点

访问嵌套对象的属性时，中间哪一层不存在（值是 `undefined` 或 `null`），直接访问就会报类型错误。

- 示例场景：拿餐厅（restaurant）周一的营业时间。周一对应的键是 `mon`，营业时间对应的键是 `open`，对象结构如下：

  ```javascript
  const restaurant = {
    openingHours: {
      thu: { open: 12, close: 22 },
      fri: { open: 11, close: 23 },
      sat: { open: 0, close: 24 }, // 0表示24小时营业
    },
  };
  ```

- 问题代码：直接访问 `restaurant.openingHours.mon.open`。对象里的 `openingHours` 没有 `mon` 这个属性，所以 `restaurant.openingHours.mon` 的结果是 `undefined`，再往下读 `open` 就报错：

  ```
  Uncaught TypeError: Cannot read properties of undefined (reading 'open')
  ```

### 1.2 传统解决方案的局限性

想不报错，就得手动一层层检查属性在不在，代码啰嗦又难读，嵌套越深越明显。

- 传统写法：

  ```javascript
  // 需先检查openingHours存在，再检查mon存在
  if (restaurant.openingHours && restaurant.openingHours.mon) {
    console.log(restaurant.openingHours.mon.open);
  } else {
    console.log("Closed");
  }
  ```

- 缺点：嵌套再多几层（比如 `restaurant.location.address.city`），条件判断就得一直往上叠，代码很臃肿。

## 二、可选链的基本概念与语法（对应视频 03:16-06:25）

### 2.1 定义与语法

- 定义：可选链（`?.`）是 ES2020 引入的特性，用来安全地访问嵌套对象 / 数组的属性或方法。`?.` 左边的值是 `null` 或 `undefined`（"空值"）时，直接返回 `undefined`，不再往后访问，也就不会报错。

- 语法规则：
  - 访问对象属性：`obj?.prop`（等价于 `obj && obj.prop`，但更简洁）
  - 访问嵌套属性：`obj?.prop1?.prop2`（支持多层嵌套，任何一层为空就返回 `undefined`）
  - 动态属性访问：`obj?.[dynamicProp]`（配合方括号写法，属性名可以是变量）

### 2.2 基础使用示例

还是 1.1 里的 `restaurant` 对象，用可选链改写属性访问：

```javascript
// 1. 访问单层可选属性：检查openingHours是否存在，再访问mon
const monOpen = restaurant.openingHours?.mon?.open;
console.log(monOpen); // undefined（无报错）

// 2. 访问存在的属性：fri存在，正常返回11
const friOpen = restaurant.openingHours?.fri?.open;
console.log(friOpen); // 11

// 3. 处理空值：用空值合并运算符（??）设置默认值（仅空值触发）
const monStatus = restaurant.openingHours?.mon?.open ?? "Closed";
console.log(monStatus); // Closed（因monOpen为undefined）
```

### 2.3 关键注意点

- 可选链只判断"空值"（`null`/`undefined`），对 `0`、`''`、`false` 这些"假值"不起作用，还是会接着往后访问。
- 示例：`restaurant.openingHours?.sat?.open` 返回 `0`（`0` 是有效值，不是空值），不是 `undefined`。

## 三、可选链在动态场景中的应用（对应视频 06:26-10:59）

### 3.1 动态属性访问（结合数组与变量）

属性名是用变量动态得到的（比如从数组里取）时，要用 `?.[变量]` 的写法，可选链照样能用。

- 示例场景：循环 `weekdays` 数组，拿餐厅每天的营业时间：

  ```javascript
  const weekdays = ["mon", "tue", "wed", "thu", "fri", "sat", "sun"];

  weekdays.forEach((day) => {
    // 动态访问：day为变量，用?.[day]检查属性是否存在
    const open = restaurant.openingHours?.[day]?.open ?? "Closed";
    console.log(`${day}: ${open}`);
  });
  ```

- 输出结果：

  ```plaintext
  mon: Closed
  tue: Closed
  wed: Closed
  thu: 12
  fri: 11
  sat: 0
  sun: Closed
  ```

### 3.2 对比传统写法

不用可选链的话，要手动检查 `openingHours` 和 `[day]` 在不在：

```javascript
weekdays.forEach((day) => {
  let open;
  if (restaurant.openingHours && restaurant.openingHours[day]) {
    open = restaurant.openingHours[day].open;
  } else {
    open = "Closed";
  }
  console.log(`${day}: ${open}`);
});
```

- 结论：可选链把 3 行判断压成了 1 行，更简洁，也更好读。

## 四、可选链与空值合并运算符的配合（对应视频 10:00-11:15）

### 4.1 为何需要搭配使用

- 问题：用 `||` 设默认值的话，会把 `0`、`''` 这些"假值"也当成"空值"。比如 `restaurant.openingHours.sat.open` 是 `0`，用 `||` 会返回默认值 `'Closed'`，跟实际业务对不上。
- 解决：空值合并运算符（`??`）只在左边是 `null`/`undefined` 时才返回右边的默认值，和可选链搭配，默认值就能处理得刚好。

### 4.2 实战示例

```javascript
// 错误写法：用||，sat的open=0会被当作假值，返回'Closed'
const satOpenWrong = restaurant.openingHours?.sat?.open || "Closed";
console.log(satOpenWrong); // Closed（错误，实际应返回0）

// 正确写法：用??，仅当值为null/undefined时返回'Closed'
const satOpenRight = restaurant.openingHours?.sat?.open ?? "Closed";
console.log(satOpenRight); // 0（正确）
```

### 4.3 常见使用场景

- 处理接口数据：接口返回的嵌套字段可能缺失时，用 `obj?.field1?.field2 ?? '默认值'`，代码不报错，显示也合理。
- 取表单值：`input?.value ?? ''`（`input` 元素还没渲染时访问 `value` 不会报错，输入为空时返回空字符串）。

## 五、可选链在方法调用中的应用（对应视频 11:16-13:20）

### 5.1 核心作用

先检查方法在不在再调用，免得调了一个"不是函数"的东西（比如 `undefined`）而报错。

- 语法：`obj?.methodName(参数)`（`obj.methodName` 不存在的话，返回 `undefined`，不执行调用）

### 5.2 示例演示

还是用 `restaurant` 对象，模拟方法存在 / 不存在两种情况：

```javascript
const restaurant = {
  openingHours: {
    /* 同前 */
  },
  // 存在的方法：点单
  order(food1, food2) {
    return `您点了${food1}和${food2}`;
  },
  // 不存在的方法：点烩饭（orderRisotto未定义）
};

// 1. 调用存在的方法：正常执行
const order1 = restaurant.order?.("汉堡", "薯条") ?? "点单失败";
console.log(order1); // 您点了汉堡和薯条

// 2. 调用不存在的方法：返回undefined，再触发默认值
const order2 = restaurant.orderRisotto?.("蘑菇烩饭") ?? "该菜品暂不提供";
console.log(order2); // 该菜品暂不提供

// 3. 若不用可选链：直接调用不存在的方法会报错
// restaurant.orderRisotto('蘑菇烩饭'); // Uncaught TypeError: restaurant.orderRisotto is not a function
```

### 5.3 注意事项

- 可选链只检查"方法存不存在"，不检查"能不能调用"（比如 `obj.method` 是个普通变量而不是函数时，照样会报错）。

- 示例：

  ```javascript
  const restaurant = { order: "这是字符串，不是方法" };
  // restaurant.order?.() 会报错：Uncaught TypeError: restaurant.order is not a function
  ```

## 六、可选链在数组中的应用（对应视频 13:21-16:04）

### 6.1 核心作用

检查数组元素在不在，免得访问越界的索引或空数组的元素时报错。

- 语法：
  - 访问指定索引：`arr?.[index]`（`arr` 是 `null`/`undefined`，或者 `index` 超出数组长度时，返回 `undefined`）
  - 访问嵌套元素：`arr?.[index]?.prop`（数组元素是对象时，安全地访问它的属性）

### 6.2 示例演示

#### 场景 1：数组非空且元素存在

```javascript
const users = [
  { name: "Jonas", email: "jonas@example.com" },
  { name: "Alice", email: "alice@example.com" },
];

// 访问索引0的name：存在，返回Jonas
const userName1 = users?.[0]?.name ?? "用户不存在";
console.log(userName1); // Jonas

// 访问索引1的email：存在，返回alice@example.com
const userEmail1 = users?.[1]?.email ?? "邮箱未设置";
console.log(userEmail1); // alice@example.com
```

#### 场景 2：数组空或索引越界

```javascript
const emptyUsers = []; // 空数组

// 1. 访问空数组的索引0：返回undefined，触发默认值
const userName2 = emptyUsers?.[0]?.name ?? "用户列表为空";
console.log(userName2); // 用户列表为空

// 2. 访问非空数组的越界索引（索引2）：返回undefined，触发默认值
const userName3 = users?.[2]?.name ?? "该用户不存在";
console.log(userName3); // 该用户不存在

// 3. 数组本身为undefined：返回undefined，触发默认值
const undefinedUsers = undefined;
const userName4 = undefinedUsers?.[0]?.name ?? "用户数据未加载";
console.log(userName4); // 用户数据未加载
```

### 6.3 对比传统写法

传统写法要先检查数组存不存在、长度是不是大于索引：

```javascript
const getUserName = (arr, index) => {
  if (arr && arr.length > index) {
    return arr[index].name ?? "邮箱未设置";
  }
  return "用户不存在";
};

console.log(getUserName(users, 0)); // Jonas
console.log(getUserName(emptyUsers, 0)); // 用户不存在
```

- 结论：可选链把这些条件判断简化成了 `arr?.[index]?.name ?? '默认值'`。

## 七、总结与常见误区（对应视频 16:05-16:11）

### 7.1 知识点总结

| 应用场景     | 语法示例                        | 核心作用                               |
| ------------ | ------------------------------- | -------------------------------------- |
| 对象属性访问 | `obj?.prop`/`obj?.prop1?.prop2` | 安全访问嵌套属性，空值返回`undefined`  |
| 动态属性访问 | `obj?.[dynamicProp]`            | 变量作为属性名时，避免属性不存在报错   |
| 方法调用     | `obj?.method(参数)`             | 检查方法存在后调用，避免非函数调用报错 |
| 数组元素访问 | `arr?.[index]`/`arr?.[i]?.prop` | 安全访问数组元素，避免越界或空数组报错 |
| 配合默认值   | `obj?.prop ?? '默认值'`         | 仅空值触发默认值，不影响`0`/`''`等假值 |

### 7.2 常见误区

1. 误区 1：以为可选链能代替所有条件判断
   - 错在：可选链只处理"空值"，要判断"值符不符合业务规则"（比如 `age > 18`），还是得另外写条件。
   - 示例：`const isAdult = user?.age > 18 ?? false`（`user.age` 是 `17` 时返回 `false`，对；`user` 为空时返回 `false`，也对）。
2. 误区 2：可选链用得太多
   - 错在：对确定存在的属性（比如自己定义的本地对象）也用 `?.`，多了没必要的语法开销。
   - 示例：`const name = user.name`（`user` 是本地定义的对象，肯定有 `name` 属性，不用写 `user?.name`）。
3. 误区 3：把 `?.` 和 `&&` 搞混
   - 区别：`&&` 碰到所有"假值"都返回左边（比如 `obj.prop = 0` 时，`obj && obj.prop` 返回 `0`，`obj?.prop` 也返回 `0`，效果一样）；但 `?.` 更简洁，多层嵌套也好写（`obj?.p1?.p2` vs `obj && obj.p1 && obj.p1.p2`）。

### 7.3 最佳实践

- 处理接口数据：后端返回的不确定字段（比如 `res.data?.list?.[0]?.id`），一定用可选链。
- DOM 操作：访问可能还没渲染的元素（比如 `document.querySelector('.modal')?.style.display`），一定用可选链。
- 本地对象：确定存在的属性不用可选链，不确定的属性（比如动态生成的对象）再用。
