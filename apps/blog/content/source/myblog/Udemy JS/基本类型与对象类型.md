## 一、核心问题引入：原始类型与对象的行为差异

### 1.1 原始类型的 “预期行为”（代码示例）

```javascript
// 1. 声明原始类型变量（数字）
let age = 30;
// 2. 复制变量值
let oldAge = age;
// 3. 修改原变量
age = 31;
// 4. 输出结果
console.log(age); // 输出：31（原变量修改后的值）
console.log(oldAge); // 输出：30（复制时的初始值，不受原变量修改影响）
```

结论：原始类型复制以后，改原变量不会影响复制出来的变量，符合直觉。

### 1.2 对象类型的 “意外行为”（代码示例）

```javascript
// 1. 声明对象类型变量
const me = {
  name: "Jonas",
  age: 30,
};
// 2. 复制对象（看似复制，实则引用）
const friend = me;
// 3. 修改复制对象的属性
friend.age = 27;
// 4. 输出结果
console.log(me.age); // 输出：27（原对象属性被修改）
console.log(friend.age); // 输出：27（复制对象的修改同步到原对象）
```

问题：为什么改 `friend` 会影响 `me`？这要从内存存储机制说起。

## 二、基础知识回顾：JS 数据类型分类

### 2.1 原始类型（Primitive Types，又称 “值类型”）

- 一共 7 种：`Number`（数字）、`String`（字符串）、`Boolean`（布尔值）、`Undefined`（未定义）、`Null`（空值）、`Symbol`（唯一标识）、`BigInt`（大整数）。
- 特点：存的是具体的值，占用的内存小而且固定。

### 2.2 引用类型（Reference Types，核心是对象）

- 包括：`Object`（普通对象）、`Array`（数组，其实是特殊的对象）、`Function`（函数，其实是能执行的对象）、`Date`（日期对象）等。
- 特点：存的是复杂的结构，占用的内存大小不固定。

## 三、关键原理：JS 引擎的内存存储机制

### 3.1 内存分区：调用堆栈（Call Stack）与堆（Heap）

| 内存区域 | 存储内容                 | 特点                                 |
| -------- | ------------------------ | ------------------------------------ |
| 调用堆栈 | 原始类型、函数执行上下文 | 速度快，内存大小有限，自动释放       |
| 堆       | 引用类型（对象）         | 速度较慢，内存空间大，手动回收（GC） |

### 3.2 原始类型的内存存储流程（对应 1.1 示例）

1. 声明 `age = 30` 时：
   - 在调用堆栈里分配一块内存（地址比如 `0001`），存值 `30`；
   - 变量 `age` 指向内存地址 `0001`（不是直接指向值 `30`）。

2. 复制 `oldAge = age` 时：
   - `oldAge` 直接指向 `age` 的内存地址 `0001`，和 `age` 共用同一个值。

3. 修改 `age = 31` 时：
   - 原始类型的值是不可变的（没法直接改 `0001` 地址里的值）；
   - 新分配一块内存（地址比如 `0002`），存 `31`；
   - `age` 改为指向 `0002`，`oldAge` 还是指向 `0001`（值 `30`）。

### 3.3 引用类型的内存存储流程（对应 1.2 示例）

1. 声明 `const me = {name: "Jonas", age: 30}` 时：
   - 在堆里分配一块内存（地址比如 `D30F`），存对象的键值对；
   - 在调用堆栈里分配一块内存（地址比如 `0003`），存堆地址 `D30F`；
   - 变量 `me` 指向调用堆栈里的 `0003`（间接指向堆里的对象）。

2. 复制 `const friend = me` 时：
   - `friend` 指向调用堆栈里和 `me` 一样的地址 `0003`；
   - 两个变量通过 `0003` 间接指向堆里的同一个对象（`D30F`），并没有新建对象。

3. 修改 `friend.age = 27` 时：
   - 直接改堆里 `D30F` 地址上对象的属性（`age` 从 `30` 改成 `27`）；
   - `me` 和 `friend` 还是共用同一个堆地址 `D30F`，所以两边读到的 `age` 都是 `27`。

## 四、重要延伸：`const`声明的可变性差异

### 4.1 `const`与原始类型：完全不可变

```javascript
const num = 10;
num = 20; // 报错：Assignment to constant variable（const禁止修改原始类型的引用）
```

原因：`const` 声明的原始类型变量，指向的内存地址不能变，原始类型的值本身也不能变，所以这个变量完全改不了。

### 4.2 `const`与引用类型：引用不可变，属性可变

```javascript
const person = { name: "Alice", age: 25 };
// 1. 修改对象属性：允许
person.age = 26;
console.log(person.age); // 输出：26（属性修改成功）

// 2. 修改引用（指向新对象）：禁止
person = { name: "Bob", age: 30 }; // 报错：Assignment to constant variable
```

原因：`const` 只禁止改"调用堆栈里的引用地址"（比如 `person` 不能从指向 `0003` 改成指向 `0004`），不限制改"堆里对象的属性"。

## 五、实践影响与后续学习提示

### 5.1 常见坑点：“复制对象” 的本质

- 误区：`const newObj = oldObj` 不是"复制对象"，而是"复制引用"，两个变量指向同一个对象。

- 示例（坑）：

  ```javascript
  const user1 = { score: 80 };
  const user2 = user1;
  user2.score = 90;
  console.log(user1.score); // 输出：90（意外修改了原对象）
  ```

### 5.2 后续学习方向

1. 解决"对象深复制"的问题：后面的课会讲 `Object.assign()`、扩展运算符（`...`）、`JSON.parse(JSON.stringify())` 这些深复制方法，避免共享引用带来意外的修改。
2. 相关概念：
   - 原型继承（OOP 章节）：对象的原型链依赖引用类型的内存机制；
   - 事件循环（异步 JS 章节）：堆里对象什么时候被回收，和事件循环有关；
   - DOM 操作（高级 DOM 章节）：DOM 元素本质上是引用类型，改 DOM 属性的原理和改对象一样。

## 六、总结：原始类型与引用类型核心差异表

| 对比维度      | 原始类型（值类型）                | 引用类型（对象）                 |
| ------------- | --------------------------------- | -------------------------------- |
| 存储位置      | 调用堆栈                          | 堆（调用堆栈存引用地址）         |
| 复制行为      | 复制值，修改原变量不影响副本      | 复制引用，修改副本影响原对象     |
| `const`可变性 | 完全不可变（地址和值均不可改）    | 引用不可变，对象属性可改         |
| 典型示例      | `let a = 10`、`const str = "abc"` | `const obj = {}`、`let arr = []` |
