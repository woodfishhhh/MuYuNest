# Gin 基础（05）：单文件与多文件上传

上传文件时，先确认三个限制：整个 HTTP 请求有多大、单个文件有多大、允许多少个文件。内存阈值是另外一件事，它决定解析 multipart 时多少内容留在内存中。

## 单文件和多文件使用同一种格式

`multipart/form-data` 由多个 part 组成。普通字段和文件都放在这些 part 中，文件部分还会携带字段名、文件名等元数据。

只取某个字段的一个文件时，可以调用 `c.FormFile("file")`；要处理重复字段里的多个文件，调用 `c.MultipartForm()`，再读取 `form.File["files"]`。字段名由接口约定，`file`、`files`、`files[]` 是不同的名字，不能随意混用。

下面统一使用 `files`：上传一次就是单文件，重复同一字段就是多文件。接口最多接收 3 个文件，每个不超过 1 MiB，整个请求不超过 4 MiB。`1 << 20` 是 1,048,576 字节。

## 内存阈值不会拒绝所有大文件

`r.MaxMultipartMemory = 256 << 10` 不是“最多上传 256 KiB”。较大的文件内容可能写入临时文件，解析器仍然可以继续接收。限制整个请求，需要在读取之前用 `http.MaxBytesReader` 包住请求体。

文件大小与请求大小也不同：请求还包含 multipart 分隔符、字段头和普通表单字段。不能把请求上限简单设成单文件上限，然后期待同样大小的文件总能上传成功。[Gin 上传大小限制](https://gin-gonic.com/en/docs/routing/upload-file/limit-bytes/)

## 可以直接运行的上传接口

使用 Go 1.25 或更高版本，新建独立目录。以下命令按 PowerShell 7 编写；Linux/macOS 请求示例中的 `curl.exe` 可换成 `curl`。

```powershell
mkdir gin-05-upload
Set-Location gin-05-upload
go mod init example.com/gin-05-upload
go get github.com/gin-gonic/gin@v1.12.0
```

每个示例单独运行，避免多个 `main` 函数放进同一个包。

保存为 `main.go`：

```go
package main

import (
	"errors"
	"io"
	"log"
	"net/http"
	"os"
	"path/filepath"

	"github.com/gin-gonic/gin"
)

const (
	maxRequestBytes = 4 << 20
	maxFileBytes    = 1 << 20
)

func NewRouter(uploadDir string) *gin.Engine {
	r := gin.New()
	r.Use(gin.Recovery())
	if err := r.SetTrustedProxies(nil); err != nil {
		panic(err)
	}
	// 这是内存阈值，超过后可以落到临时文件，并不是上传大小上限。
	r.MaxMultipartMemory = 256 << 10
	r.POST("/uploads", func(c *gin.Context) {
		if c.ContentType() != gin.MIMEMultipartPOSTForm {
			c.JSON(http.StatusUnsupportedMediaType, gin.H{"error": "请提交 multipart/form-data"})
			return
		}
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, maxRequestBytes)
		form, err := c.MultipartForm()
		if err != nil {
			status := http.StatusBadRequest
			var tooLarge *http.MaxBytesError
			if errors.As(err, &tooLarge) {
				status = http.StatusRequestEntityTooLarge
			}
			c.JSON(status, gin.H{"error": "上传表单无效或请求超过 4 MiB"})
			return
		}
		defer form.RemoveAll()
		files := form.File["files"]
		if len(files) == 0 || len(files) > 3 {
			c.JSON(http.StatusBadRequest, gin.H{"error": "files 字段需要 1 到 3 个文件"})
			return
		}
		for _, file := range files {
			if file.Size > maxFileBytes {
				c.JSON(http.StatusRequestEntityTooLarge, gin.H{"error": "单个文件不能超过 1 MiB"})
				return
			}
		}
		if err := os.MkdirAll(uploadDir, 0700); err != nil {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "存储目录不可用"})
			return
		}
		var paths []string
		var saved []gin.H
		committed := false
		defer func() {
			if !committed {
				for _, name := range paths {
					_ = os.Remove(name)
				}
			}
		}()
		for _, header := range files {
			src, err := header.Open()
			if err != nil {
				c.JSON(http.StatusInternalServerError, gin.H{"error": "打开上传内容失败"})
				return
			}
			// 不把 header.Filename 拼进磁盘路径。文件名由服务器生成。
			dst, err := os.CreateTemp(uploadDir, "upload-*.bin")
			if err != nil {
				_ = src.Close()
				c.JSON(http.StatusInternalServerError, gin.H{"error": "创建文件失败"})
				return
			}
			paths = append(paths, dst.Name())
			written, copyErr := io.Copy(dst, io.LimitReader(src, maxFileBytes+1))
			sourceCloseErr := src.Close()
			destinationCloseErr := dst.Close()
			if copyErr != nil || sourceCloseErr != nil || destinationCloseErr != nil || written > maxFileBytes {
				c.JSON(http.StatusInternalServerError, gin.H{"error": "保存文件失败"})
				return
			}
			saved = append(saved, gin.H{"id": filepath.Base(dst.Name()), "bytes": written})
		}
		committed = true
		c.JSON(http.StatusCreated, gin.H{"files": saved})
	})
	return r
}

func main() {
	if err := NewRouter(filepath.Join("data", "uploads")).Run("127.0.0.1:8080"); err != nil {
		log.Fatal(err)
	}
}
```

处理顺序是：限制请求体、解析表单、检查数量与单文件大小、创建服务器文件名、复制内容、返回结果。前面的检查通过之后才写正式文件，因此明确超限的请求不会留下半份上传结果。

`FileHeader` 描述已经解析出的文件，包括大小和文件名。`Open` 返回可读取的内容；`io.Copy` 逐段复制，避免再把整个文件读进一个大字节切片。上传内容和目标文件都需要关闭，否则可能留下文件描述符，或在 Windows 上导致后续操作无法打开同一文件。

解析过程使用的临时文件与正式上传文件是两批资源。`form.RemoveAll()` 清理前者；`paths` 和 `committed` 清理本次保存失败时已经创建的正式文件。这里的批次清理能处理普通处理错误，不能替代数据库事务，也不能保证进程突然崩溃时没有遗留文件。

## 文件名由服务器决定

客户端文件名只是输入元数据，不应直接拼进服务器路径。`os.CreateTemp(uploadDir, "upload-*.bin")` 在目标目录内创建一个新文件，避免路径穿越和同名覆盖。响应只返回服务器生成的 ID。

目录 `data/uploads` 没有映射到 `r.Static`，上传成功不代表任何人都能通过 URL 读取它。要做下载功能，可以根据文件 ID、记录和访问权限决定是否返回内容。扩展名、上传方声明的 Content-Type 也不能单独证明文件真实类型；如果业务只接受图片，还需要实际解码校验。[Gin 单文件上传说明](https://gin-gonic.com/en/docs/routing/upload-file/single-file/)

## 单文件、多文件和错误结果

运行 `go run .`，再打开一个终端：

```powershell
'hello' | Set-Content -Encoding utf8NoBOM -NoNewline a.txt
'world' | Set-Content -Encoding utf8NoBOM -NoNewline b.txt
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@a.txt"
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@a.txt" -F "files=@b.txt"
```

成功响应是 `201`，结构如下；文件 ID 每次不同。命令中的 `-NoNewline` 避免自动添加换行，因此 `hello` 恰好是 5 字节：

```json
{"files":[{"id":"upload-随机数字.bin","bytes":5}]}
```

检查拒绝场景：

```powershell
[System.IO.File]::WriteAllBytes((Join-Path $PWD 'too-large.bin'), [byte[]]::new(1048577))
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@too-large.bin"
```

单文件超过 1 MiB 时返回 `413`。没有提交 `files`，或一次提交超过 3 个文件时返回 `400`。一个 512 KiB 的文件虽然超过 256 KiB 内存阈值，但仍小于文件和请求上限，可以成功保存。

`c.SaveUploadedFile` 可以简化复制操作，但并不会替你设计字段数量、总请求限制、文件类型与业务权限。使用它时同样应该传入服务器选择的目标路径。
