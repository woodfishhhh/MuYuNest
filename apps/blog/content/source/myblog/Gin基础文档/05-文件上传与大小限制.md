# Gin 基础（05）：单文件与多文件上传

上传文件先定三个限制：

- 整个 HTTP 请求多大
- 单个文件多大
- 最多允许几个文件

内存阈值是另一回事，它只决定解析 multipart 时多少内容留在内存里。

## 单文件和多文件使用同一种格式

`multipart/form-data` 由多个 part 组成。普通字段和文件都放在 part 里，文件 part 还带着字段名、文件名等元数据。

只取某个字段的一个文件，用 `c.FormFile("file")`；同一个字段重复出现、有多个文件，用 `c.MultipartForm()` 再读 `form.File["files"]`。字段名由接口约定，`file`、`files`、`files[]` 是不同的名字，别混用。

下面统一用 `files`：传一次就是单文件，重复同一字段就是多文件。接口最多收 3 个文件，每个不超过 1 MiB，整个请求不超过 4 MiB。`1 << 20` 是 1,048,576 字节。

## 内存阈值不会拒绝所有大文件

`r.MaxMultipartMemory = 256 << 10` 不是“最多上传 256 KiB”。大一点的文件内容可能写进临时文件，解析器照样继续接收。要限制整个请求，得在读取前用 `http.MaxBytesReader` 包住请求体。

文件大小和请求大小也不一样：请求里还有 multipart 分隔符、字段头和普通表单字段。请求上限别直接设成单文件上限，不然同样大小的文件不一定总能传上去。[Gin 上传大小限制](https://gin-gonic.com/en/docs/routing/upload-file/limit-bytes/)

## 可以直接运行的上传接口

用 Go 1.25 或更高版本，新建一个独立目录。下面的命令按 PowerShell 7 写；Linux/macOS 上把请求示例里的 `curl.exe` 换成 `curl`。

```powershell
mkdir gin-05-upload
Set-Location gin-05-upload
go mod init example.com/gin-05-upload
go get github.com/gin-gonic/gin@v1.12.0
```

每个示例单独运行，别把多个 `main` 函数放进同一个包。

保存为 `main.go`：

```go
package main

import (
	"errors"
	"io"
	"log"
	"net/http"
	"os"
	"path/filepath"

	"github.com/gin-gonic/gin"
)

const (
	maxRequestBytes = 4 << 20
	maxFileBytes    = 1 << 20
)

func NewRouter(uploadDir string) *gin.Engine {
	r := gin.New()
	r.Use(gin.Recovery())
	if err := r.SetTrustedProxies(nil); err != nil {
		panic(err)
	}
	// 这是内存阈值，超过后可以落到临时文件，并不是上传大小上限。
	r.MaxMultipartMemory = 256 << 10
	r.POST("/uploads", func(c *gin.Context) {
		if c.ContentType() != gin.MIMEMultipartPOSTForm {
			c.JSON(http.StatusUnsupportedMediaType, gin.H{"error": "请提交 multipart/form-data"})
			return
		}
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, maxRequestBytes)
		form, err := c.MultipartForm()
		if err != nil {
			status := http.StatusBadRequest
			var tooLarge *http.MaxBytesError
			if errors.As(err, &tooLarge) {
				status = http.StatusRequestEntityTooLarge
			}
			c.JSON(status, gin.H{"error": "上传表单无效或请求超过 4 MiB"})
			return
		}
		defer form.RemoveAll()
		files := form.File["files"]
		if len(files) == 0 || len(files) > 3 {
			c.JSON(http.StatusBadRequest, gin.H{"error": "files 字段需要 1 到 3 个文件"})
			return
		}
		for _, file := range files {
			if file.Size > maxFileBytes {
				c.JSON(http.StatusRequestEntityTooLarge, gin.H{"error": "单个文件不能超过 1 MiB"})
				return
			}
		}
		if err := os.MkdirAll(uploadDir, 0700); err != nil {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "存储目录不可用"})
			return
		}
		var paths []string
		var saved []gin.H
		committed := false
		defer func() {
			if !committed {
				for _, name := range paths {
					_ = os.Remove(name)
				}
			}
		}()
		for _, header := range files {
			src, err := header.Open()
			if err != nil {
				c.JSON(http.StatusInternalServerError, gin.H{"error": "打开上传内容失败"})
				return
			}
			// 不把 header.Filename 拼进磁盘路径。文件名由服务器生成。
			dst, err := os.CreateTemp(uploadDir, "upload-*.bin")
			if err != nil {
				_ = src.Close()
				c.JSON(http.StatusInternalServerError, gin.H{"error": "创建文件失败"})
				return
			}
			paths = append(paths, dst.Name())
			written, copyErr := io.Copy(dst, io.LimitReader(src, maxFileBytes+1))
			sourceCloseErr := src.Close()
			destinationCloseErr := dst.Close()
			if copyErr != nil || sourceCloseErr != nil || destinationCloseErr != nil || written > maxFileBytes {
				c.JSON(http.StatusInternalServerError, gin.H{"error": "保存文件失败"})
				return
			}
			saved = append(saved, gin.H{"id": filepath.Base(dst.Name()), "bytes": written})
		}
		committed = true
		c.JSON(http.StatusCreated, gin.H{"files": saved})
	})
	return r
}

func main() {
	if err := NewRouter(filepath.Join("data", "uploads")).Run("127.0.0.1:8080"); err != nil {
		log.Fatal(err)
	}
}
```

处理顺序：

1. 限制请求体
2. 解析表单
3. 检查数量和单文件大小
4. 创建服务器文件名
5. 复制内容
6. 返回结果

前面的检查都通过了才写正式文件，所以明确超限的请求不会留下半份上传结果。

`FileHeader` 描述已经解析出的文件，包括大小和文件名。`Open` 返回可读的内容；`io.Copy` 逐段复制，不用把整个文件读进一个大字节切片。上传内容和目标文件都要关闭，不然可能留下文件描述符，在 Windows 上还可能导致后续操作打不开同一个文件。

解析用的临时文件和正式上传文件是两批资源：

- `form.RemoveAll()` 清理临时文件。
- `paths` 和 `committed` 清理本次保存失败时已经创建的正式文件。

这种批次清理能处理普通的处理错误，但替代不了数据库事务，也不能保证进程突然崩溃时没有遗留文件。

## 文件名由服务器决定

客户端文件名只是输入的元数据，别直接拼进服务器路径。`os.CreateTemp(uploadDir, "upload-*.bin")` 在目标目录里新建一个文件，避免路径穿越和同名覆盖。响应只返回服务器生成的 ID。

目录 `data/uploads` 没有映射到 `r.Static`，上传成功不等于谁都能通过 URL 读到它。要做下载功能，可以按文件 ID、记录和访问权限决定是否返回内容。扩展名、上传方声明的 Content-Type 都不能单独证明文件的真实类型；业务只收图片的话，还要实际解码校验。[Gin 单文件上传说明](https://gin-gonic.com/en/docs/routing/upload-file/single-file/)

## 单文件、多文件和错误结果

运行 `go run .`，另开一个终端：

```powershell
'hello' | Set-Content -Encoding utf8NoBOM -NoNewline a.txt
'world' | Set-Content -Encoding utf8NoBOM -NoNewline b.txt
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@a.txt"
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@a.txt" -F "files=@b.txt"
```

成功响应是 `201`，结构如下，文件 ID 每次不同。命令里的 `-NoNewline` 防止自动加换行，所以 `hello` 正好 5 字节：

```json
{"files":[{"id":"upload-随机数字.bin","bytes":5}]}
```

检查拒绝场景：

```powershell
[System.IO.File]::WriteAllBytes((Join-Path $PWD 'too-large.bin'), [byte[]]::new(1048577))
curl.exe -i "http://127.0.0.1:8080/uploads" -F "files=@too-large.bin"
```

- 单文件超过 1 MiB：返回 `413`。
- 没提交 `files`，或一次超过 3 个文件：返回 `400`。
- 512 KiB 的文件：超过了 256 KiB 内存阈值，但小于文件和请求上限，可以成功保存。

`c.SaveUploadedFile` 能简化复制操作，但字段数量、总请求限制、文件类型和业务权限它都不会替你设计。用它时同样要传入服务器选定的目标路径。
