# Gin 基础（08）：路由分组、中间件与服务退出

认证、日志、耗时统计通常要作用在一组接口上。中间件把这些公共处理放进请求链，路由分组决定这条链覆盖哪些路径。搞清执行顺序，才知道失败后哪些代码还会运行。

## 路由由方法和资源路径共同决定

| 请求 | 常见含义 |
| --- | --- |
| `GET /api/users` | 读取用户列表 |
| `POST /api/users` | 创建用户 |
| `GET /api/users/:id` | 读取一个用户 |
| `PUT /api/users/:id` | 按约定替换资源状态 |
| `PATCH /api/users/:id` | 修改部分内容 |
| `DELETE /api/users/:id` | 删除用户 |

复数资源名只是常见的命名习惯。设计接口还要定方法语义、状态码和错误契约。RESTful 不只是“URL 换个名字”，也不用把所有业务硬套成同一种操作。

幂等：同样的请求重复执行，最终资源状态和执行一次一样。DELETE 第一次返回 `204`、第二次返回 `404`，删除操作照样是幂等的，幂等不要求每次响应都相同。PATCH 是否幂等看具体修改规则。

## Next、Abort、return 各自改变什么

`c.Next()` 先执行后面的处理器，等它们返回，再接着执行当前函数里 `Next` 之后的代码。多个中间件这样嵌套，结果就是“前置代码正序、后置代码逆序”。

![中间件前置与后置代码的执行顺序](./assets/middleware-chain.svg)

`c.Abort()` 阻止剩下的处理器执行，但不会让当前 Go 函数立即返回：它后面的普通语句照样运行，外层中间件已经进入的后置代码也会继续执行。

`return` 只结束当前函数。中间件里只写 `return`，Gin 还是会调用剩下的处理器。所以拒绝请求一般是：写错误响应、调 Abort、再 return：

```go
c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "凭证无效"})
return
```

`AbortWithStatusJSON` 把中止处理链和 JSON 响应合在一起了，但还是要后面的 `return` 才能结束当前函数。[Gin Context.Abort](https://pkg.go.dev/github.com/gin-gonic/gin@v1.12.0#Context.Abort)

## 全局、分组和单条路由的中间件

- `r.Use(...)`：作用于之后注册在这个引擎链上的路由。
- `group.Use(...)` 或 `r.Group("/api", ...)`：限定到分组。
- `r.GET("/path", middleware, handler)`：给单条路由配置链。

注册路由时，Gin 就把当时的处理器链组合好了。先注册路由、之后再加 `Use`，旧路由不会跟着变。公共中间件放在路由定义之前，创建分组也按这个顺序。

## 一个包含认证、日志和正常退出的服务

用 Go 1.25 或更高版本，新建一个独立目录。下面的命令按 PowerShell 7 写；Linux/macOS 上把请求示例里的 `curl.exe` 换成 `curl`。

```powershell
mkdir gin-08-middleware
Set-Location gin-08-middleware
go mod init example.com/gin-08-middleware
go get github.com/gin-gonic/gin@v1.12.0
```

每个示例单独运行，别把多个 `main` 函数放进同一个包。

保存为 `main.go`：

```go
package main

import (
	"context"
	"crypto/subtle"
	"errors"
	"fmt"
	"io"
	"log"
	"net/http"
	"os"
	"os/signal"
	"strings"
	"syscall"
	"time"

	"github.com/gin-gonic/gin"
)

func Trace(name string, output io.Writer) gin.HandlerFunc {
	logger := log.New(output, "", 0)
	return func(c *gin.Context) {
		logger.Printf("%s.before", name)
		c.Next()
		logger.Printf("%s.after status=%d", name, c.Writer.Status())
	}
}

func Auth(token string) gin.HandlerFunc {
	return func(c *gin.Context) {
		want := "Bearer " + token
		if subtle.ConstantTimeCompare([]byte(c.GetHeader("Authorization")), []byte(want)) != 1 {
			c.Header("WWW-Authenticate", `Bearer realm="gin-basics"`)
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "凭证缺失或无效"})
			return
		}
		// 固定身份只用于演示认证结果如何传给后续处理器。
		c.Set("user_id", "demo-user")
		c.Next()
	}
}

func NewRouter(token string, output io.Writer) (*gin.Engine, error) {
	if strings.TrimSpace(token) == "" {
		return nil, fmt.Errorf("DEMO_API_TOKEN must not be empty")
	}
	r := gin.New()
	r.Use(gin.Recovery(), Trace("global", output))
	if err := r.SetTrustedProxies(nil); err != nil {
		return nil, err
	}
	r.HandleMethodNotAllowed = true
	r.NoMethod(func(c *gin.Context) {
		c.JSON(http.StatusMethodNotAllowed, gin.H{"error": "请求方法不支持"})
	})
	r.GET("/healthz", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"status": "ok"})
	})
	api := r.Group("/api", Trace("group", output), Auth(token))
	api.GET("/me", func(c *gin.Context) {
		userID, exists := c.Get("user_id")
		if !exists {
			c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "身份上下文缺失"})
			return
		}
		log.New(output, "", 0).Print("handler")
		c.JSON(http.StatusOK, gin.H{"user_id": userID, "client_ip": c.ClientIP()})
	})
	return r, nil
}

func main() {
	router, err := NewRouter(os.Getenv("DEMO_API_TOKEN"), os.Stdout)
	if err != nil {
		log.Fatal(err)
	}
	server := &http.Server{
		Addr: "127.0.0.1:8080", Handler: router,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      15 * time.Second,
		IdleTimeout:       60 * time.Second,
	}
	stop, cancel := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer cancel()
	serveErr := make(chan error, 1)
	go func() { serveErr <- server.ListenAndServe() }()
	select {
	case err := <-serveErr:
		if !errors.Is(err, http.ErrServerClosed) {
			log.Fatal(err)
		}
		return
	case <-stop.Done():
	}
	ctx, finish := context.WithTimeout(context.Background(), 5*time.Second)
	defer finish()
	if err := server.Shutdown(ctx); err != nil {
		log.Printf("graceful shutdown: %v", err)
		_ = server.Close()
	}
	if err := <-serveErr; !errors.Is(err, http.ErrServerClosed) {
		log.Printf("server exit: %v", err)
	}
}
```

`NewRouter` 的 `output` 是日志写入位置：`main` 传终端输出，测试传内存缓冲区。`Trace` 记录前后顺序和最终状态码，不把请求头里的令牌写进日志。

`Auth` 用 `c.Set("user_id", ...)` 把认证结果放进当前请求的 Gin Context，后面的处理器用 `c.Get` 读取。这只是本次请求的临时数据，不是进程级的用户缓存，下一次请求也不会自动带上。

示例令牌从环境变量读取，只演示认证中间件放在哪、怎么拒绝请求；成功时用固定的 `demo-user`。真实的身份系统还要验证实际凭证、查询对应身份。跨网络传凭证要用 HTTPS，本例绑定 `127.0.0.1`，只供本机练习。

## 按日志核对执行顺序

先在 PowerShell 7 里设置演示令牌：

```powershell
$env:DEMO_API_TOKEN = 'local-demo-token'
go run .
```

另开一个终端：

```powershell
curl.exe -i "http://127.0.0.1:8080/api/me"
curl.exe -i "http://127.0.0.1:8080/api/me" -H "Authorization: Bearer local-demo-token"
```

第一条得到 `401`。第二条得到 `200`，包含 `user_id: "demo-user"`。成功请求的终端日志顺序：

```text
global.before
group.before
handler
group.after status=200
global.after status=200
```

认证失败时没有 `handler`，但 `group.after status=401` 和 `global.after status=401` 都还在。所以日志和耗时中间件在请求被拒绝后还能继续记录结果。

## Context、代理和服务退出的边界

Gin 会复用 `*gin.Context`。别把它存进全局变量，请求结束后也别再用它写响应。要把取消信号传给数据库或另一个 HTTP 请求，一般传 `c.Request.Context()`。`c.Copy()` 可以用在生命周期明确的只读访问上，但原请求的 ResponseWriter 不会因此变成能长期使用的对象。

这里关掉了可信代理，客户端随便发 `X-Forwarded-For` 也改变不了 `c.ClientIP()` 的结果。部署在自己的反向代理后面时，要配置实际的可信代理地址或网段，再让代理生成或重写转发头。[可信代理配置](https://gin-gonic.com/en/docs/server-config/trusted-proxies/)

`http.Server` 的超时用来限制各个阶段的等待。示例的 15 秒读写超时是给本地小请求用的；长时间上传、下载或流式响应要按实际协议调整，别机械照搬。

收到 Ctrl+C 或终止信号后，`Shutdown` 先停止接收新连接，再给已有请求时间完成。`main` 会等这个过程结束，免得监听函数刚返回整个进程就退出了。超过 5 秒还没结束，示例才调用 `Close`。WebSocket 这类已经被劫持的连接，还要由应用单独管理。[正常关闭服务](https://gin-gonic.com/en/docs/server-config/graceful-restart-or-stop/)
