# Gin 基础（07）：校验规则、中文错误与自定义校验

做参数校验先想清楚两件事：哪些值合法；失败了前端怎么定位到对应字段。只返回一大段 `err.Error()`，前端很难找到对应的输入框，响应文案也跟服务端内部类型名绑死了。

## required 判断的是值，不是原始 JSON 是否出现过这个键

普通 `int` 的零值是 `0`，普通 `bool` 的零值是 `false`。直接加 `required`，这两个零值也会被判不通过。`0` 或 `false` 是合法业务值的话，用指针表示“有没有传值”，再单独检查内容。

空字符串和只有空格的字符串也不一样，`required` 不会帮你调 `strings.TrimSpace`。集合还要考虑空集合和 `nil`：至少要一个元素，就明确写 `min=1`。

| 规则 | 检查内容 | 使用时要明确的边界 |
| --- | --- | --- |
| `min`、`max`、`len` | 长度或大小 | 字符串、集合与数字的解释不同 |
| `gt`、`gte`、`lt`、`lte` | 大小关系 | 例如年龄范围 `gte=0,lte=150` |
| `eqfield=Password` | 与另一个字段比较 | 指向 Go 字段名，不是 JSON 键 |
| `oneof=reader editor` | 枚举取值 | 可用于角色、状态等有限集合 |
| `omitempty` | 空值时跳过后续规则 | 不应拿来替代必填检查 |
| `dive` | 进入集合中的元素 | 例如 `min=1,dive,email` |
| `email`、`ip`、`url` | 格式 | 格式正确不表示邮箱、主机或网页真实可达 |
| `datetime=2006-01-02` | 日期格式与有效日期 | Go 使用参考日期布局，不是 `YYYY-MM-DD` |

字符串用 `contains`、`excludes`、`startswith`、`endswith` 做包含和前后缀约束。多个规则用逗号隔开。要用到业务数据的规则，比如“用户名还没被别人占用”，一般还得查服务或数据库，光靠格式标签判断不了。

这些标签来自 `go-playground/validator`，Gin 用 `binding` 标签驱动它。[validator 规则文档](https://pkg.go.dev/github.com/go-playground/validator/v10@v10.30.1)

## 把错误分成格式错误和字段错误

`{"age":"abc"}` 解码不成整数，首先是 JSON 字段类型错误。`{"age":-1}` 能解码成整数，但可能违反年龄下限。只有后面这类校验失败才能按 `validator.ValidationErrors` 遍历。

返回给前端的结构可以这样：

```json
{"errors":{"name":["用户名为必填字段"]}}
```

`name` 是稳定的 JSON 字段键，中文只负责展示文案。别先拼成 `name---用户名` 再去拆翻译后的字符串，翻译格式或分隔符一变，定位字段的代码就跟着失效。

## 完整示例：中文字段名、自定义规则和错误映射

用 Go 1.25 或更高版本，新建一个独立目录。下面的命令按 PowerShell 7 写；Linux/macOS 上把请求示例里的 `curl.exe` 换成 `curl`。

```powershell
mkdir gin-07-validation
Set-Location gin-07-validation
go mod init example.com/gin-07-validation
go get github.com/gin-gonic/gin@v1.12.0
```

每个示例单独运行，别把多个 `main` 函数放进同一个包。

保存为 `main.go`：

```go
package main

import (
	"errors"
	"fmt"
	"log"
	"net/http"
	"reflect"
	"regexp"
	"strings"
	"sync"

	"github.com/gin-gonic/gin"
	"github.com/gin-gonic/gin/binding"
	"github.com/go-playground/locales/zh"
	ut "github.com/go-playground/universal-translator"
	"github.com/go-playground/validator/v10"
	zhtranslations "github.com/go-playground/validator/v10/translations/zh"
)

type Input struct {
	Name  string `json:"name" binding:"required,min=2,max=32" label:"用户名"`
	Email string `json:"email" binding:"required,email" label:"邮箱"`
	Age   *int   `json:"age" binding:"required,gte=0,lte=150" label:"年龄"`
	IP    string `json:"ip" binding:"omitempty,ip" label:"IP 地址"`
	Slug  string `json:"slug" binding:"required,course_slug" label:"课程标识"`
}

var (
	setupOnce sync.Once
	setupErr  error
	trans     ut.Translator
	slugRule  = regexp.MustCompile(`^[a-z][a-z0-9-]{2,31}$`)
)

// 规则、标签名和翻译在开始处理请求之前注册。
func configureValidation() error {
	v, ok := binding.Validator.Engine().(*validator.Validate)
	if !ok {
		return fmt.Errorf("unexpected validator implementation")
	}
	locale := zh.New()
	uni := ut.New(locale, locale)
	trans, ok = uni.GetTranslator("zh")
	if !ok {
		return fmt.Errorf("Chinese translator is unavailable")
	}
	if err := zhtranslations.RegisterDefaultTranslations(v, trans); err != nil {
		return err
	}
	v.RegisterTagNameFunc(func(field reflect.StructField) string {
		if label := field.Tag.Get("label"); label != "" {
			return label
		}
		return field.Name
	})
	if err := v.RegisterValidation("course_slug", func(fl validator.FieldLevel) bool {
		return fl.Field().Kind() == reflect.String && slugRule.MatchString(fl.Field().String())
	}); err != nil {
		return err
	}
	return v.RegisterTranslation("course_slug", trans, func(t ut.Translator) error {
		return t.Add("course_slug", "{0}需为3到32位小写字母、数字或中划线，且以字母开头", true)
	}, func(t ut.Translator, field validator.FieldError) string {
		message, err := t.T("course_slug", field.Field())
		if err != nil {
			return "课程标识格式不正确"
		}
		return message
	})
}

func fieldErrors(err validator.ValidationErrors) map[string][]string {
	result := make(map[string][]string)
	inputType := reflect.TypeOf(Input{})
	for _, failure := range err {
		name := failure.StructField()
		if field, found := inputType.FieldByName(name); found {
			if jsonName := strings.Split(field.Tag.Get("json"), ",")[0]; jsonName != "" && jsonName != "-" {
				name = jsonName
			}
		}
		// 字段键从结构体标签读取，文案独立翻译，不拆分翻译后的字符串。
		result[name] = append(result[name], failure.Translate(trans))
	}
	return result
}

func NewRouter() *gin.Engine {
	setupOnce.Do(func() { setupErr = configureValidation() })
	if setupErr != nil {
		panic(setupErr)
	}
	r := gin.New()
	r.Use(gin.Recovery())
	if err := r.SetTrustedProxies(nil); err != nil {
		panic(err)
	}
	r.POST("/validate", func(c *gin.Context) {
		if c.ContentType() != gin.MIMEJSON {
			c.JSON(http.StatusUnsupportedMediaType, gin.H{"error": "请提交 JSON"})
			return
		}
		c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, 8192)
		var input Input
		if err := c.ShouldBindJSON(&input); err != nil {
			var failures validator.ValidationErrors
			var tooLarge *http.MaxBytesError
			switch {
			case errors.As(err, &tooLarge):
				c.JSON(http.StatusRequestEntityTooLarge, gin.H{"error": "请求体超过 8 KiB"})
			case errors.As(err, &failures):
				c.JSON(http.StatusBadRequest, gin.H{"errors": fieldErrors(failures)})
			default:
				c.JSON(http.StatusBadRequest, gin.H{"error": "JSON 格式或字段类型不正确"})
			}
			return
		}
		c.JSON(http.StatusOK, gin.H{"name": input.Name, "age": *input.Age, "slug": input.Slug})
	})
	return r
}

func main() {
	if err := NewRouter().Run("127.0.0.1:8080"); err != nil {
		log.Fatal(err)
	}
}
```

示例输入有用户名、邮箱、年龄、可选 IP 和课程标识。IP 直接用内置的 `omitempty,ip`；课程标识用自定义的 `course_slug`：3 到 32 位，小写字母开头，其余字符可以是小写字母、数字和中划线。

`configureValidation` 只在开始处理请求前执行一次：先确认底层校验器的类型，再注册中文翻译、显示字段名和自定义规则。配置失败就直接终止启动，免得等到某次请求才发现规则或翻译用不了。

`ut.New(locale, locale)` 的第一个参数是回退语言，后面的参数是注册的支持语言。这里两处都配成中文，所以能明确检查 `GetTranslator("zh")` 有没有拿到已注册的翻译器。[Universal Translator API](https://pkg.go.dev/github.com/go-playground/universal-translator#New)

`Field()` 用注册后的显示名称参与翻译；`StructField()` 仍然指向 Go 字段。`fieldErrors` 用 `reflect.TypeOf(Input{})` 查看字段声明，再从 `json` 标签取出给前端用的键。这里反射只读类型元数据，不会读取或改写用户的字段值。

## 验证合法零值和中文错误

运行 `go mod tidy`、`go run .`，另开一个终端发送：

```powershell
'{"name":"小明","email":"lin@example.com","age":0,"slug":"gin-basics"}' | Set-Content -Encoding utf8NoBOM request.json
curl.exe -i "http://127.0.0.1:8080/validate" -H "Content-Type: application/json" --data-binary "@request.json"
```

应该得到 `200`，`age` 保持 `0`。然后改几处再试：

- 删掉 `name`：得到前面展示的 `errors.name`。
- `slug` 改成 `Gin`：得到 `errors.slug` 的中文格式说明。
- `age` 改成字符串：得到 `400` 和 JSON 格式或类型错误，不会假装成一条 validator 字段错误。

## 错误映射也有适用范围

这里的字段映射只针对平面的 `Input`。嵌套对象、数组里的同名字段，要结合 `Namespace`、`StructNamespace` 和结构体层级生成完整路径，比如 `items[0].price`，不能只用最后的 `price` 当键。

`*int` 能区分 `nil` 和 `0`，但不能自动区分“没有这个键”和“显式传入 null”。业务要区分这两种情况，可以用自定义解码类型记录字段有没有出现。

自定义校验器接收 `validator.FieldLevel`，能看到字段、父结构、顶层结构和规则参数。只做格式验证时，函数保持纯粹、快速；耗时的网络调用放进业务服务，并用可取消的请求上下文。

参考：[Gin 自定义校验](https://gin-gonic.com/en/docs/binding/custom-validators/)、[FieldError 的字段与命名空间](https://pkg.go.dev/github.com/go-playground/validator/v10@v10.30.1#FieldError)。
