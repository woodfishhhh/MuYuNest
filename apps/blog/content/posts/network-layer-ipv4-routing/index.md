# 计算机网络网络层：分组转发、IPv4 与路由选择

## 4.1 网络层概述

网络层是 OSI 体系结构自下而上的第三层，负责把分组从源主机经过多个网络和链路传到目的主机。两大功能：分组转发、路由选择；向上层提供两种服务。

### 4.1.1 分组转发和路由选择

1. 分组转发：路由器从某个接口收到分组后，按分组首部的转发标识（可能是目的地址或连接指示）查自己的转发表，再从合适的接口转发给下一跳路由器或目的主机。每个路由器都要维护转发表。例：R1 从接口 1 收到分组，按首部转发标识 A 查转发表，得知要从接口 2 转发。
2. 路由选择：源主机和目的主机之间可能有多条路径，网络层要决定走哪条。比如 H1 到 H2 有 H1→R1→R2→H2 和 H1→R1→R4→R3→R2→H2 两条路径，选哪条取决于路由选择方式，主要三种：
    - 集中式路由选择：由网络控制中心执行路由选择，向各路由器下载路由信息。
    - 分布式路由选择：各路由器运行路由选择协议，相互交换路由信息，自己计算路由。
    - 人工路由选择：由网络运维人员手动配置路由。
3. 路由表与转发表：路由选择生成路由表，只含目的网络到下一跳的映射，要针对网络拓扑变化的计算做优化；转发表由路由表得出，结构要针对查找过程做优化。本书讲路由选择原理时不严格区分两者，统一说路由表。

### 4.1.2 网络层向其上层提供的两种服务

1. 面向连接的虚电路服务
    - 思路：可靠通信由网络自己保证。
    - 过程：先建立虚电路（逻辑连接，不是物理连接），保证通信所需的网络资源；然后双方沿虚电路发分组，连接建立阶段用完整的目的主机地址，之后分组首部只带虚电路编号；通信结束后释放虚电路。
    - 特点：分组按逻辑连接存储转发；再用上可靠传输协议，分组就能无差错、按序到达，不丢失、不重复。
    - 应用：X.25、帧中继（FR）、异步传输模式（ATM）等广域分组交换网用过，因特网没采用。
2. 无连接的数据报服务
    - 思路：可靠通信由用户主机保证。
    - 过程：通信前不用建立网络层连接；每个分组可以走不同路径，首部都要带完整的目的主机地址；分组可能误码、丢失、重复、失序；通信结束也不用释放连接。
    - 特点：路由器结构简单、成本低。因特网用的就是这种：复杂的处理放在边缘（用户主机及其内部的运输层），核心只做尽最大努力的分组交付，所以网络造价低、运行灵活、能适应多种应用。
3. 两种服务对比：思路、要不要建连接、目的地址怎么用、分组转发方式、节点故障的影响、分组顺序、服务质量实现难度都有明显差异，见表 4-1。TCP/IP 体系结构中，网际层向上层提供的是无连接、尽最大努力交付的数据报服务。

## 4.2 网际协议（IP）

网际协议 IP 是 TCP/IP 体系结构网络层的核心协议，这里讲的是 IPv4。和 IP 配套使用的有 ARP、RARP、ICMP、IGMP 四个协议，其中 RARP 已淘汰。

### 4.2.1 异构网络互连

1. 异构网络：因特网由大量拓扑、性能、协议各不相同的网络通过路由器互连而成。用户需求多样，没有哪一种网络能满足所有需求。
2. 互连要解决的问题：不同的网络接入机制、差错恢复方法、路由选择技术、寻址方案、最大分组长度、服务类型等。
3. IP 网：各异构网络的网络层都用同一个 IP 协议，从网络层看就像一个统一的 IP 网。IP 网上的主机通信时不用管各网络的异构细节，就像在单个网络里通信。

### 4.2.2 IPv4 地址及其编址方法

1. IPv4 地址：给 IP 网上主机（或路由器）每个接口分配的 32 比特全球唯一标识符，由 ICANN 分配，我国用户可以向 APNIC 申请（要缴费，一般不接受个人申请）。2011 年 2 月 3 日，IANA 宣布 IPv4 地址分配完毕；我国 2014-2015 年逐步停止向新用户和应用分配 IPv4 地址，同时部署 IPv6。
2. 表示方法：点分十进制。32 比特地址每 8 比特一组，各自转成十进制数，组之间用 “.” 隔开。例如 00001010111100000000111110101010 转换后是 10.240.15.170。
3. 编址方法的发展阶段
    - 分类编址（1981 年）：32 比特地址分成网络号（标志接口连接的网络）和主机号（标志主机或路由器接口）。同一网络中网络号相同、主机号不同。分 A、B、C、D、E 五类：
      - A 类：网络号 8 比特（首 1 位 0），主机号 24 比特
      - B 类：网络号 16 比特（首 2 位 10），主机号 16 比特
      - C 类：网络号 24 比特（首 3 位 110），主机号 8 比特
      - D 类：多播地址（首 4 位 1110）
      - E 类：保留地址（首 4 位 1111）
      - 只有 A、B、C 类地址能分配给接口；主机号全 0 是网络地址，全 1 是广播地址，都不能分配
      - 各类地址可指派的网络数量、每个网络可分配的地址数量等细节见表 4-2、表 4-3
    - [[划分子网]]（1985 年，RFC 950）：为了解决分类编址浪费地址的问题，从主机号借一部分比特作为子网号，地址从两级结构变成三级结构（网络号、子网号、主机号）。
      - 子网掩码：32 比特，连续的 1 对应网络号和子网号，连续的 0 对应主机号，用来表明借了多少比特
      - 地址和子网掩码逐比特逻辑与运算，得到子网的网络地址
      - 默认子网掩码，即未[[划分子网]]时的子网掩码：A 类 255.0.0.0，B 类 255.255.0.0，C 类 255.255.255.0
    - 无分类编址（1993 年，CIDR）：为了进一步缓解地址资源紧张，取消分类编址和[[划分子网]]的概念，地址改回两级结构（网络前缀、主机号），网络前缀不定长。
      - 用地址掩码（同子网掩码）配合地址，也可以用斜线记法（地址后加 “/” 和网络前缀比特数）
      - CIDR 地址块可以聚合多个连续地址；通过地址可以确定地址块的最小地址、最大地址、地址数量、聚合网络数量、地址掩码等
      - 能实现路由聚合（构造超网），减少路由表条目；查找时遵循[[最长前缀匹配原则]]

### 4.2.3 IPv4 地址的应用规划

应用规划就是把给定的地址块（或分类网络）划分成更小的地址块（或子网），分给不同网络，再给主机和路由器接口分配地址。两种方法：

1. 定长的子网掩码（FLSM）：每个子网用同一个子网掩码，地址数量相同，容易浪费地址。例：C 类网络 218.75.230.0 按需求借 3 比特作子网号，分成 8 个子网，每个子网 32 个地址，分给不同网络时，有的网络用不完。
2. 变长的子网掩码（VLSM）：每个子网可以用不同的子网掩码，地址数量按需分配，减少浪费。例：CIDR 地址块 218.75.230.0/24，按各网络的地址需求，分别划出 /27、/28、/30 等不同前缀长度的地址块，满足不同网络的需求，避免浪费。

### 4.2.4 IPv4 地址与 MAC 地址

1. 封装位置：IP 地址是网际层及以上各层用的地址，封装在 IP 数据报首部；MAC 地址（硬件 / 物理地址）是数据链路层用的地址，封装在帧首部。
2. 传送中的变化：分组传输过程中，源 IP 地址和目的 IP 地址始终不变，源 MAC 地址和目的 MAC 地址逐网络（或逐链路）变化。例：H1 给 H2 发分组，经 R1、R2 转发：
    - H1 到 R1：帧的源 MAC 是 H1 的 MAC，目的 MAC 是 R1 的 MAC
    - R1 到 R2：帧的源 MAC 是 R1 转发接口的 MAC，目的 MAC 是 R2 的 MAC
    - R2 到 H2：帧的源 MAC 是 R2 转发接口的 MAC，目的 MAC 是 H2 的 MAC
    - 全程 IP 数据报的源 IP 和目的 IP 都是 H1 和 H2 的 IP
3. 两者关系：只用 MAC 地址通信，路由器的路由表就得记录海量 MAC 地址，配置和维护困难，还占用大量通信资源和存储空间，增加分组转发时延。网际层用 IP 地址寻址，路由表条目少；但要用地址解析协议拿到下一跳的 MAC 地址，才能完成数据链路层帧的封装。

### 4.2.5 地址解析协议

1. ARP 协议：通过已知的 IP 地址找到对应的 MAC 地址。
    - 主机维护 ARP 高速缓存表，记录 IP 与 MAC 地址的对应关系。分动态和静态：动态由 ARP 自动获取，生命周期默认 2 分钟；静态由人工配置。
    - 主机要给其他主机发分组时，先查 ARP 高速缓存表；查不到就发 ARP 请求报文（广播，含自己的 IP、MAC 和目标 IP）。
    - 目标主机收到后，把发送方的 IP 与 MAC 记进自己的缓存表，再发 ARP 响应报文（单播，含自己的 IP、MAC）。
    - 发送方收到后更新自己的缓存表，就可以发分组了。
    - ARP 只在同一局域网使用。跨网络通信时，各段链路分别使用 ARP。
2. RARP 协议：让只知道自己 MAC 地址的主机找出 IP 地址。DHCP 已经包含它的功能，现在不再使用。
3. ARP 协议归属：有的教材划归网际层，有的划归数据链路层，都合理。除了请求和响应报文，还有无故 ARP 等类型的报文。ARP 没有安全验证机制，存在欺骗和攻击问题。

### 4.2.6 IP 数据报的发送和转发过程

1. 主机发送 IP 数据报
    - 直接交付：同一网络中的主机通信，源主机通过 ARP 拿到目的主机的 MAC 地址，把 IP 数据报封装成帧发送。判断是不是同一网络：把自己和目的主机的 IP 地址都保持网络前缀不变、主机号清零，得到的网络地址相同就是同一网络。
    - 间接交付：不同网络中的主机通信，源主机通过 ARP 拿到默认网关（路由器）的 MAC 地址，把 IP 数据报封装成帧发给默认网关，由网关转发。
2. 路由器转发 IP 数据报：收到正确的 IP 数据报（TTL 未结束、首部无误码）后，按目的 IP 地址查路由表。
    - 查到匹配条目就按指示转发；查不到就丢弃，并向源主机发送差错报告。
    - 例：主机 A 给 D 发 IP 数据报，路由器 R 收到后，把目的 IP 和路由表中的地址掩码逐比特逻辑与运算，找到匹配的目的网络条目，从对应接口转发给 D。
    - 路由器不转发目的地址为广播地址的 IP 数据报，以此隔离广播域，避免广播风暴。

### 4.2.7 IPv4 数据报的首部格式

IPv4 数据报首部由 20 字节固定部分和最多 40 字节可变部分组成。各字段：

1. 版本：4 比特，表示 IP 协议版本，目前是 4（IPv4）。
2. 首部长度、可选字段和填充：
    - 首部长度：4 比特，以 4 字节为单位，最小 5（20 字节固定部分），最大 15（20 字节固定 + 40 字节可变）
    - 可选字段：1-40 字节，支持排错、测量等功能，很少用
    - 填充字段：用全 0 填充，保证首部长度是 4 字节的整数倍
3. 区分服务：8 比特，旧称服务类型，现在用来提供不同的服务质量，一般不使用。
4. 总长度：16 比特，以字节为单位，表示 IP 数据报总长度（首部 + 数据载荷），最大 65535 字节。
5. 标识、标志和片偏移：一起用于数据报分片。
    - 标识：16 比特，同一数据报的分片标识相同
    - 标志：3 比特。最低位 MF（1 表示后面还有分片，0 表示没有）；中间位 DF（1 表示不允许分片，0 表示允许）；最高位保留为 0
    - 片偏移：13 比特，以 8 字节为单位，表示分片的数据载荷在原数据报中的偏移位置
6. 生存时间（TTL）：8 比特，最初以秒为单位，现在以跳数为单位。源主机设初始值，路由器转发时减 1，减到 0 就丢弃，防止数据报无限兜圈。
7. 协议：8 比特，指明数据载荷的协议类型，如 6 对应 TCP，17 对应 UDP 等。
8. 首部检验和：16 比特，检测首部的传输差错，路由器转发时要重新计算。计算方法：发送方把首部划分成 16 比特字的序列，检验和字段先置 0，反码算术求和后取反码写入；接收方重新求和再取反码，结果为 0 就是没有差错，否则丢弃。
9. 源 IP 地址和目的 IP 地址：各 32 比特，分别是发送方和接收方的 IP 地址。

## 4.3 静态路由配置

静态路由配置就是人工给路由器配置路由表。简单、开销小，但适应不了网络状态变化，适合小规模网络。

### 4.3.1 直连路由和非直连路由

1. 直连路由：给路由器各接口配好 IP 地址和地址掩码后，路由器自己就能得出各接口直连网络的路由条目，记录在路由表中。
2. 非直连路由：路由器到其他非直连网络的路由，靠人工配置（静态路由）或通过路由选择协议自动获取（动态路由）。例：R1 接口 0、1 直连的网络，对应的路由条目是直连路由；到 R2 直连的另一个网络的路由条目要人工配置，是非直连路由。

### 4.3.2 默认路由和特定主机路由

1. 默认路由：路由器查不到匹配的路由条目时，按默认路由转发。默认路由条目的目的网络是 0.0.0.0/0，匹配优先级最低（[[最长前缀匹配原则]]），能减少路由表的存储空间和查找时间。例：R1 到因特网的路由配一条默认路由，下一跳为 R2，就不用配置到因特网各个网络的路由条目。
2. 特定主机路由：针对某一台主机的路由，目的网络是该主机 IP/32，匹配优先级最高，用于安全控制、网络测试和排错。例：R1 到主机 192.168.2.1 配一条特定主机路由，下一跳为 R2。

配置静态路由要小心，别配出路由环路。

## 4.4 因特网的路由选择协议

### 4.4.1 路由选择分类

1. 静态路由选择：人工配置路由条目。简单、开销小，但适应不了网络状态变化，适合小规模网络。
2. 动态路由选择：路由器通过路由选择协议自动获取路由信息。复杂、开销大，但能适应网络状态变化，适合大规模网络。

### 4.4.2 因特网采用分层次的路由选择协议

1. 特点：
    - 自适应：动态路由，适应网络状态变化
    - 分布式：各路由器交换信息，共同完成路由的获取和更新
    - 分层次：把因特网划分成自治系统 AS，AS 内和 AS 间用不同的路由选择协议
2. 路由选择协议分类
    - 内部网关协议（IGP）：用于 AS 内的路由选择，各 AS 可以选不同的 IGP，如 RIP、OSPF。
    - 外部网关协议（EGP）：用于 AS 间的路由选择（域间路由选择），如 BGP。早期 RFC 叫 “网关”，新文档叫 “路由器”，两种叫法都可以。

### 4.4.3 路由信息协议（RIP）

1. 基本概念：
    - 早期广泛使用的 IGP，标准文档 RFC 1058，基于距离向量算法
    - 用跳数衡量到目的网络的距离：直连网络距离为 1，非直连网络为经过的路由器数 + 1；最大跳数 15（16 表示不可达），适合小型互联网
    - 认为跳数少的路由就是好路由；可以做等价负载均衡
    - 只和相邻路由器周期性（约 30 秒）交换自己的路由表信息；网络拓扑变化时触发更新，加快收敛
2. 工作过程：路由器一开始只知道直连网络的路由；和相邻路由器周期性交换、更新路由信息；经过若干次交换更新后，每个路由器都知道 AS 内各网络的最短距离和下一跳，这就是收敛。
3. 距离向量算法：路由器收到相邻路由器的路由更新报文后，先修改报文（下一跳改为这个相邻路由器，距离加 1），再更新自己的路由表。时间参数：每 30 秒发送更新报文，180 秒没收到更新就把该路由标记为无效，再过 120 秒还没收到就删除该路由。更新规则：
    - 下一跳相同：不管距离怎么变，都更新
    - 发现新网络：添加路由条目
    - 下一跳不同，新路由距离更小：更新
    - 下一跳不同，新路由距离相同：添加条目（等价负载均衡）
    - 下一跳不同，新路由距离更大：不更新
4. 存在问题：“坏消息传播得慢”，容易形成路由环路，可能持续数分钟。可以用限制最大跳数、触发更新、水平分割等措施降低出问题的概率或减轻危害，但没法彻底解决：路由器缺少到目的网络的完整路径信息，判断不了路由是否成环。
5. 版本和报文：最新版本 RIP2（RFC 2453），支持 VLSM、CIDR、鉴别和多播。RIP 报文用 UDP（端口 520）传送，属于应用层，但核心功能属于网际层。
6. 优缺点：
    - 优点：实现简单，路由器开销小，好消息传播快
    - 缺点：限制了最大跳数，网络规模受限；相邻路由器交换的是完整路由表，网络规模变大后开销增加；坏消息传播慢，收敛时间长
    - 大规模 AS 用 OSPF，小规模 AS 仍常用 RIP

### 4.4.4 开放最短路径优先协议（OSPF）

1. 基本概念：1989 年开发，用来克服 RIP 的缺点。“开放” 指协议公开发表；“最短路径优先” 是因为用了 Dijkstra 算法。基于链路状态（路由器的相邻关系和链路代价；代价由网络管理人员决定，如思科路由器用 100Mb/s 除以链路带宽计算）。没有路由环路，不限制网络规模，更新效率高，收敛快。
2. 关键机制
    - 邻居关系建立和维护：相邻路由器用 Hello 分组（封装在 IP 数据报中，发往组播地址 224.0.0.5，协议号 89）建立和维护邻居关系。Hello 分组每 10 秒发一次，40 秒没收到就认为邻居不可达。主机建立邻居表。
    - 链路状态通告（LSA）：每个路由器产生 LSA，包含直连网络和邻居路由器的链路状态信息。
    - 链路状态更新分组（LSU）：LSA 封装在 LSU 中，用洪泛法发送，使各路由器的链路状态数据库（LSDB）一致。
    - 链路状态数据库（LSDB）：存储 LSA。各路由器 LSDB 一致后，基于 Dijkstra 算法计算最短路径，构建路由表。
3. 分组类型，共五种：
    - 问候（Hello）分组：发现和维护邻居可达性
    - 数据库描述分组：给邻居发送 LSDB 摘要
    - 链路状态请求分组：请求邻居发送特定 LSA 的详细信息
    - 链路状态更新分组：洪泛发送 LSA
    - 链路状态确认分组：确认 LSU
4. 工作过程：
    1. 相邻路由器交换 Hello 分组，建立邻居关系
    2. 发送数据库描述分组，共享 LSDB 摘要
    3. 针对缺少的 LSA，发送链路状态请求分组
    4. 邻居发送 LSU，请求方更新 LSDB 并发送确认
    5. LSDB 同步后，路由器基于 LSDB 计算路由表
    6. 之后每 30 分钟或链路状态变化时，洪泛发送 LSU，更新 LSDB
5. 多点接入网络优化：选举指定路由器（DR）和备用指定路由器（BDR），普通路由器只和 DR、BDR 建立邻居关系，减少发送的分组数量。DR 故障时由 BDR 顶替。
6. 区域划分：把 AS 划分成多个区域，主干区域（标识 0）连通其他区域。区域划分把洪泛范围限制在区域内，减少通信量。涉及的路由器：
    - 区域边界路由器：连接自己的区域和主干区域
    - 区域内路由器：所有接口都在同一区域
    - 主干路由器：主干区域内的路由器，包括区域边界路由器
    - 自治系统边界路由器：主干区域内和其他 AS 交换路由信息的路由器

### 4.4.5 边界网关协议（BGP）

1. 基本概念：属于 EGP，用于 AS 间的路由选择。不同 AS 度量路由 “代价” 的方式不同，还要考虑政治、经济、安全等策略，所以 BGP 不找最佳路由，只找能到达目的网络、没有环路的较好路由。
2. BGP 边界路由器：每个 AS 至少选一个路由器作为 BGP 发言人（一般是边界路由器）。不同 AS 的 BGP 发言人建立 TCP 连接（端口 179）进行 BGP 会话，交换路由信息（网络可达性，也就是到达某个网络要经过的 AS 序列），构建无环路的 AS 连通图。BGP 发言人还要运行所在 AS 的 IGP（如 RIP、OSPF）。
3. BGP-4 报文：一开始交换完整路由表，之后只更新变化的部分。报文共四种：
    - OPEN 报文：建立 BGP 关系，初始化通信
    - UPDATE 报文：通告路由信息，撤销过时路由
    - KEEPALIVE 报文：周期性证实邻站连通性，约 30 秒发一次，只有 19 字节
    - NOTIFICATION 报文：发送差错信息
    - 另外，RFC 2918 增加了 ROUTE-REFRESH 报文：请求对等方重新通告路由

### 4.4.6 路由器的基本工作原理

路由器是有多个输入、输出端口的专用计算机，任务是转发分组，分为路由选择和分组转发两部分。

1. 路由选择部分：核心是路由选择处理机，按路由选择协议周期性地和其他路由器交换路由信息，构建和更新路由表。
2. 分组转发部分：由输入端口、交换结构、输出端口组成。信号从输入端口进来，物理层把比特流交给数据链路层，数据链路层识别出帧，去掉帧头帧尾交给网络层：
    - 普通的待转发数据分组：网络层按目的地址查转发表，更新分组首部（如 TTL 减 1），交给数据链路层封装成帧，由物理层发送。
    - 路由分组：交给路由选择处理机，更新路由表；路由选择处理机还会周期性地发送路由信息。
3. 缓冲区：各端口有输入缓冲区（暂存待处理分组）和输出缓冲区（暂存待发送分组）。
4. 交换结构：关键构件，负责把分组从输入端口转到输出端口。三种实现方式：通过存储器、总线、互连网络，转发速率依次提高。

## 4.5 网际控制报文协议（ICMP）

为了更有效地转发 IP 数据报、提高交付成功率，TCP/IP 体系结构的网际层使用 ICMP。主机或路由器用它发送差错报告和询问报文，ICMP 报文封装在 IP 数据报中发送。

### 4.5.1 ICMP 报文的种类

1. ICMP 差错报告报文：报告差错情况，共五种：
    - 终点不可达：路由器或主机不能交付 IP 数据报时发送，细分为目的网络、主机、协议、端口不可达等 13 种错误。例：R1 的路由表里没有 H2 所在网络的路由，收到 H1 发给 H2 的 IP 数据报后，丢弃并向 H1 发送终点不可达报文。
    - 源点抑制：路由器或主机因为拥塞丢弃 IP 数据报时发送，让源主机降低发送速率。例：R2 拥塞，丢弃 H1 发给 H2 的 IP 数据报，向 H1 发送源点抑制报文。
    - 时间超过（超时）：路由器转发 IP 数据报时 TTL 减 1 后为 0，丢弃并发送；终点在规定时间内没收到全部数据报片，丢弃已收到的片并发送。例：H1 发送 TTL=2 的 IP 数据报，经 R1（TTL=1）、R2（TTL=0），R2 丢弃并向 H1 发送时间超过报文。
    - 参数问题：路由器或目的主机收到 IP 数据报，首部检验和出错就丢弃并发送。例：H1 发给 H2 的 IP 数据报首部受干扰出错，R1 检测到后丢弃并向 H1 发送参数问题报文。
    - 改变路由（重定向）：路由器告诉主机下次把数据报发给另一个路由器，以选择更好的路由。例：H1 的默认网关是 R1，R1 发现 H1 发往 N2 的最佳路由要经过 R4，就向 H1 发送改变路由报文，H1 更新路由表。
    - 不发送 ICMP 差错报告报文的情况：
      - 对 ICMP 差错报告报文不发送
      - 对第一个分片后续的分片不发送
      - 对多播地址的 IP 数据报不发送
      - 对特殊地址（如 127.0.0.0、0.0.0.0）的数据报不发送
2. ICMP 询问报文，常用的有：
    - 回送请求和回答：测试目的站的可达性及状态
    - 时间戳请求和回答：请求日期时间，用于时钟同步和时间测量

### 4.5.2 ICMP 的典型应用

1. 分组网间探测（PING）：测试主机或路由器的连通性。应用层直接使用 ICMP，不使用 TCP 或 UDP，用的是回送请求和回答报文。例：PC 给服务器发 4 个 ICMP 回送请求报文，收到 4 个回送回答报文，就能得出连通性和往返时间。部分主机 / 服务器为了防攻击，可能不理睬这种报文。
2. 跟踪路由
    - 工具：UNIX 中是 “traceroute”（用 UDP，ICMP 差错报告报文），Windows 中是 “tracert”（直接用 ICMP，回送请求、回答及差错报告报文）。
    - tracert 原理：主机发送 ICMP 回送请求报文，TTL 依次设为 1、2、3…
      - TTL=1：第一台路由器收到后 TTL 减为 0，丢弃并发送时间超过报文，主机就知道了第一台路由器
      - TTL=2：第二台路由器收到后 TTL 减为 0，丢弃并发送时间超过报文，主机就知道了第二台路由器
      - 直到 TTL 足够大，目的主机收到后发送回送回答报文，主机就知道已经到达目的主机
      - 例：H1 跟踪到 H2 的路由，依次发送 TTL=1、2、3 的报文，获取各路由器的 IP 地址

## 4.6 虚拟专用网（VPN）和网络地址转换（NAT）

### 4.6.1 虚拟专用网（VPN）

1. 背景：远程专用网之间通信有两种方式：租用电信线路（简单但费用高），或者把因特网当载体（就是 VPN，成本低）。专用网内主机用专用地址（RFC 1918 规定 10.0.0.0~10.255.255.255、172.16.0.0~172.31.255.255、192.168.0.0~192.168.255.255），只在机构内部有效，因特网路由器不转发目的地址为专用地址的 IP 数据报。
2. 工作原理：用的是 IP 隧道技术，逻辑上就像在专用网内通信。专用网至少要有一个路由器有全球 IP 地址，并做 VPN 配置：
    - 源主机把内部 IP 数据报发给路由器
    - 路由器加密内部 IP 数据报，重新封装成外部 IP 数据报（源、目的都是路由器的全球 IP），通过因特网发给目的专用网的路由器
    - 目的路由器解密，取出内部 IP 数据报，发给目的主机
3. VPN 类型：
    - 内联网 VPN：由同一机构内不同部门的专用网构成
    - 外联网 VPN：机构的 VPN 包含外部合作伙伴
    - 远程接入 VPN：外地员工通过因特网访问公司专用网

### 4.6.2 网络地址转换（NAT）

1. 背景：1994 年提出，用来缓解 IPv4 地址耗尽问题，让大量使用内部专用地址的主机共享少量外部全球地址访问因特网。要在专用网连接因特网的路由器（NAT 路由器）上安装 NAT 软件，NAT 路由器至少有一个全球 IP。
2. 基本 NAT 方法：
    - 发出：源主机给外部主机发 IP 数据报，NAT 路由器从全球地址池选一个临时全球地址，修改数据报的源地址，记录内部 IP 与全球 IP 的对应关系，再转发
    - 返回：外部主机发回数据报，NAT 路由器按对应关系把目的地址改回内部 IP，转发给源主机
    - 缺点：NAT 路由器有 n 个全球 IP，专用网最多只能有 n 台主机同时接入因特网
3. 网络地址与端口号转换（NAPT）：把运输层端口号也用上，大量内部主机就能共用 1 个全球 IP。
    - NAPT 路由器收到内部主机的 IP 数据报，把源地址改成全球 IP，修改运输层源端口号，记录 内部 IP: 端口 与 全球 IP: 端口 的对应关系，再转发
    - 收到外部主机的数据报，按对应关系修改目的地址和端口号，转发给内部主机
    - 限制：NAPT 对部分网络应用不透明；通信要由专用网内部发起，内部主机不能直接充当因特网服务器；P2P 应用需要 NAT 穿透技术

## 4.7 IP 多播

### 4.7.1 IP 多播技术的相关基本概念

多播（组播）是 “一对多” 通信技术，相比单播 “一对一”，能节省网络资源。IP 多播由 Steve Dering 于 1988 年提出，1992 年 3 月首次实验。

例：视频服务器向 60 台主机传视频，单播要发 60 个，多播只发 1 个，由路由器按需复制；到了局域网利用硬件多播，多播组成员都能收到。

因特网上实现多播需要路由器支持多播功能，涉及多播寻址和路由选择协议。

### 4.7.2 IP 多播地址和多播组

1. 多播地址：IPv4 中的 D 类地址就是多播地址，首 4 位 1110，剩下 28 位可变，范围 224.0.0.0~239.255.255.255，只能作目的地址。
2. 多播组：每个 D 类地址标识一个多播组，用同一多播地址接收数据报的主机构成多播组。
    - 成员可以动态变动，一台主机可以属于多个多播组
    - 非成员也可以向多播组发送数据报
    - 多播数据报 “尽最大努力交付”
3. D 类地址分类：预留多播地址（永久）、全球可用多播地址、本地管理多播地址（只在本地有效）。
4. IP 多播类型：本局域网上的硬件多播、因特网上的多播。因特网上的多播最后阶段要在局域网用硬件多播交付。

### 4.7.3 在局域网上进行硬件多播

局域网支持硬件多播：把 IPv4 多播地址映射成多播 MAC 地址（IANA 分配了 01-00-5E-00-00-00~01-00-5E-7F-FF-FF 的 MAC 地址）。多播 MAC 地址首 25 比特固定，剩下 23 比特来自 D 类 IP 地址的低 23 比特，所以多播 IP 与 MAC 地址的映射不唯一。

主机收到多播数据报后，先用 MAC 地址判断是否属于本硬件多播组，是就交给网际层；网际层再根据 IP 地址判断是否属于本 IP 多播组，是就接受，否则丢弃。

### 4.7.4 在因特网上进行 IP 多播需要的两种协议

因特网上的 IP 多播需要两种协议：

- 网际组管理协议（IGMP）：让本地局域网的多播路由器知道本局域网上是否有主机加入 / 退出多播组。只在本网络有效，不知道多播组成员的数量和分布。
- 多播路由选择协议：让多播路由器协同工作，为每个多播组建立多播转发树。IP 多播数据报沿树洪泛，再通过硬件多播发给成员。

### 4.7.5 网际组管理协议（IGMP）

1. 基本概念：最新版本 IGMPv3（RFC 3376），有成员报告、成员查询、离开组三种报文，封装在 IP 多播数据报中发送（协议字段 = 2，目的地址为多播地址，TTL=1）。
2. 工作原理
    - 加入多播组：主机发送 IGMP 成员报告报文（含要加入的多播组地址，数据报目的地址就是该多播组地址），同组其他成员监听到就取消发送。多播路由器收到未知多播组的报告，把该多播组地址加入多播组列表（不记录主机 IP）。
    - 监视多播组成员变化：多播路由器默认每 125 秒发送 IGMP 成员查询报文（含特定多播组地址或全 0，数据报目的地址 224.0.0.1）。收到查询的多播组成员随机延迟 1-10 秒响应，如果收到了同组其他成员的响应就取消。某个多播组长时间没有响应，就把它从列表删除。同一网络中的多播路由器会选举查询路由器（IP 地址最小的）来发送查询报文。
    - 退出多播组：IGMPv2 支持主机主动发送离开组报文（含要退出的多播组地址，数据报目的地址 224.0.0.2）。多播路由器收到后，立即针对该多播组发送查询报文，预定时间内没收到响应就删除该多播组。

### 4.7.6 多播路由选择协议

多播路由选择协议为每个多播组建立多播转发树，有两种构建方法：

1. 基于源树的多播路由选择：典型算法是反向路径多播（RPM）。
    - 先通过反向路径广播（RPB）建立广播转发树。RPB 检查广播分组是否从源点经最短路径传来，是才转发，以此避免洪泛法在有环路网络中的问题
    - 再用剪枝算法剪除下游的非成员路由器，得到多播转发树
    - 被剪枝的路由器如果又发现了多播组成员，可以发送嫁接报文重新加入
2. 组共享树多播路由选择：用基于核心的分布式生成树算法，指定核心路由器，以它为根建立多播转发树。成员路由器向核心路由器单播加入报文，加入报文经过的路径构成树的分支，嫁接到现有的树上。
3. 因特网多播路由选择协议：目前没有全球使用的协议，建议使用的有 DVMRP、MOSPF、PIM-SM、PIM-DM、CBT 等。IP 多播目前主要用于局部网络；应用层多播技术也在发展，多播路由选择协议的算法思想仍然适用。

## 4.8 移动 IP 技术

### 4.8.1 移动性对因特网应用的影响

1. 没影响的场景：主机在同一 Wi-Fi 服务区内移动（IP 不变）；主机在不同地点关机后重新上网（通过 DHCP 获取新 IP，对用户透明）。
2. 有影响的场景：主机在不同网络之间移动，而且要不间断通信（如在汽车中下载视频）。切换网络导致 IP 变化，应用程序没法向 IP 在变的主机发送数据。IP 地址指明了主机及其所在的网络，移动主机切换网络就必须换 IP，否则数据报仍会路由到原网络。

### 4.8.2 移动 IP 技术的相关基本概念

移动 IP（RFC 3344）让移动主机在网络之间漫游时保持原 IP 不变，非移动主机也能正确地向它发送数据报，而且不用改变非移动主机的软件和多数路由器的工作方式。

1. 归属网络、归属地址（永久地址）、归属代理：
    - 归属网络：移动主机默认连接或最初接入的网络
    - 归属地址：移动主机在归属网络的 IP，通信中不变
    - 归属代理：归属网络中执行移动管理功能的实体（通常是路由器，功能在应用层完成）
2. 外地网络（被访网络）、外地代理、转交地址：
    - 外地网络：移动主机当前漫游所在的网络
    - 外地代理：外地网络中帮助移动主机执行移动管理功能的实体（通常是路由器）
    - 转交地址：外地代理为移动主机提供的临时外地网络地址
3. 工作过程：移动主机漫游到外地网络后，归属代理代收它的数据报，按转交地址通过 IP-in-IP 隧道转发给外地代理，外地代理再转发给移动主机。整个过程对固定主机透明。

### 4.8.3 移动 IP 技术的基本工作原理

1. 代理发现与注册：移动主机漫游到外地网络，通过代理发现协议和外地代理建立联系，获取转交地址并注册；外地代理向归属代理注册移动主机的转交地址；归属代理记录转交地址，之后代收并转发数据报。
2. 固定主机向移动主机发送 IP 数据报：
    - 固定主机发送数据报（目的地址是移动主机的归属地址），数据报被路由到归属网络，由归属代理代收
    - 归属代理把它封装成新的 IP 数据报（目的地址是转交地址），通过 IP 隧道发给外地代理；外地代理解封后转发给移动主机
    - 归属代理用 ARP 代理技术代收数据报
    - 转交地址可以是外地代理的地址（多台主机共享），外地代理通过记录移动主机永久地址与 MAC 地址的对应关系来转发数据报
3. 移动主机向固定主机发送 IP 数据报：移动主机发送数据报（源地址是归属地址，目的地址是固定主机 IP），按正常流程发送：把外地代理或外地网络的路由器设为默认网关，不用经过归属代理转发。
4. 同址转交地址：外地代理可以运行在移动主机上，这时转交地址叫同址转交地址（既是外地代理的地址，也是移动主机的地址）。移动主机要通过 DHCP 获取外地网络地址，并运行外地代理软件。
5. 三角形路由问题：固定主机向移动主机发数据报要经过归属代理转发，可能走了低效路径（如固定主机和移动主机就在同一个外地网络）。解决方法：固定主机配置通信代理，从归属代理获取移动主机的转交地址，直接通过隧道发送。代价是增加了复杂性，而且对固定主机不透明。

### 4.8.4 蜂窝移动通信网中的移动性管理

蜂窝移动通信网更早就支持移动性：手机漫游时用同一个电话号码，通话不中断，采用和移动 IP 类似但更复杂的机制。CDMA2000 分组域核心网络支持用移动 IP 为数据业务提供移动性服务；其他 3G 标准在 IP 层以下提供，而且只在网络内部提供移动性服务。目前移动 IP 还没有在全球因特网上大规模使用。

## 4.9 下一代网际协议 IPv6

### 4.9.1 IPv6 引进的主要变化

IPv4 地址设计有缺陷，导致地址耗尽：2011 年 IANA 宣布 IPv4 地址分配完毕，我国 2014-2015 年停止分配并部署 IPv6。IPv6 支持无连接、尽最大努力交付，协议数据单元叫分组（本书仍叫 IP 数据报）。主要变化：

1. 更大的地址空间：地址长度从 32 比特增加到 128 比特，地址空间极大，可预见的未来不会用完。
2. 扩展的地址层次结构：地址空间大，可以划分更多层次，反映因特网拓扑，优化寻址和路由设计。
3. 灵活的首部格式：首部与 IPv4 不兼容，定义了可选的扩展首部，提高路由器处理效率（只处理逐跳扩展首部）。
4. 改进的选项：允许数据报包含选项控制信息，可以添加新选项；IPv4 的选项是固定的。
5. 允许协议继续扩充：适应技术发展和新应用的出现；IPv4 的功能是固定的。
6. 支持即插即用（自动配置）：主机或路由器自动配置 IPv6 地址及网络参数，不需要 DHCP。
7. 支持资源预分配：为实时音视频等应用提供更好的服务质量保证。

### 4.9.2 IPv6 数据报的基本首部

IPv6 数据报由 40 字节基本首部和可变长度的有效载荷（含零个或多个扩展首部及数据部分）组成。和 IPv4 首部相比：

- 取消了首部长度、服务类型、总长度、标识、标志、片偏移、协议、检验和、选项等字段
- 新增通信量类、流标号字段
- TTL 改为跳数限制，协议改为下一个首部

基本首部各字段：

1. 版本：4 比特，IPv6 对应的值是 6。
2. 通信量类：8 比特，区分数据报的类别或优先级。
3. 流标号：20 比特，标识 “流”（特定源到目的的一系列数据报），用于资源预分配，非实时数据置 0。
4. 有效载荷长度：16 比特，表示基本首部后面有效载荷的字节数，最大 65535 字节。
5. 下一个首部：8 比特，没有扩展首部时表示数据部分的协议类型，有扩展首部时表示第一个扩展首部的类型。
6. 跳数限制：8 比特，源主机设初始值（最大 255），路由器转发时减 1，为 0 就丢弃。
7. 源地址、目的地址：各 128 比特，分别是发送端和接收端的 IPv6 地址。

### 4.9.3 IPv6 数据报的扩展首部

IPv6 把 IPv4 首部中的选项放进扩展首部，由源点和终点主机处理，路径上的路由器不处理（逐跳选项扩展首部除外），提高处理效率。RFC 2460 定义了六种扩展首部：逐跳选项、路由选择、分片、鉴别、封装安全有效载荷、目的站选项。每个扩展首部的第一个字段都是 8 比特的下一个首部字段，多个扩展首部按特定顺序出现。

### 4.9.4 IPv6 地址

1. 地址分配：IPv6 给节点的每个接口指派地址，一个节点可以有多个单播地址。
2. 地址空间大小：128 比特，地址空间为 2^128，极其巨大，能满足未来需求。
3. 表示方法：冒号十六进制记法。128 比特每 16 比特一组（共 8 组），组之间用 “:” 分隔，每组按 4 比特转十六进制数。
    - “左侧零” 省略：十六进制数的前导零可以省略
    - “连续零” 压缩：连续的零用 “::” 替代，一个地址里只能用一次
    - 还可以结合点分十进制后缀（过渡阶段用）
    - CIDR 斜线记法仍然适用
4. 地址分类
    - 目的地址类型：单播（点对点）、多播（一点对多点，广播是多播的特例）、任播（一点对一组中最近的一个）。
    - 地址分类：
      - 未指明地址：全 0，缩写 “::”，只能作源地址
      - 环回地址：只有最低比特为 1，其余全 0，缩写 “::1”
      - 多播地址：首 8 比特全 1，记为 FF00::/8
      - 本地链路单播地址：首 10 比特 1111111010，记为 FE80::/10，只用于本地网络通信
      - 全球单播地址：除上述四种之外的地址，三级结构：48 比特全球路由选择前缀、16 比特子网标识符、64 比特接口标识符

### 4.9.5 从 IPv4 向 IPv6 过渡

因特网上的 IPv4 路由器数量太多，只能逐步过渡，新的 IPv6 系统要兼容 IPv4。主要有两种过渡策略：

1. 双协议栈：主机或路由器装 IPv4 和 IPv6 两套协议栈，能和两种系统通信，记为 IPv6/IPv4。双协议栈主机通过 DNS 查询目的主机的地址类型，再选对应的协议通信。例：IPv6 主机 A 给 B 发数据报，途经 IPv6/IPv4 路由器 R1、R4 和 IPv4 路由器 R2、R3。R1 把 IPv6 数据报转成 IPv4 数据报，R2、R3 转发，R4 再恢复成 IPv6 数据报交给 B。转换可能损失部分 IPv6 字段信息。
2. 隧道技术：IPv6 数据报进入 IPv4 网络时，封装成 IPv4 数据报（IPv6 数据报作为数据部分），在 IPv4 网络中传输，离开时再取出 IPv6 数据报转发。IPv4 数据报的源、目的地址是隧道入口、出口路由器的 IPv4 地址，协议字段设为 41，表明数据部分是 IPv6 数据报。

### 4.9.6 网际控制报文协议 ICMPv6

IPv6 需要 ICMPv6 反馈差错信息。ICMPv6 比 ICMPv4 复杂，合并了 ARP 和 IGMP 的功能，所以 IPv6 网际层只有 ICMPv6 一个配套协议。ICMPv6 报文封装成 IPv6 数据报发送，前面是基本首部和扩展首部，前面首部的下一个首部字段置为 58。

ICMPv6 报文可以报告差错、获取信息、探测邻站、管理多播通信。常用报文类型：

- 差错报告：目的站不可达、分组太长、时间超过、参数问题
- 查询：回送请求、回答
- 多播管理：多播听众查询、报告、完成
- 邻站发现：路由器询问、通告、邻站询问、通告、改变路由

## 4.10 软件定义网络（SDN）

SDN 由 Nick McKeown 教授于 2009 年提出，最初是学术探讨的网络体系结构，后来被企业采用（如谷歌 B4 数据中心网络）。能提高带宽利用率和稳定性、简化管理、降低成本，是当前网络领域的热门技术。

### 4.10.1 网络层的数据层面和控制层面

路由器的功能分为分组转发（数据层面）和路由选择（控制层面）：

- 数据层面：按转发表转发分组，现在多为硬件实现，转发时间是纳秒级
- 控制层面：路由器之间要交换路由信息，用软件计算路由，生成路由表，再得出转发表，计算时间是秒级

传统路由器里两者在同一台设备上。SDN 把两者分离：路由器没有路由选择软件，也不交换路由信息；控制层面有一个逻辑上集中的远程控制器（物理上可以由多台服务器组成），掌握网络状态，计算最佳路由，生成各路由器的转发表，路由器只管查表转发分组。

SDN 适用于大型数据中心广域网等场景，没打算把整个因特网改成集中控制。

### 4.10.2 OpenFlow 协议

OpenFlow 协议是 SDN 的重要标准。SDN 是新型网络体系结构，要点是控制层面与数据层面分离；OpenFlow 就是两者之间的通信接口，让控制器可以直接访问和控制数据层面的设备（逻辑集中、基于流的控制）。规范由 ONF 制定：2009 年 1.0 版，2015 年 3 月 1.5.1 版，成熟版本是 1.3 版。SDN 不强制使用 OpenFlow，但多数产品采用。

1. 传统数据层面任务：“匹配 + 动作”，匹配转发表里的网络前缀（最长前缀匹配），动作是从指定接口转发。
2. SDN 广义转发：匹配可以涉及各层首部字段，动作除了转发，还可以是负载均衡、重写 IP 首部、阻挡分组等。
3. OpenFlow 交换机和流表
    - 关系：SDN 中完成 “匹配 + 动作” 的设备叫 OpenFlow 交换机（分组交换机），取代路由器转发表的是流表，流表由 SDN 远程控制器通过安全信道（OpenFlow 协议）管理。OpenFlow 既是通信协议，也是交换功能逻辑结构的规约，不同厂商的设备对控制器呈现统一的逻辑交换功能。
    - 流表结构：每个 OpenFlow 交换机有一个或多个流表。流表项包含首部字段值（匹配字段，涉及多层首部）、计数器（匹配分组数、时间等）、动作（转发、丢弃、复制、重写首部等）。
    - 示例：不同场景下，流表项设置不同的匹配和动作：
      - 简单转发：按源、目的 IP 匹配，从指定端口转发
      - 负载均衡：按入端口和目的 IP 匹配，不同入端口对应不同转发端口
      - 防火墙：按源 IP 匹配，允许特定源 IP 的分组转发

### 4.10.3 SDN 体系结构

1. 关键特征
    - 基于流的转发：数据层面的分组交换机由 SDN 控制器控制，转发基于多层首部字段，流表项由控制器计算、管理和安装。
    - 数据与控制层面分离：数据层面是简单快速的分组交换机，执行 “匹配 + 动作”；控制层面由服务器和软件组成，计算和管理流表。
    - 外部网络控制功能：控制层面软件运行在远离数据层面设备的机器上，包括 SDN 控制器（网络操作系统）和网络控制应用程序，控制器维护网络状态，提供控制接口。
    - 可编程网络：通过控制层面的网络控制应用程序，控制器控制数据层面交换机，实现路由选择、负载均衡、接入控制等功能，使网络可编程。
2. SDN 控制器：SDN 体系结构中最复杂的部分，分三层：
    - 通信层：底层，负责控制器和数据层面设备之间的通信，使用 OpenFlow 协议；设备向控制器传送本地事件，确保控制器掌握网络最新状态。
    - 网络范围的状态管理层：中间层，维护全网主机、链路、交换机、流表等状态信息，为控制决策提供依据。
    - 到网络控制应用程序层的接口：顶层，通过北向 API（如 REST 风格 API）实现控制器与网络控制应用程序的交互，应用程序可以读写网络状态和流表，处理网络事件。
3. 接口：SDN 控制器和数据层面设备之间的通信接口是南向 API，和控制层面应用程序之间的接口是北向 API。SDN 各组件可以由不同厂商提供，这点和传统网络（设备集成控制层面和数据层面）不同。目前有 OpenDaylight、ONOS 等开源 SDN 控制器。
